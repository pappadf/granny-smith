# The V8 family — LC II, Classic II, Color Classic and the Sonora boards

Granny Smith's model of Apple's low-cost 68030 boards built around one
"VISA"-lineage decoder: the **V8** (Macintosh LC II), the **Eagle**
(Macintosh Classic II) and the **Spice** (Macintosh Color Classic).  The
hardware is described in [reference/machines/v8/v8.md](../../../reference/machines/v8/v8.md);
this page is how the emulator models it.

## 1. Source layout

| File | Holds |
|---|---|
| `src/machines/v8/v8.h` | `v8_board_t` (the per-model hardware data), the substrate, the family's fixed addresses |
| `src/machines/v8/v8_internal.h` | the machine state, the built-in video state, `v8_chip_ops_t` |
| `src/machines/v8/v8.c` | the substrate: construction, the RAM decode, the overlay, reset, VBL; the V8 kind's `v8_chip_ops` |
| `src/machines/v8/v8_video.c` | the built-in video: the scanout over VRAM or a DRAM page, over the shared Ariel |
| `src/machines/v8/sonora.c` | the Sonora chip kind (§9): its I/O rows, CPU ID register, RAM decode, memory map; `sonora_chip_ops` |
| `src/machines/v8/v8_models.c` | the eight `hw_profile_t`s and their `v8_board_t`s |

Shared code the family reuses: `mdu/rbv.c` in its `RBV_VARIANT_V8` variant
(the pseudo-VIA2 at `$50F26000`); `mdu/rbv_board.c`, the device run and
glue the IIci and IIsi build too (ADB, the 5380 and the sound interrupt
through the RBV, Egret or Cuda, the RBV's interrupt at IPL 2, soft
power-off, teardown); `mdu/mdu_io.c`'s island table; `runtime/ariel.c`, the
Ariel CLUT/DAC the PDM Power Macs share; `core/peripherals/egret.c` (LC II,
Classic II) or `cuda.c` (Color Classic), `asc.c` in its FIFO-only form,
`floppy_swim.c`, the 5380 in `scsi.c`, `via.c`, the 68k board runtime.

## 2. A model profile

Every model is the same substrate (`v8_substrate`) over a `v8_board_t`
(`v8_models.c`, whose `V8_PROFILE_COMMON` carries the profile fields every
member shares).  The board's `kind` picks its decoder's `v8_chip_ops_t`:
the board descriptor (ROM window, island table, bus-error window), the RAM
layout and decode, the memory map, the reset half and checkpoint block, the
VRAM base and how the video is controlled.

| Field | LC II | Classic II | Color Classic |
|---|---|---|---|
| decoder | V8 | Eagle | Spice |
| `id_strap` (VIA1 PA6/PA4/PA2/PA1) | `$54` (1/1/1/0) | `$12` (0/1/0/1) | `$02` (0/0/0/1) |
| `pcb_ram` | 4 MB | 2 MB | 4 MB |
| `fb_source` | VRAM, 256 KB | DRAM at `$9F9A80` | VRAM, 256 KB |
| `crt_width × crt_height` | external port (sense decides) | 512 × 342 | 512 × 384 |
| companion | Egret | Egret | Cuda |
| ROM box flag | 13 (LC; 31 under 7.1+) | 17 | 43 |

The ID strap is what the ROM's machine-identification tables test; the box
flags are what the ROM (and, for the LC II, System 7.1) leave in BoxFlag.

No board of the family ships with an FPU — the 68882 is an empty socket or
an expansion-card option — so every profile sets `fpu_absent`, and the
68030's FPU instructions take the F-line trap.

## 3. Address map

| Range | What answers | How it is mapped |
|---|---|---|
| `$00000000-$009FFFFF` | RAM space (§4) | SoA pages, re-decoded on every write to the expansion register |
| `$00A00000-$00DFFFFF` | ROM (the 24-bit window) | overlay trigger until the first ROM access, then direct pages; host region for the PMMU |
| `$00F00000-$00F3FFFF` | the I/O island again | same `board_io_t` |
| `$00F40000-$00FBFFFF` | VRAM again | direct pages + host region |
| `$40000000-$4FFFFFFF` | ROM, mirrored | overlay trigger, then direct pages |
| `$50F00000-$50F3FFFF` | the I/O island | `mdu_io_ranges_tbl` (the MDU's) |
| `$50F40000-$50FBFFFF` | VRAM, repeating at its size | direct pages + host region (+ alias) |
| `$FE000000-$FEFFFFFF` | the empty PDS slot | bus error |

The low 16 MB repeats the 24-bit map in either addressing mode; the ROM
runs its early code at `$00A0xxxx` and its MMU tables map ROMBase onto the
24-bit window.  The island does **not** repeat at `$50F40000`: the ROM tells
a VISA-lineage decoder from an MDU by checking that VIA1's IER is not there.
The PMMU's `ram_size_max` is set to the whole low 16 MB, so a write the
guest's tables send to ROM through `$A00000` completes and is dropped
rather than timing out.

The island is the MDU's, row for row: VIA1 `$00000`, SCC `$04000`, SCSI
handshake `$06000`, SCSI registers `$10000`, SCSI pseudo-DMA `$12000`, sound
`$14000`, SWIM `$16000`, Ariel `$24000` (bound as the VDAC device, into
`v8_video.c`), V8 registers `$26000` (the RBV row).

## 4. RAM decode

The expansion register (`$50F26001`) carries the SIMM bank size in bits 7-6
(0, 2, 4, 8 MB) and the soldered RAM's decode in bit 5 (0 = 4 MB, 1 = 2 MB).
`v8_map_ram_decode` maps the 10 MB space as:

- `$800000-$9FFFFF`: the top 2 MB of the soldered RAM, always;
- `[0, bank A)`: the SIMMs, repeating at their installed size (nothing when
  there are none);
- `[bank A, bank A + decode)`: the soldered RAM, repeating at its size;
- anything else floats.

The ROM sizes memory by programming the bits and probing, so the RBV
variant's expansion-register callback re-decodes on every write (and the
overlay drop decodes the current value).  Host RAM is laid out
`[SIMMs][soldered]`, so the decode the ROM settles on is host-contiguous and
the PMMU's plain `phys < ram_size` path serves it; the `$800000` image is one
extra host region when the configured total is 8 MB or less.  On the full
10 MB with 4 MB soldered, the soldered RAM's bottom 2 MB has no address once
sized and lives in a side buffer (`pcb_hidden`, checkpointed).

The configurable totals are the real ones: 4/6/8/10 MB (LC II, Color
Classic) and 2/4/6/10 MB (Classic II).

## 5. Overlay and reset

The overlay (`m68k_board_overlay_t`, DROP_ON_ACCESS) has its trigger
aperture on the 24-bit ROM window, and the 32-bit ROM space is its alias
(`m68k_board_overlay_set_alias`): every arm -- construction and every bus
reset -- routes it to the same trigger, because the ROM's restart path
(System 7.6 switching to 32-bit addressing) runs on in the 32-bit ROM space
after its `RESET`.  The drop maps RAM at zero as the size bits decode
(`v8_map_ram`, the RAM decode only) and the overlay turns both ROM windows
into direct pages.  Sonora has no 24-bit window: its aperture is the 32-bit
ROM space itself.

## 6. Two shared-code accommodations

**The instruction cache across an MMU enable** (`mmu.h`, `mmu_icache_hold`).
The ROM runs its MMU-enable sequence twice from the 24-bit ROM window —
warming the 68030's logically addressed instruction cache — then
`PMOVE`s TC and `JMP`s into the 32-bit ROM space; the new tables do not map
the window it is executing from.  Without a cache model, a PMOVE to TC that
turns translation on with the cache enabled holds the PC's page under the
old translation, and the fetch of the next instruction refills its page
from it once; any other TLB miss first drops the hold unused.  The family
turns it on (`icache_hold_enabled`); no other 68030 board has it.

**A FIFO-only sound block** (`asc_set_fifo_only`).  The family's sound is
"a subset of the Apple Sound Chip" with no wavetable mode.  The mode
register is pinned to FIFO and the FIFOs drain from power-on; status bits
0/2 report half-empty and bits 1/3 report empty as levels.  The Color
Classic's ROM plays its boot sound without writing the mode register and
waits for half-empty before its first byte.

## 7. Video

`v8_video.c` is the scanout over the Ariel (`runtime/ariel.c`, shared with
the PDM: address, data, control, key at offsets 0-3, the R/G/B sequencer
shared with the other RAMDAC models).
Depth comes from the V8's MonP register (bits 0-2: 1, 2, 4, 8, 16 bpp)
through the RBV mode callback, and MonP's RvVIDOff (bit 6) blanks the VRAM
video through the blank callback (the LC II and Color Classic; the Classic
II's DRAM screen ignores it).  On Sonora both come from its own video
registers instead (§9): the mode register's bit 7 blanks, and MonP drives
nothing.  A /RESET returns the video to its power-on state.  The row stride is fixed by the VRAM fitted
(512 bytes on 256 KB).  At a reduced depth the pixel drives the high index
lines, so the presented palette is CLUT entries `(v << (8-d)) | (2^(8-d)-1)`;
the Classic II's one-gun CRT shows the table's green component (the PDM
shows its blue: `pdm/video.md`).  Depth codes 5-7 read as 16 bpp.
The LC II's external port decodes the 12" RGB (sense 2, 512 × 384) and the
13" RGB (sense 6, 640 × 480); anything else selects the 512 × 384 timing.
The Classic II scans 512 × 342 at 1 bpp from `$9F9A80`, which the RAM decode
always backs (the top-2 MB image); the Color Classic's CRT is strapped as
the 12" RGB.  The frame interrupt is slot-interrupt bit 6, raised every VBL
and cleared by a write of `$40` (the V8 variant's rule) or a read.

## 8. Status and gaps

- All three models boot 7.0.1 (LC II, Classic II), 7.1 (LC II, Classic II),
  7.5.3 and 7.6 (Color Classic, LC II 7.5.3) to the Finder; `suite-v8`.
  The Color Classic refuses 7.0.1 at startup, as the real machine does.
- The Color Classic with System 7.1 needs its System Enabler, which the
  test data does not hold; under 7.5.3 and 7.6 without it, About This
  Macintosh names it "Macintosh" (as 7.5 does for every model).
- Not modelled: sound input / DFAC, the Color Classic's front-panel
  buttons and brightness/contrast, 512 KB VRAM, the Apple IIe card mode,
  PDS cards, the Eagle's alternate screen page.
- **The Macintosh LC** (68020, the same V8 board with 2 MB soldered) is a
  board profile away once a 68020 core exists: its ROM (`$350EACF0`) is
  already in the ROM table, the decode is the V8's with bit 5 set, and the
  LC lacks only the PMMU (so §6's cache hold never fires).
- The Sonora boards are §9.

## 9. The Sonora chip kind

`v8_board_t.kind = V8_KIND_SONORA` selects `sonora.c` inside the same
substrate: `v8_init` builds the same devices (VIA1, Egret or Cuda, the
Combo's SCC and 5380, the FIFO-only sound block, SWIM, the RBV register
file in its V8 variant) and takes its kind's `sonora_chip_ops` -- the RAM
layout and decode (the RBV's register 1 is Sonora's RAM configuration
register), the memory map, the checkpoint block, the reset half that
clears Sonora's own registers, the VRAM base, and video that follows its
own control registers instead of MonP.

| Board | CPU ID | Box flag | Display | Companion |
|---|---|---|---|---|
| LC III (`lciii`) | `$A55A0001` | 21 | external port, 13" / 12" RGB | Egret |
| LC III+ (`lciiip`) | `$A55A0003` | 56 | external port | Egret |
| LC 520 (`lc520`) | `$A55A0100` | 50 | built-in 640 x 480, sense 6 | Cuda |
| LC 550 (`lc550`) | `$A55A0101` | 74 | built-in 640 x 480, sense 6 | Cuda |
| Color Classic II (`colorclassicii`) | `$A55A0101` | 77 | built-in 512 x 384, sense 2 | Cuda |

**Identification.**  The ROM reads the CPU ID register at `$5FFFFFFC`
(checking it is read-only and carries `$A55A`), matches the low word
against its ProductInfo records, and -- for the `$EDE66CBD` ROM -- breaks the
tie between boards sharing an ID by the sense code it reads back from the
video sense register: sense 6 selects the "Hook" records (LC 520/550),
sense 2 the "Slice" ones (Color Classic II).  The register is a page at
`$5FFFF000` answering only in its last longword (the rest reads `$FF`):
the shared `runtime/cpuid_page.c`, as on the AV and MEMC boards.

**Address map.**  32-bit decode only: RAM from 0, ROM through the whole
`$40000000-$4FFFFFFF` space (ROMBase `$40800000`; the space is also the
overlay's trigger aperture), the island at `$50F00000`, VRAM at
`$60B00000`.  The island adds three rows ahead of the shared ones:
`$26004-$2600F` (VRAM size, speed and the Ardbeg's registers, plain
latches), `$28000-$28003` (video mode, depth and sense), and
`$0A000-$0BFFF`, the SONIC window, which times out (a `.berr` row: the
`board_io` engine charges its penalty and raises the fault at the island
base plus the offset; the table is
`mdu_io.h`'s row macros with these inserted): the LC III+'s
ProductInfo marks a SONIC valid and its probe must see none.

**RAM.**  Host RAM is `[soldered 4 MB][SIMM]`.  The configuration register
($50F26001) holds a SIMM size code (bank size 2^(n-1) MB) per socket; code 7
is the ROM's sizing configuration, which decodes each bank on a 16 MB
boundary (built-in RAM at 0, the SIMM's banks at 16 and 32 MB; a 2, 8 or
32 MB SIMM is two banks).  Any other value stitches the SIMM directly above
the soldered RAM, so the final decode is host-contiguous.

**Video.**  `v8_video.c` serves Sonora too: the depth comes from the depth
register (0..4), the raster from the monitor code in the mode register
(2 = 512 x 384, 6 = 640 x 480, 13 = 640 x 400, ...: the Sonora timing
sets, `ariel_mode_geometry`), rows packed at
width x depth / 8.  Only the soldered 512 KB VRAM bank is fitted; the SIMM
bank floats, so the video driver sizes 512 KB.  The sense register drives
the lines with its low three bits (0 pulls a line low) and reads
`sense & drive` back in bits 4-6.

**Status.**  All five boot System 7.5.3 and 7.6 from SCSI and the 7.6 Disk
Tools floppy to the Finder; `suite-sonora`.  System 7.0.1 and 7.1 refuse to
start without the machines' System Enablers, which the test data does not
hold; 7.5 and later name every one "Macintosh" in About This Macintosh.
Not modelled: the VRAM SIMM (768 KB, 16 bpp at 640 x 480), the front-panel
buttons and Ardbeg power saving, sound input, the PDS, Omega dot-clock
programming (accepted and ignored).  The Macintosh TV's box flag (82) is
absent from the `$EDE66CBD` ROM's ProductInfo tables, so how that ROM
identifies it is unknown; it is not modelled.
