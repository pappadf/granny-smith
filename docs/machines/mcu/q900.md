# Macintosh Quadra 900

The **Macintosh Quadra 900** ("Eclipse", 25 MHz 68040, October 1991) is
the tower member of the MCU/DAFB family. Profile + board wiring:
[src/machines/mcu/q900.c](../../../src/machines/mcu/q900.c) (shared with
the Q950 through
[q900_internal.h](../../../src/machines/mcu/q900_internal.h)); family
substrate: [mcu.md](mcu.md).

It shares the `420DBFF3` ROM with the Quadra 700; the ROM picks the tower
paths from the model sense (`PA & $56 == $50`, so `via1_pa_model = $D0`)
and the box's ProductInfo flags (Apple's `UniversalTables.a`
`InfoQuadra900` [A]):

## What differs from the Q700

| Aspect | Q700 | Q900 |
|---|---|---|
| System manager | classic RTC on VIA1 | **Caboose** (Egret protocol) on VIA1 SR + PB3/4/5 |
| ADB | VIA1 shifter | **behind the SWIM IOP** (`ADBIop`, like the IIfx) |
| SCC | direct | behind the **SCC IOP** (island `$C000`; bypass window at base+`$20`) |
| SWIM | direct | behind the **SWIM IOP** (island `$1E000`) |
| SCSI | one 53C96 | **dual 53C96**: internal `$F000/$F100`, external `$F402/$F502` |
| NuBus | slots $D, $E | **five NuBus '90 slots $A–$E** |
| Keyswitch/power | — | VIA2 PB straps (PB0 not-secure, PB2 not-off, PB5 speed sense) |

### Caboose

The tower's system manager speaks the **Egret protocol** — the emulator
reuses the mdu `egret.c` engine verbatim as the "Caboose" instance
(RTC/PRAM/power/keyswitch; ADB stays NULL because tower ADB belongs to
the SWIM IOP). The ROM's `ChkFirmware` branches on the **box flag**, not
by querying the chip, so no protocol delta is needed for boot. Not
modeled: CPU reset-hold by Caboose (permissive start), keyswitch-change
unsolicited messages (the ROM reads VIA2 PB directly).

### IOPs

The two Apple PIC/IOPs reuse the IIfx behavioural models
([oss/iop.c](../../../src/machines/oss/iop.c)) **unchanged** — the tower
ROM uploads bit-identical IOP firmware to the IIfx's (both FNV hashes
verify at boot). The host register layout (`iopRamAddrH $00` / `L $02` /
`StatCtl $04` / `Data $08`) is the same `HardwarePrivateEqu.a` set. Only
base addresses and IRQ routing differ: the SCC IOP host INT **wire-ORs
with the SCC chip INT** onto the level-4 source (`mcu_board_t.scc_irq`
hook); the SWIM IOP host INT drives VIA2 CA2.

### Dual SCSI

Both 53C96 INT outputs wire-OR (active-low) onto VIA2 CB2. The external
bus is electrically isolated with no default devices — selections time
out like an empty chain. DAFB TurboSCSI channel 1 observes the external
controller's DRQ.

## Save-state

All tower devices (Caboose, both IOPs, the external 53C96 + bus)
checkpoint with the machine — see [mcu.md](mcu.md) for the stream order.
The `q900-checkpoint` integration test saves mid-boot (live IOP
mailboxes) and restores in a fresh process to a pixel-exact desktop.

## Gates (integration tests)

- `q900-boot-hd` — System 7.1 SCSI HD boot through the tower path
  (Caboose RTC/PRAM handshake, IOP firmware upload + mailbox ADB, dual
  53C96) to the desktop; `BoxFlag == 14` (boxQuadra900), pixel-exact.
- `q900-boot-floppy` — Disk Tools boot through the SWIM IOP mailbox path
  + ADB-alive check.
- `q900-checkpoint` — tower save/restore across processes.
