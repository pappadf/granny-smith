# Power Macintosh 9600/200 and 9600/200MP

The Power Macintosh 9600 is the 1997 reissue of the 9500's maximum configuration: the same
twelve-DIMM-slot, six-PCI-slot, no-onboard-video TNT logic board, moved into a new easy-access
tower enclosure and re-equipped with a PowerPC 604e processor card running at 200 MHz on a
50 MHz bus. It shipped in two processor complements, the single-processor 9600/200 and the
dual-processor 9600/200MP, both covered by the same developer note [1] Table 1-1 p. 2.

To software the machine is a Power Macintosh 9500. Its ROMs carry a byte-identical Open
Firmware image, so it answers `AAPL,9500` in the device tree and the 9500's gestalt value
outright — the 1997 machines report the 1995 identities because the firmware cannot tell them
apart, and software must read the processor's version register instead (tnt.md §6.5, §1.2).
This page therefore does not restate the 9500's specification: the developer note covering
this machine is a delta guide — "This developer note describes only the changes that make the
new models different from their earlier counterparts" [1] §"About This Developer Note" p. vii —
and its compatibility statement carries everything the note does not change across from the
9500: "Except for the changes described in this developer note, the features of the faster
Power Macintosh 7600, 8600, and 9600 computers are the same as those of their earlier
counterparts" [1] §"Compatibility Issues" p. 17. The board-level baseline is the family doc
([tnt.md](tnt.md) §2–§5); the machine-level baseline is the 9500's page
([pm9500.md](pm9500.md) §2–§4); between those and this page, the 9600 is completely specified.

## 1. Identity

### 1.1 What the machine is

The 9600 is the 9500's board architecture in a new enclosure with a new processor card —
Apple's own comparison table states the delta in one row: the 9600/200 against the 9500/200
differs in "New tower enclosure, 12X-speed CD-ROM drive, new accelerated display card", and
the 9600/200MP against the 9500/180MP adds "Clock speed 200 MHz, dual PPC604e
microprocessors" to the same list [1] Table 1-1 p. 2. The ASIC set, the shared memory map,
the interrupt, bus and clock architecture and the DBDMA engine are the TNT platform's
(tnt.md §2–§5); the twelve-slot memory array, the soldered 512 KB second-level cache, the
six-slot two-Bandit PCI topology and the absence of any onboard video are the 9500's
(pm9500.md §2.3–§2.5, §3.4). What the 9600 adds of its own is the subject of §2 through §4.

The developer note covers seven models in one document and names the two 9600
configurations on its cover [1] p. 1; it directs developers to *Macintosh Developer Note
Number 12* (the 9500, ADC part R0651LL/A) and *Number 13* (the 7500/8500) for the base
machines [1] p. vii — which is also this page's division of labor, with
[pm9500.md](pm9500.md) standing in for Developer Note 12.

### 1.2 Identity values

The platform's identity machinery — the Hammerhead identifier, the machine-class flag and
the Grand Central BoxID register, read by both halves of the ROM — is the family doc's
(tnt.md §2.6), the register detail is [hammerhead.md](hammerhead.md) §2.2–§2.4's, and the 1997
machines' wholesale reuse of the 1995 identities is established at tnt.md §6.5. This
machine's values:

| Identity value | Value | Witness |
|---|---|---|
| Platform / ROM family | TNT — the `$39` first byte of the Hammerhead identifier selects the TNT arm of both decodes | tnt.md §2.6; [hammerhead.md](hammerhead.md) §2.2 |
| Machine-class flag (Hammerhead `+$20`) | bit 30 set — the 9500 class, as on the 9500 | tnt.md §6.3, §6.5; [hammerhead.md](hammerhead.md) §2.3 |
| Open Firmware `compatible` | `"AAPL,9500"` followed by `"MacRISC"` — the byte-identical firmware image produces the 9500's answer | tnt.md §1.3, §6.5 (*observed* on the ROM's identity path) |
| Open Firmware `AAPL,cpu-id` | built exactly as the 9500's ([hammerhead.md](hammerhead.md) §2.3–§2.4) — and equally unable to distinguish the two, since the not-a-601 flag is set for the 604e as for the 604 | tnt.md §6.5; pm9500.md §1.2; §6.10 |
| 68k product record / `BoxFlag` / gestalt machine type | `$3D` / `$3D` / 67 — the 9500's: "The new Power Macintosh 7600, 8600, and 9600 computers have the same machine ID values as their earlier counterparts" | [1] §"Machine Identification" p. 17; pm9500.md §1.2 (*observed*) |
| Boot ROM | the 1997 image `$960E4BE9`, ROM version `077D.34F2` — the one release covering the 7300/7600/8600/9600 | [2]; tnt.md §1.3 |
| Display identity | none — the firmware instantiates no `chaos`/`control` nodes, matching a board with no onboard video | tnt.md §6.3; pm9500.md §2.5 (*observed*) |

The discriminating fact, stated precisely: of the three properties that separate the 1997
machines from their 1995 namesakes — the processor's PVR, the L2 configuration, the AV
hardware (tnt.md §6.5) — only the **PVR** separates a 9600/200 from a 9500: the 512 KB
soldered cache is common to both and neither carries AV hardware, so the installed processor
is the machine's only software-visible signature — a 604 answers version `$0004`, a 604e
`$0009` [5]. No other 1997 model shares this near-total indistinguishability (the 7600's L2
and the 8600's AV hardware each break their own ties).

The identity-miss path is the family's (tnt.md §2.6): an unrecognized register set yields
`compatible = "AAPL,????"` and a tree with no display nodes at all.

### 1.4 Factory configurations

The standard configurations [1] §"Configurations" Table 1-4 p. 7:

| Model | DRAM | Hard disk | L2 cache | Special features |
|---|---|---|---|---|
| Power Macintosh 9600/200 | 32 MB | 4 GB | 512 KB | Video display card with graphics acceleration |
| Power Macintosh 9600/200MP | 32 MB | 4 GB | 512 KB | Dual microprocessors, video display card with graphics acceleration |

Two framing statements from the same section: "The new models of the Power Macintosh 7300,
7600, 8600, and 9600 computers come with 16 or 32 MB of main RAM installed in RAM DIMM
slots. All models have a built-in second-level (L2) cache of either 256 or 512 KB. The size
of the internal hard disk is either 2 or 4 GB" [1] p. 7 — the 9600 sits at the top of all
three ranges — and every model includes the built-in 12X CD-ROM drive [1] p. 7 note. The L2
split is architectural, not incidental: "The L2 cache in the Power Macintosh 9600/200 and
9600/200MP consists of 512 KB of fast static RAM on the main logic board. The L2 cache in the
other models consists of a 256 KB DIMM installed in a slot" [1] §"Second-Level Cache" p. 4 —
the 9600 alone keeps the 9500's soldered-cache arrangement (§3.3).

### 1.5 The new tower enclosure

The enclosure is the 9600's largest physical delta and the note devotes most of its length to
it. "The new tower enclosure is used for the Power Macintosh 8600 and 9600 computers"
[1] §"Appearance of the New Tower Enclosure" p. 8, and its five stated features are "more
space for internal storage devices, larger power supply, easier access to internal
components, a locking feature, [and] space for larger-size DIMMs" [1] §"New Tower Enclosure"
p. 8. The dimensions — 429 mm high, 224 mm wide, 440 mm deep [1] Table 1-5 p. 10 — replace
the 9500's 8100-derived stretched tower (pm9500.md §1.5).

"The new tower enclosure has spaces for up to seven internal storage devices. Four of those
spaces are accessible from the front; of those four, three can accommodate 5.25-inch devices
and one can accommodate a 3.5-inch device. The other spaces are not accessible from the
front; they can accommodate three 3.5-inch devices or one 5.25-inch device and one 3.5-inch
device" [1] §"Internal Storage Devices" p. 10. The shipped complement of the front bays is
described as "the floppy disk drive, the CD-ROM drive, and the Zip drive" [1] §"Accessible
Devices" p. 11 — but the built-in Zip is the 8600's option, not the 9600's [1] Table 1-1
p. 2, so the 9600's third front bay ships empty (*inferred*; §6.15). The bays are
user-serviceable: the floppy bay takes a replacement 3.5-inch SCSI hard disk up to 1 inch
high, the CD-ROM bay a 5.25-inch or smaller SCSI device up to 1.625 inches high, and each
front panel is removable from the side [1] p. 11. Of the three internal spaces, one is the
startup hard disk bay; beyond the seven supported bays, "the bottom part of the enclosure
also has space for one or two additional disk drives, such as RAID stacks" mounted on a
drive carrier [1] §"Inaccessible Devices" p. 11. Two IMPORTANTs govern that bottom space:
the carrier "must be in place whenever the computer is operating" to prevent electromagnetic
interference, and "the added drives in the bottom of the enclosure occupy the space that
would be used by PCI cards in the lowest one or two of the six PCI expansion slots in the
Power Macintosh 9600" [1] pp. 11–12 — the one place the note states the slot count, and a
genuine expansion trade-off unique to this machine.

Access is the enclosure's selling point. The left side panel is removable via a pushbutton
latch, exposing "PCI expansion slots, the DAV connector, and the space for internal RAID
storage devices" [1] §"Removable Side Panel" p. 13; the power supply and disk drives sit on
"a hinged subchassis that can be tilted out of the enclosure", folding the machine open for
DIMM access exactly where the 9500's supply obstructed the slots [1] §"Hinged Subchassis"
p. 14; and a rear tab latches the side panel and takes a security cable or padlock
[1] §"Locking Feature" p. 15. The supply itself: "The power supply in the new tower
enclosure now provides a total of 390 watts to support the larger number of drives and the
faster processor", supporting "as many as six 15-watt cards or four 25-watt cards"
[1] §"Larger Power Supply" p. 12, with the per-device rail budget of Table 1-6 (§4.1) and
two power connectors for added drives — the user supplies the cables and "a PCI expansion
card to provide the interface to the added drives" [1] p. 12.

### 1.6 The later speed grades

The developer note documents only the /200 and the /200MP. Community coverage describes two
further waves: a 9600/233 (a 233 MHz 604e on a 46.6 MHz bus, a 256 KB cache DIMM) and the
August 1997 9600/300 and /350 — a "Mach 5" 604ev-class part on a board revision that moves
the second-level cache onto a 1 MB inline card and runs a 100 MHz card bus (*inferred —
unverified*; no Apple document in evidence describes any of them, and the revision codenames
in circulation are community-attested). The one piece of primary evidence for a post-/200
CPU is indirect: the second 1997 ROM release, labeled for the 8600 and 9600, carries a
kernel special-case for a processor whose version register upper halfword is `$0060` — a
value no PowerPC version assignment in evidence identifies [2] (§6.4). Until an Apple
document surfaces, the 233/300/350 grades are open territory, not specification.

## 3. Per-subsystem wiring

### 3.1 The processor card and the AR bus

The processor subsystem card is the family's — a plug-in card carrying the processor and its
clock circuits, the upgrade path (tnt.md §2.2) — and on this machine it supplies 50.0 MHz to
the board and carries one 604e (or two; §4.5). The 604e is the 604 with the doubled caches and
a rewritten internal clocking scheme: a single SYSCLK input sets the bus-interface frequency
and an internal PLL generates the core clock, phase-locked to it [3] §1.3.8 p. 1-27,
§1.2 p. 1-2. The card's 4:1 ratio is therefore a strap the card makes once, and software can
read the answer back: HID1, a read-only supervisor register the 604e adds over the 604,
publishes the PLL configuration in bits 0–3 [3] §2.1.2.4 p. 2-12. The version register — the
one read that distinguishes this machine from a 9500 (§1.2) — answers `$0009` for the 604e
[5].

The AR bus is the family's multiple-master 60x bus (tnt.md §5.2), and this machine's agent
set is the 9500's: the 604e, Hammerhead as the slave for RAM, ROM and the L2, and two Bandit
bridges — no Chaos, since there is no display bus (pm9500.md §3.1). On the /200MP the
card contributes a second caching agent; both processors snoop the one bus, the 604e
implementing the four-state MESI protocol with hardware snooping of its caches
[3] §3.6 pp. 3-12–3-15, over the coherency architecture the family doc states (32-byte
granularity, L2-forced L1 inclusion; tnt.md §5.2, [hammerhead.md](hammerhead.md) §3.4).

One memory-model change belongs here because it is board-architecture, not chip detail: the
1997 ROM marks every I/O mapping Guarded (tnt.md §3.5), and Apple's own one-sentence
description of the change is in the developer note's ROM-change list — "The software now sets
the guarded bit in the MMU for cache-inhibited address space" [1] §"Changes in the ROM"
p. 16. Guarding blocks the speculative, out-of-order access the 604e performs where the 601
did not — the developer note's confirmation of the configuration-record diff the family doc
established (tnt.md §6.5).

### 3.2 Memory

The array is the 9500's, and its complete rule set is cited, not restated, from
[pm9500.md](pm9500.md) §2.3 and §3.2: twelve 168-pin 8-byte DIMM slots, no soldered
capacity, one-DIMM minimum, banks of 4 to 64 MB, the 128 MB two-bank DIMM ceiling,
contiguity manufactured by Hammerhead's bank base registers, the 128-bit interleave on
same-size pairs, sizing performed by the startup software through the bank base register
file ([hammerhead.md](hammerhead.md) §2.10, §3.2). This machine's own additions are three
statements in the developer note's RAM-DIMM section:

- **Module heights.** "The new tower enclosure for the Power Macintosh 8600 and 9600
  accommodates RAM DIMMs of 1.1 and 1.255 inches in height" [1] §"RAM DIMM Modifications"
  p. 18, the enclosure's "space for larger-size DIMMs" feature made concrete [1] p. 8 —
  the taller JEDEC MO-161 profile now fits under the hinged subchassis (§1.5).
- **Device technology.** "The RAM expansion DIMMs in the new computers can use either
  extended data out (EDO) or fast page mode (FPM) DRAM devices. The computer always operates
  the devices in fast page mode" [1] p. 18 — a new statement for 1997; whether the sizing
  path programs Hammerhead differently for an EDO part is attested nowhere (§6.14).
- **Power.** "As in the previous Power Macintosh models, only 5-V power is available on the
  RAM DIMM slots. Devices that require 3.3-V power cannot be used" [1] p. 18 — the family's
  rule unchanged (pm9500.md §3.2).

The factory load-out is 32 MB [1] Table 1-4 p. 7. The interleaving geometry, the address
multiplexing modes and the module mechanics are all the 9500's (pm9500.md §3.2), carried
across by the compatibility statement [1] p. 17.

### 3.3 The L2 cache as fitted

The 9600 keeps the arrangement that makes the 9500 the family's exception: its second-level
cache is "512 KB of fast static RAM on the main logic board" [1] §"Second-Level Cache" p. 4 —
not a SIMM, never absent, never sensed, while the 7300/7600/8600 move to "a 256 KB DIMM
installed in a slot" [1] p. 4. Apple credits the cache with "a performance improvement of
up to 40% over machines without such a cache" [1] p. 4. The cache's write-back,
direct-mapped, allocate-on-read-or-write policy and its SRAM stores are the 9500's
(pm9500.md §2.4); the controller register surface, the size decode and the POST bring-up are
[hammerhead.md](hammerhead.md) §2.8–§2.9, §4.4's. The 1997 firmware's POST runs the identical
L2 probe choreography against that cache — the 1997 ROM diff shows every hardware access in
the diagnostics object byte-for-byte unchanged, so Hammerhead was not revised for this
machine (tnt.md §6.5).

### 3.4 The two Bandits and the PCI topology

The PCI topology is the 9500's, exactly: two Bandit bridges — one for slots 1–3, the other
for slots 4–6 — each owning its fixed 32 MB control slice at `$F2000000` and `$F4000000`,
each forwarding an independent 256 MB PCI memory space, Grand Central a device on Bandit 1's
bus alone (pm9500.md §3.4; tnt.md §3.1–§3.2). Because the 1997 Open Firmware image is
byte-identical (tnt.md §1.3), the device tree this firmware builds on this machine — the
same `bandit` nodes with the same `reg`, `ranges`, `bus-range`, `AAPL,interrupts` and
`slot-names` properties, the same IDSEL map, the same slot labels A1–C1 and D2–F2 — is
literally the 9500's tree (pm9500.md §3.4). The bridge register files, the configuration
mechanism and the byte-order translation are [bandit.md](bandit.md) §2–§3's.

One 9600-specific fact belongs in this section because it is topology: on the dual-processor
machine, Bandit 1's **configuration address port** at `$F2800000` doubles as the secondary
processor's start-vector mailbox (§4.5) — a reuse the developer note never mentions and
that no Apple document describes.

### 3.5 Grand Central and the I/O stack

The I/O silicon is unchanged — the compatibility statement is explicit that everything
unlisted is the earlier machine's [1] p. 17 — so Grand Central and its cells (Curio's MACE
and 53C94, MESH, the Cuda behind VIA1, SWIM III, the ESCC), the 32-source interrupt
collector, the DBDMA channel file and the NVRAM apertures are all
[grand-central.md](grand-central.md) §2–§3's, restated nowhere here. The codec the firmware
publishes is still AWACS — the 1997 image contains no other codec string, so every OS driver
takes the AWACS path on this machine even if the board carries the register-compatible
superset part (tnt.md §6.5; the silicon-side question is §6.13).

Two I/O behaviours do change, both in the developer note's ROM-change list: "The SCSI
Manager has been revised to correct a problem with the asynchronous receive-acknowledge
signal in the SCSI controller" [1] p. 16 — a driver-side fix in the ROM's native SCSI
Manager 4.3 resource [2], the MESH and 53C94 silicon untouched — and "the default value of
the hard disk time-out has been increased from 25 to 31 seconds" [1] p. 16. The interrupt
architecture, the VIA1 cascade, the DBDMA channels and the boot-time NVRAM reformat
behaviour are the family's (tnt.md §2.7, §5.1; [grand-central.md](grand-central.md)
§3.2–§3.6).

### 3.6 Storage

- **Hard disk.** The factory disk is 4 GB on the internal SCSI bus [1] Table 1-4 p. 7, and
  the note's disk-software changes extend Drive Setup to the 2 and 4 GB drives
  [1] §"Changes in the Disk Software" p. 17.
- **CD-ROM.** Every new model carries "a built-in 12X-speed CD-ROM drive, an AppleCD 1600i"
  supporting "sustained data transfer rates of 1600 KB per second", reading CD-ROM, CD-ROM
  XA, CD-I and PhotoCD plus audio, with a sliding tray [1] §"12X-Speed CD-ROM Drive" p. 5 —
  replacing the 9500's 600i and its disputed speed rating (pm9500.md §4.4).
- **Floppy.** One internal Apple SuperDrive on SWIM III (inherited; pm9500.md §3.6), in a
  front bay replaceable by a 1-inch 3.5-inch SCSI drive [1] §"Accessible Devices" p. 11.
- **Enclosure capacity.** Up to seven supported bays plus the bottom RAID space, with the
  drive-carrier and PCI-displacement rules of §1.5; the internal bus's termination
  discipline is the 9500's (pm9500.md §3.6).

### 3.8 The boot ROM as this machine carries it

The image is the platform's single 4 MB ROM in its 1997 releases: `$960E4BE9` (ROM version
`077D.34F2`), the release covering the 7300/7600/8600/9600 — this machine, in both processor
complements — plus `$960FC647` (`077D.34F5`), the late-revision 8600/9600 image [2];
tnt.md §1.3. The component diff against 1995 is the family doc's (tnt.md §6.5): Open
Firmware byte-identical, the configuration record changed only in the I/O pages' Guarded
attribute, the `DecoderInfo` pair and every POST hardware probe unchanged, and exactly six
of the 180 Toolbox resources revised [2].

Two facts are 9600-specific enough to record here. First, the kernel is rebuilt in both
images — the family doc characterizes the change as kernel-emulator contract detail, not
hardware (tnt.md §6.5) — and the rebuild carries new processor-table entries, including one
whose cache geometry matches the PowerPC 750's, evidence that the ROM anticipates upgrade
cards beyond the 604e in this chassis [2] (§4.4). The late-revision image's kernel
additionally skips its entire performance-monitor SPR probe sequence for a processor whose
PVR upper halfword reads `$0060`, storing capability flags unprobed — a CPU Apple shipped
firmware for and no version assignment in evidence identifies [2] (§6.4). Second, the image
contains **no multiprocessing code at all**: no `MPLibrary`, `Multiprocessing`, `DayStar`,
`TwoCPU` or `WhoAmI` string anywhere in the image, and the kernel never accesses Hammerhead
`+$90`, `+$B0` or `+$C0` [2]. The multiprocessor machine boots as a uniprocessor, and MP is
a system-software concern above the kernel — established at tnt.md §6.5, and the reason
§4.5's hardware surface is exercised only by operating-system code loaded from disk.

## 4. Expansion

### 4.1 The six PCI slots and the power budget

The card contract is the 9500's — PCI Local Bus Specification rev 2.0, 5 V signaling in the
ISA fence, INTA#–INTD# per slot, none of the optional signal groups (pm9500.md §4.1) — and
the slot population, IDSEL map and interrupt lines of pm9500.md §3.4's tables apply verbatim
on this board. The 1997 note contributes the power statements: "The power supply in the new
tower enclosure now provides a total of 390 watts", it "can support as many as six 15-watt
cards or four 25-watt cards", and Table 1-6 gives the per-device rail budget [1] §"Larger
Power Supply" p. 12:

| Device | Voltage | Current | Power |
|---|---|---|---|
| Expansion card (15 W) | +5 V | 3 A | 15 W |
| | +12 V | 0.5 A | 6 W |
| | −12 V | 0.1 A | 1.2 W |
| | +3.3 V | 2 A | 6.6 W |
| Expansion card (25 W) | +5 V | 5 A | 25 W |
| | +12 V | 0.5 A | 6 W |
| | −12 V | 0.1 A | 1.2 W |
| | +3.3 V | 2 A | 6.6 W |
| Storage devices | +5 V | 9 A | 45 W |
| | +12 V | 3 A | 36 W |
| | +12 V | 7.5 A peak | — (startup only) |

The six-15-watt-card figure agrees with the 9500's 90 W slot budget (pm9500.md §4.1); the
four-25-watt option exceeds it and is this enclosure's own. The bottom RAID space displaces
the lowest one or two slots entirely [1] p. 12 — the only configuration on the platform
where installing storage removes PCI capacity (§1.5).

### 4.2 Memory expansion

The operator-level rules are the 9500's (pm9500.md §4.2): any count of 8-byte DIMMs from
one up, same-size/same-mode pairs in corresponding slots for the 128-bit bank, the bank and
DIMM ceilings, the load limits. This machine's own additions: the 1.255-inch module height
fits — the enclosure was redesigned for it (§3.2) — and either EDO or FPM devices may be
used, always operated in fast page mode [1] p. 18.

### 4.3 Storage expansion

§1.5 carries the bay inventory. Three interface facts: the floppy bay takes a 1-inch
3.5-inch SCSI drive and the CD-ROM bay a 1.625-inch 5.25-inch-or-smaller device [1] p. 11;
the bottom carrier takes one 5.25-inch or two 3.5-inch drives, "such as RAID stacks"; and
the machine supplies power but not the interface — "The user must install power cables and a
PCI expansion card to provide the interface to the added drives" [1] p. 12. The EMI drive
carrier must be installed whenever the machine operates [1] p. 11.

### 4.4 Processor upgrades

The processor card is the platform's stated upgrade path (tnt.md §2.2), and this machine's
ROM is the first in the family to carry kernel-side evidence of it: the rebuilt 1997
NanoKernel's processor table gains entries for processors beyond the 604e — one matching
the PowerPC 750's cache geometry — so the firmware already describes upgrade cards the
machine never shipped with [2]. (The kernel table is a capability record, not a hardware
fact of the board; the card slot's electrical contract for 750-family parts is documented
nowhere in evidence.) The other direction of upgrade is the dual-604e card — the /200MP is
that card factory-fitted, and the question of field conversion between the /200 and the
/200MP is a card-population matter no document addresses (§6.5).

### 4.5 The 9600/200MP: the dual-604e card

**The configuration.** "In the 9600/200MP model, two PowerPC 604e microprocessors are on the
processor card. With applications that support the new multiprocessor API, the MP
configuration provides up to 2 times the performance of the equivalent single-processor
computers. The operation of the dual-processor configuration is asymmetric multiprocessing.
One processor is the primary processor: it runs the Mac OS and handles interrupts from the
I/O systems. The second processor runs MP tasks as set up by the primary processor"
[1] §"Dual Processor Configuration" p. 3. Both processors run at 200 MHz on the 50.0 MHz
bus [1] Table 1-2 p. 4. The API is Apple's to give — "Developers can obtain the
multiprocessor API and documentation from Apple Computer, Inc." [1] p. vii — and "the
multiprocessor API is the same as the one available from Daystar Digital, Inc.",
installed automatically on the hard disk of dual-processor machines [1] §"Changes in the
Disk Software" p. 17. Mac OS conditions for effective dual-processor operation: memory-doubler
extensions must not be installed, virtual memory must be off, and the hard disk must never
be put to sleep [1] §"Dual Processor Operation" p. 17.

**The hardware surface.** The machine needs nothing the 9500/MP does not have: the same three
Hammerhead multiprocessor registers and the same doorbell wiring (tnt.md §6.5;
[hammerhead.md](hammerhead.md) §2.5–§2.7, §4.5; pm9500.md §3.5). What this page adds is the
surface those registers do not cover — the secondary's start path, which no Apple document
in evidence describes and which survives in the two operating systems that drove it:

| Address | Name | Access | Semantics | Witness |
|---|---|---|---|---|
| `$F2800000` | Bandit 1's configuration address port, reused | write u32, big-endian | the secondary processor's start-vector mailbox; idle value `$100` — the PowerPC system-reset vector | [4], [5] |
| `$F3019000` | the Ethernet PROM chip-select space inside Grand Central's window | **read** u32 | the read itself asserts the primary's IPI, arriving as Grand Central source 30 | [4], [5], [6] |

MkLinux hands both to its multiprocessor plug-in by name — the installation call maps the
work area, Bandit 1, Hammerhead, Grand Central, `PCI1AdrReg` at `$F2800000` and the Ethernet
ROM space at `$F3019000`, and the plug-in's entry table exposes the operations a driver
needs (count, start with the physical entry address, resume, stop, reset, signal, store
machine state, synchronize clock, external hook, processor state, run-signal, and a dummy
firmware entry for the alternate processors), over a four-state per-processor state machine
(uninitialized, reset, stopped, operating) [4].

**Why the mailbox alias is safe.** The reuse looks like a collision — writing a start vector
into a bridge's configuration port — but the bridge's mechanism makes it harmless
(*inferred* from [bandit.md](bandit.md) §2.2–§2.3; no Apple document describes the aliasing):
the address port is a latch, and a configuration cycle is performed only by a subsequent
access through the **data** port at `$F2C00000`, so parking a value in the latch initiates
nothing on the PCI bus. The idle value `$100`, decoded as a type-0 configuration address,
selects a device number that does not exist on the bus ([bandit.md](bandit.md) §3.2's
device floor), and every legitimate configuration access rewrites the latch first
([bandit.md](bandit.md) §3.3) — so the mailbox and the configuration mechanism interfere
only if a driver violates the write-before-access discipline.

**The kick protocol.** As performed by the Linux PowerSurge driver [5], corroborated by
MkLinux's two-phase clock-synchronization function codes [4]: the operating system detects
the second processor by reading the arbiter configuration and requiring the two-processor
bit; it flushes the address range the secondary will execute from; it writes the physical
entry address to `$F2800000`; it asserts the interprocessor interrupt, spins briefly, and
deasserts; and the **shared time base freezes across the kick window** — the primary
publishes its counter image, the secondary installs it and sets its decrementer, and the
primary's re-issued interrupt restarts both counters, after which the primary re-arms the
mailbox to `$100` [5]. The 604e has the hook this handshake needs: "The time base counter
is clocked at a frequency that is one-fourth that of the bus clock. Counting is enabled by
assertion of the timebase enable (TBE) input signal" [3] §7.2.10.2 p. 7-31 — what gates the
two processors' TBE inputs on the card, and who asserts it during the freeze, is attested by
no document in evidence (§6.5). The interprocessor interrupt register's doorbell bit is
**active low**: the MkLinux header names it as bit `$80` [4] while the Linux driver asserts
by writing zero and deasserts by writing `$FF` [5] — whole-byte writes that are only
consistent if the bit is asserted when clear (*inferred — unverified*; stated by neither
source).

**Reset-time behavior.** The ROM contains no multiprocessing code (§3.8; tnt.md §6.5), so the
boot path never reads the arbiter configuration: the device tree is the 9500's, with no
second CPU node, and software learns of the second processor only by probing [4]. Whether
the secondary fetches `$FFF00100` and spin-waits — the flow the derived server design
describes for the 9500 family ([hammerhead.md](hammerhead.md) §4.5) — or is held by the card
until the mailbox is written is established by no document; the mailbox protocol suggests
the latter, as inference (§6.5).

**The card.** The design is the Apple/DayStar two-way board: MkLinux's plug-in is explicitly
"specific to a single MP hardware type: the Apple/DayStar 2-way board", its multiprocessor
support "an extension of the hardware, not an I/O device" [4]; and the Linux driver excludes
a first revision of that board, which carried a hardware watchdog [5]. The card's schematic,
clocks, bus loading and its watchdog revision are documented nowhere in evidence (§6.5). Quad-processor register space exists in the same address universe but belongs to
DayStar four-way cards this machine never shipped [5]; nothing on this board decodes it.

### 4.6 What this machine does not expand by

- **No NuBus** — the platform contract (tnt.md §1.1); six PCI slots and nothing else on the
  card edge.
- **No L2 expansion** — the cache is soldered to the board [1] p. 4; unlike the 7300/7600/
  8600's cache DIMM there is no slot to upgrade, and unlike the 9500's optional-SIMM
  relatives nothing to add (tnt.md §2.3).
- **No VRAM or video expansion on the board** — the display path grows only by replacing the
  PCI card, and the shipped card cannot be expanded at all [1] p. 6.
- **No DAV connector, presumably** — the 9500 carries none (pm9500.md §4.5) and this machine
  inherits its AV-less I/O back panel, but the enclosure chapter's access text names "the
  DAV connector" among the bottom-of-case components [1] §"Removable Side Panel" p. 13 —
  a sentence written against the 8600/9600 shared enclosure. Whether a 9600 main logic board
  carries the connector is not stated anywhere (§6.1).
- **No communication slot or processor-direct expansion** of any kind appears in the note;
  the processor card, the six PCI slots, the twelve DIMM slots and the drive bays are the
  machine's entire expansion surface.

## 5. Boot sequence summary

The cold-boot contract — reset vector, NanoKernel, Open Firmware as the bring-up, POST as
diagnostics, `boot /AAPL,ROM` into the 68k emulator — is the family's (tnt.md §2.7). This
machine's branch points, step by step:

1. **Reset.** The 604e fetches the hardware-reset vector at `$FFF00100`, inside the ROM
   decode, at image offset +$300100 (tnt.md §2.7, §3.4). On the /200MP the secondary
   processor's reset-time behavior is the one genuinely open boot question on this machine:
   the ROM has no multiprocessor code, so nothing in firmware decides who is primary
   (§3.8, §4.5; §6.5).
2. **NanoKernel.** The 1997 configuration record is the 1995 one with the I/O pages' Guarded
   attribute set; every scalar the kernel consumes is unchanged (tnt.md §3.5), and the
   kernel rebuild around them is kernel-emulator contract, not hardware (tnt.md §6.5). Its
   new processor-table entries recognize the 604e and later parts [2].
3. **Open Firmware.** The byte-identical image reads the identity registers and — because
   they answer as a 9500's — builds the 9500's tree verbatim: `compatible = "AAPL,9500"`, no
   `chaos`/`control` nodes, the two `bandit` nodes, the dangling `vci0` alias (tnt.md §1.3,
   §6.5; pm9500.md §2.5, §3.4). It sizes the twelve slots through Hammerhead's bank base
   registers, probes the bridges and Grand Central, assigns the cards' BARs and manages
   NVRAM, reformatting a blank store before the OS reads it (tnt.md §2.7).
4. **POST.** The rebuilt diagnostics object runs the identical hardware probes and logs
   through Grand Central's NVRAM apertures; `.L2DataCacheTest` runs against the soldered
   512 KB cache exactly as on the 9500 (tnt.md §6.5; [hammerhead.md](hammerhead.md) §4.4).
5. **`boot /AAPL,ROM`** hands the PowerPC to the 68k emulator; the identification routine
   lands on the `$3D` product record, the unchanged TNT `DecoderInfo` table installs the
   legacy device bases, and the classic Macintosh start-up proceeds (tnt.md §2.7, §3.6).
6. **The startup screen.** With no built-in display, the first image on the monitor is drawn
   by the display card's own FCode boot driver (§3.7; pm9500.md §5).
7. **System software.** The machine ships "a modified version of System 7.5.5 with a new
   enabler" [1] §"System Software" p. 16; the enabler also supports the earlier machines,
   including the 7500 [1] p. 18. On the /200MP the multiprocessor API is installed
   automatically from the hard disk [1] §"Changes in the Disk Software" p. 17 — the only
   place MP enters the boot at all.
8. **Boot-device behavior.** The Start Manager honors the PRAM default boot device first and
   walks the drive queue only after a spin-up timeout of roughly thirty guest-seconds
   (*observed*; tnt.md §2.7); the ROM's hard-disk time-out default is now 31 seconds
   [1] p. 16.
9. **Error paths.** The identity-miss and factory-test paths are the family's
   (tnt.md §2.6, §2.7).

The one-line conclusion: steps 1 through 9 contain nothing that depends on the machine
being a 9600 rather than a 9500 — the identity registers, the tree and the decoder table
all answer as the 9500's, by design (tnt.md §6.5). The 9600's boot differs only in the
processor that executes it, the cache POST tests, the card that draws the startup screen
and the ROM it runs from.

## 6. Open questions

1. **The DAV connector.** The enclosure chapter's access text names "the DAV connector" among
   the components exposed by the side panel [1] p. 13 — a sentence covering the 8600/9600
   enclosure jointly, and the 8600 is the machine with AV hardware for a DAV card. The 9500
   carries no DAV (pm9500.md §4.5) and the 9600 inherits its board features by the
   compatibility statement, yet no document states whether a 9600 board has the connector
   fitted.
2. **The "up to 5 times" clock claim.** The developer note says the 604e offers "processor
   clock speed up to 5 times the bus clock speed" [1] p. 3; the 604e manual's ratio set tops
   out at 4:1 [3] §1.2 p. 1-2, and the /200 is exactly 4:1. No 604e ratio yields 5:1, and no
   documented 9600 grade uses one — unless the sentence anticipates the 233 MHz grade
   (§1.6), whose community-attested 46.6 MHz bus would be 5:1.
3. **The 9600/233 and the 300/350 grades.** No Apple document in evidence describes them;
   their processors, bus ratios, cache arrangements and the board revision the 300/350 use
   are community-attested only (*inferred — unverified*, §1.6). Which ROM release the 300/350
   require is likewise unstated — the second 1997 image's own label covers "the 8600 and
   9600", and nothing ties it to specific grades.
4. **PVR `$0060`.** The late-revision ROM's kernel refuses to SPR-probe a processor whose
   version register upper halfword reads `$0060`, storing capability flags unprobed [2].
   Apple shipped firmware for this CPU; no version assignment in evidence identifies it —
   604e is `$0009`, 604ev `$000A` [5] — making it the strongest primary-evidence hint at
   the post-/200 grades, and unidentified.
5. **The dual-604e card itself.** No schematic, photograph or datasheet of the Apple/DayStar
   two-way board is in evidence: its clocks, bus loading, the TBE gating behind the
   timebase-freeze handshake, the per-processor routing of the who-am-I answer, and the
   first-revision watchdog variant the Linux driver excludes [5] are all undocumented — as
   is where CPU 1's power-on parking lives: the ROM has no MP code, so card hardware holding
   the secondary until the mailbox is written is the narrowed, unproven hypothesis (§4.5).
6. **The SecInt polarity.** Active-low is the only reading that reconciles MkLinux's bit
   definition with the Linux driver's write-zero-to-assert, write-`$FF`-to-clear whole-byte
   writes [4], [5] — stated by neither source; the MkLinux multiprocessor plug-in binary
   (not part of its source tree) would settle it.
7. **The DayStar multiprocessing API.** The note directs developers to Apple for the API
   [1] p. vii and installs it automatically on dual-processor machines [1] p. 17, but its
   programming surface survives only indirectly, through MkLinux's plug-in interface [4];
   no copy of the library or its documentation is in evidence.
8. **Apple's ROM-change list versus the diff.** The note lists four ROM changes [1] p. 16;
   the component diff shows six changed Toolbox resources — the three video drivers, the AV
   audio component, the native SCSI Manager 4.3 component and the RAM-disk driver [2]. Which
   resource carries the 25-to-31-second time-out, and what the video-driver and AV-audio
   changes correspond to, is not accounted for by Apple's list.
9. **The multiprocessor "bug fixes".** "The ROM has been modified to fix bugs that affected
   multiprocessor operation" [1] p. 16 — but the ROM contains no MP code [2]. The Guarded
   I/O mappings (which block speculative access to device registers, a failure mode that
   two processors make intermittent) are the plausible candidate, and Apple states no
   candidate; treat the identification as unverified inference.
10. **This board's own register values.** That the 9600's Hammerhead `+$30` and BoxID read
    as a 9500's — making even `AAPL,cpu-id` identical — is an assumption licensed by the
    byte-identical firmware and the shared identity, but no 9600 register dump is in
    evidence; only the registers' consumption is attested (pm9500.md §1.2; tnt.md §7
    items 3–4).
11. **The DIMM-height contradiction.** The 1997 note's IMPORTANT states "Other Power
    Macintosh computers accommodate only DIMMs with the 1.1-inch height" [1] p. 18 — but
    the 9500's own note allows up to 1.255 inches (pm9500.md §3.2). One of the two notes
    misstates the earlier machines; which one is wrong is not decidable from the notes
    themselves.
12. **The display card's identity.** The 9600's bundled card is named by no vendor and no
    chip set, and the note gives no connector, monitor-sense scheme or acceleration
    architecture — only the 4 MB non-expandable buffer, the mode table and the sync-on-green
    restriction [1] p. 6. The 9500's card was at least named and connector-specified
    (pm9500.md §3.8).
13. **The sound codec silicon.** The 1997 firmware publishes AWACS and no other codec
    (tnt.md §6.5), but whether the fitted part is the original AWACS or the
    register-compatible superset is unattested by any Apple document for this machine.
14. **EDO DIMMs in a Hammerhead array.** "The computer always operates the devices in fast
    page mode" [1] p. 18 — a policy with no stated consequence: whether the sizing path
    treats an EDO part differently, and whether the DRAM timing programmed into Hammerhead
    differs, is attested nowhere (the controller's DRAM register gap, tnt.md §7 item 2).
15. **The shipped front-bay complement.** The enclosure chapter ships the front bays with
    "the floppy disk drive, the CD-ROM drive, and the Zip drive" [1] p. 11 — the Zip being
    the 8600's option [1] Table 1-1 p. 2. The 9600's third front bay is presumably empty at
    shipping (*inferred*); no document says.
