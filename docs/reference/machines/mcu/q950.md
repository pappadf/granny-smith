# Macintosh Quadra 950

The Macintosh Quadra 950 is the 33.333 MHz successor tower of the [Quadra 900](q900.md) — Apple's own
one-sentence description is *\"basically a higher-performance Macintosh Quadra 900\"* [1] Chapter 1
p. 4 — and it is the machine that closes the MCU family: the same Eclipse-generation tower
board, the same custom-IC set, the same IOP/Caboose low-speed organization, the same five-slot
NuBus backplane and the same dual-SCSI arrangement, re-clocked from 25 MHz to 33.333 MHz and
re-videod (80 ns VRAM, the AC842a RAMDAC, a 16-bit-per-pixel mode). It shipped with its own boot
ROM image, `$3DC27823` (March 1992) [4], the only member of the family not running the
`$420DBFF3` image the [Quadra 700](q700.md) and 900 share ([mcu.md](mcu.md) §1.2).

## 1. Identity

### 1.1 What the machine is

The 950 is a speed-and-video revision of the Quadra 900's tower, introduced while the 900 was
still Apple's top-of-line machine: the developer note is a **preliminary** document with a single
chapter, structured deliberately as a delta — *\"this developer note has only one chapter. The
chapter describes the features of the Macintosh Quadra 950 that are different from those of the
Macintosh Quadra 900\"*, with the complete description deferred to the Quadra Family developer
notes [1] Preface pp. v–vi. The improved-feature list is four items long: a faster processor (33
vs 25 MHz, *\"for a performance increase of up to 30%\"*), faster video hardware (*\"by as much
as 20%\"*, *\"as much as 50% overall\"* cumulatively), 16 bits per pixel *\"even on the 21-inch
color monitor\"*, and a faster I/O bus (25 MHz *\"instead of the 16 MHz\"*, as Apple rounds it)
[1] Chapter 1 p. 4. Everything else — the case, the slot count, the IOPs, the dual SCSI, the
keyswitch, the 300 W supply — is the 900's and is inherited through the family doc
([mcu.md](mcu.md) §2, §6.2) and the 900's own note [2].

The board's project name never appears in Apple's published documents for the machine. Secondary
historical sources carry **Zydeco** (and, less consistently, *Amazon*) as the 950's project name;
Apple's own released SCSI Manager platform tables list a platform named **Zydeco** whose CPU and
SCSI clocks — 33 MHz and 24.28416 MHz — are exactly the 950's ([ncr-53c96.md](../../hardware/scsi/ncr-53c96.md)
§1.3; [5]) — but the 950 developer note uses no project name at all, and the identification of
the driver-table row with this machine is *inferred — unverified* (§6.1).

### 1.4 The tower enclosure

The case, the bay count and the supply are the 900's and are described once in its note: four
half-height internal mounting locations, two of them front-accessible for removable media, any of
them able to take a 3.5-inch or 5.25-inch SCSI device [2] §\"Internal mass-storage devices\"
p. 21; a 300 W supply with a 120 mm fan and a switched convenience receptacle for the monitor,
its +5V TRKL trickle rail keeping PRAM, power-on logic and NuBus standby alive whenever the
machine is plugged in [2] §\"Power supply\" p. 24; and the three-position keyswitch — OFF, ON,
SECURE, the SECURE position disabling ADB and floppy and auto-starting the machine when power is
applied, with the reset and interrupt buttons still live [2] §\"Keyswitch\" p. 26. All of this is
family territory ([mcu.md](mcu.md) §5.6, §6.2); the 950 note adds nothing to it beyond listing
the features again [1] p. 5. The developer note publishes no factory-configuration table for the
950 — no shipped RAM, disk or monitor load-outs appear anywhere in it (§6.8).

## 2. Deltas vs the family doc

### 2.1 The delta list

Everything not in this table is the family baseline by construction ([mcu.md](mcu.md) §2–§5):
one board architecture, one I/O island, one interrupt architecture, one IOP/Caboose low-speed
design, one NuBus '90 backplane.

| Area | Family baseline ([mcu.md](mcu.md)) | Quadra 950 |
|---|---|---|
| System bus / CPU clock | 25 MHz (700, 900) | 33.333 MHz; CPU internal 66.666 MHz via the 2X clock [1] p. 5 |
| Processor thermal | no heat sink documented | 7.6 W worst case, heat sink fitted [1] p. 5 |
| I/O bus | 15.6672 MHz, asynchronous | 24.28416 MHz (\"25 MHz\" in Apple's rounded phrasing) [1] p. 7 |
| SONIC | 20 MHz-class DP83932 | a 25 MHz version of the DP83932 [1] p. 7 |
| VRAM speed | 100 ns devices (900) | 80 ns devices [1] §\"Faster video hardware\" p. 6 |
| Video controller | DAFB, AC842 RAMDAC, version register 0–2 class | DAFB reprogrammed for the faster VRAM; version/test register answers revision 3 ([dafb.md](dafb.md) §2.2); AC842a RAMDAC ([dafb.md](dafb.md) §2.4.4) |
| Large-monitor depth | 8 bpp ceiling above the 24-bpp sizes (900) | 16 bpp added — up to 32,768 colors, \"Thousands\" in the Monitors panel [1] §\"Improved video on large monitors\" pp. 6–7 |
| RAM as documented | 1/4/16 MB SIMMs, 4–64 MB (900 note) | 4 or 16 MB per bank, 64 MB maximum [1] p. 5 |
| RAM the board holds | 4–256 MB, sixteen 16 MB SIMMs (§2.3) | 4–256 MB, the same board (§2.3) |
| Boot ROM | `$420DBFF3`, shared by 700 and 900 | `$3DC27823`, the 950's own image [4] |
| Model sense | VIA1 port A, ROM-read, per-machine straps | the `$90` pattern, `InfoQuadra950`'s `(PA & $56) == $10` test [5] |
| Speed sense | — | VIA2 port B bit 5 (`v2Speed`) = 1 [5] |
| PDS | 25 MHz 68040 timing | 33 MHz 68040 timing required of cards [1] §\"Faster PDS\" p. 6 |
| SCSI driver constants | 25 MHz-class clock factors | 33 MHz-class clock factor and selection timeout, selected from the speed-sense bit ([ncr-53c96.md](../../hardware/scsi/ncr-53c96.md) §1.3, §4.2) |

Two negations worth stating explicitly, because a faster board invites wrong guesses: the NuBus
does **not** speed up — it stays at the standard 10 MHz transaction clock with the 20 MHz
/CLK2X card-to-card rate ([mcu.md](mcu.md) §2.1) — and the interrupt architecture does not
change: the same VIA1/VIA2/pAL autovectored structure and the A/UX remap serve the 950
([mcu.md](mcu.md) §5.1).

The one number that needs care is the I/O bus: Apple's feature bullets round it to *\"25 MHz
instead of the 16 MHz\"* [1] Chapter 1 p. 4, while the section that specifies it gives
**24.28416 MHz** exactly [1] p. 7 — the same 1.5×-ish relation to the 700/900's 15.6672 MHz that
the old II-family I/O clock bore to its system clocks. The exact figure is the one to use
everywhere a number matters (the SONIC's bus-clock grade, the SCSI clock question of §6.2).

### 2.3 Memory as documented

The four-bank tower RAM geometry — banks on 64 MB physical boundaries, ROM-sized and stitched
contiguous by the MCU — is [mcu.md](mcu.md) §3.3's, and the SIMM rules (four equal 30-pin
fast-page-mode SIMMs per bank, 80 ns or faster) are the 900 note's [2] §\"RAM control\" p. 11,
inherited here. The 950 note's own statement narrows the documented module set: *\"four banks of
dynamic RAM with 4 or 16 MB per bank for a maximum of 64 MB\"* [1] §\"Summary of features\" p. 5
— that is, 1 MB or 4 MB SIMMs; the 16 MB SIMM that the 900 note allows [2] p. 11 is absent from
the 950's list, and no configuration between the two notes' statements is reconciled by any
document in evidence. Later Apple specifications acknowledge configurations up to 256 MB on this
board — sixteen 16 MB SIMMs, each bank filling its 64 MB window, which the `$3DC27823` ROM's POST
sizes like any smaller population.  Whether the 64 MB figure reflects a documentation era, a board
revision or an MCU mask change remains [mcu.md](mcu.md) §7 item 12's open question.

The register mechanics — Orwell's serial configuration register and latch strobes at
$5000E000, the boot-time programming sequence — are [mcu.md](mcu.md) §2.4–§2.7's. One field is
950-specific: the recovered **system clock speed select bit** (bit 18 of the serial
configuration register, [mcu.md](mcu.md) §2.5), which selects the 25/33.333 MHz class. The
`$3DC27823` ROM must program the 33.333 MHz class and the matching DRAM timing fields, but no
access trace of this machine's Orwell programming exists in evidence — the observed sequence of
[mcu.md](mcu.md) §2.7 is the `$420DBFF3` image's, on a Quadra 700 configuration — so the 950's
own bring-up values are *inferred — unverified* (§6.3).

### 2.4 The video revision

The 950 keeps the 900's video architecture — DAFB on the system bus, dedicated VRAM in four
banks, the slot-$9 apertures ([mcu.md](mcu.md) §3.4, [dafb.md](dafb.md) §2.1) — and changes three
things:

1. **The VRAM**: 80 ns devices against the 900's 100 ns, and the controller *\"has been
   reprogrammed to take advantage of the faster VRAM, speeding up video performance by as much
   as 20%\"* — on top of the 33 MHz processor's contribution, *\"as much as 50% overall\"* [1]
   §\"Faster video hardware\" p. 6. The register-level consequence is in the timing constants
   DAFB is programmed with ([dafb.md](dafb.md) §4.2); Apple's word *\"reprogrammed\"* does not
   settle whether the part is a new mask or a revised configuration of the same silicon
   ([dafb.md](dafb.md) §6 carries the question).
2. **The RAMDAC**: the **AC842a**, whose indirectly selected extended control register (PCBR1)
   adds the 16-bit direct-color format — big-endian x555 words, 5 bits per component, the top
   bit ignored — to the AC842's depths ([dafb.md](dafb.md) §2.4.4).
3. **The mode ceiling**: 16 bpp where the 900 topped out at 8 bpp — *\"The 16 bit-per-pixel
   video displays provide up to 32,768 colors\"*, user-selected as *\"Thousands\"* in the
   Monitors control panel [1] §\"Improved video on large monitors\" p. 6. The shipped 1 MB of
   VRAM already supports 16 bpp on the 13-inch and 16-inch RGB monitors, and 2 MB extends 16 bpp
   to the 21-inch and the 1024×768 19-inch class [1] p. 7; the complete
   resolution/VRAM/depth tables, including the 24-bpp sizes that did not change, are
   [dafb-modes.md](dafb-modes.md)'s.

Apple adds a system-software clause worth quoting exactly, because it dates the whole revision:
*\"The video hardware in the Macintosh Quadra 950 incorporates several modifications so that it
can support 16 bits per pixel. The system software has been changed to accomodate the hardware
modifications. Except for the addition of the 16 bit-per-pixel mode itself, the changes should be
transparent to application programs.\"* [1] p. 7 — the modifications are in DAFB and the AC842a,
and the compensating changes are in the ROM's video driver and the Monitors software, not in the
applications.

## 3. Per-subsystem wiring

### 3.1 Processor and the system bus

The MC68040 runs at 33.333 MHz with the 2X clock input at 66.666 MHz ([1] p. 5), drawing up to
7.6 W at 5.25 V worst case — enough that Apple fits a heat sink [1] §\"Processor power
dissipation\" p. 5. The system bus is wired exactly as the family doc describes it
([mcu.md](mcu.md) §2.1): MCU/Orwell, YANCC, DAFB and the two 53C96 paths on the processor's
pins, the PDS connector unbuffered on the same pins, alternate masters (YANCC for NuBus, the
SONIC on the I/O bus, PDS cards) arbitrated by Relayer with the 68040 parked lowest
([mcu.md](mcu.md) §5.3), and cache snooping present on the die but unused — the ROM's
uncacheable-page discipline for alternate-master buffers is the family's ([mcu.md](mcu.md)
§5.4). Nothing in the 950's re-clocking changes any of this wiring; what changes is timing
margins, and the one place Apple says so is the PDS (§4.2).

### 3.2 Memory controller

Orwell's window ($5000E000–$5000EFFF), its serial configuration register, latch strobes, the
reset overlay and the bank-stitching contract are [mcu.md](mcu.md) §2.3–§2.9's and are not
restated. The 950-specific content is one recovered register field and one gap: the clock-class
select (bit 18) must be programmed for the 33.333 MHz class, and the DRAM access-time and
refresh fields for the timing the 80 ns-class SIMMs need at the faster bus ([mcu.md](mcu.md)
§2.5) — *inferred — unverified*, since the only observed Orwell programming in evidence is the
700/900 ROM's (§2.3 above, §6.3). The four banks' 64 MB decode windows, the power-up
$10/$20/$30 split and the ROM's progressive re-stitching are the family's ([mcu.md](mcu.md)
§3.3, §2.7).

### 3.3 Video

Wiring: DAFB at the slot-$9 apertures — the 2 MB VRAM window at $F9000000, the 1 KB register
window at $F9800000 ([dafb.md](dafb.md) §2.1) — with the monitor-sense lines, the Swatch CRTC,
the DP8531 pixel-clock synthesizer and the VBL/scanline interrupt into VIA2 port A bit 6
([mcu.md](mcu.md) §3.4, §5.2). The 950's part in that file: the version/test register at +$02C
answers **revision 3**, against the 0/1/2 class of the 700/900 parts ([dafb.md](dafb.md) §2.2),
and the RAMDAC block is the AC842a with its indirect PCBR1 selection and the x555 direct format
([dafb.md](dafb.md) §2.4.4). The register values themselves — every timing constant the
reprogrammed part is driven with, and the exact indirect-selection sequence for PCBR1 — are the
device page's reconstruction and open questions ([dafb.md](dafb.md) §4.2, §6), not restated
here.

VRAM population: 1 MB shipped, *\"sockets for expanding the VRAM to a total of 2 MB\"* [1] p. 7
— the expansion is four 256 KB VRAM SIMMs into the empty banks
([dafb-modes.md](dafb-modes.md)). The shipped megabyte's soldered-versus-SIMM bank split is
documented for the 900 (two banks soldered, two for expansion, [2] Table 1-4 p. 29) but not
restated for the 950; that the 950 keeps the same split is *inferred — unverified* from its
being the same board design (§6.9).

### 3.4 SCSI

The dual-controller arrangement is the family's: SCSI 0 (the internal bus) at $5000F000 and
SCSI 1 (the external bus) at $5000F400, both 53C96 parts behind DAFB's TurboSCSI timing assist
([mcu.md](mcu.md) §3.2; [ncr-53c96.md](../../hardware/scsi/ncr-53c96.md) §2.1, §3.8), the two
buses *\"logically connected but electrically separate\"* with the internal bus tuned to
5 MB/s ([mcu.md](mcu.md) §6.2). The 950's specific content is all in the driver's constants:
Apple's Quadra-generation SCSI driver writes the DAFB TurboSCSI channel configuration at
$F9800024 — **$041 on the 33 MHz-CPU machines against $1EC on the 25 MHz machines** — and
selects the 53C96's clock conversion factor and selection timeout the same way, discriminating
the two machines on the VIA2 speed-sense bit ([ncr-53c96.md](../../hardware/scsi/ncr-53c96.md)
§1.3, §4.2). The wire-side ceiling stays narrow single-ended SCSI; the re-clocking buys shorter
programmed-I/O cycles, not a new transfer mode ([ncr-53c96.md](../../hardware/scsi/ncr-53c96.md)
§3.8).

One discrepancy lives in Apple's own released driver tables: the SCSI Manager platform list
carries the **Zydeco** row at a 24.28416 MHz SCSI clock, while the same source's Quadra
900/950 row is expressed as 25 MHz on the 33 MHz-CPU machines ([ncr-53c96.md](../../hardware/scsi/ncr-53c96.md)
§1.3). Whether the 950's 53C96 CLK is a 25 MHz-grade oscillator or the 24.28416 MHz I/O-bus
clock itself is not decidable from the evidence (§6.2).

### 3.5 Ethernet

The SONIC is the one peripheral whose **part** changes with the 950: *\"To accomodate the faster
I/O bus clock, the Macintosh Quadra 950 uses a 25 MHz version of the Sonic, the DP83932 Ethernet
controller IC made by National Semiconductor\"*, because *\"The higher clock frequency …
provides better throughput on Ethernet\"* [1] §\"Faster I/O bus\" p. 7. The DP83932's data
manual covers exactly this grade — its AC specifications are tabulated for 20 MHz and 25 MHz
bus clocks ([sonic.md](../../hardware/sonic.md) §1.2) — so the 950's part is a bus-clock grade
selection, not a different architecture. Everything else is unchanged from the 900: the
register window at $5000A000 and the station-address PROM at $50008000 ([mcu.md](mcu.md) §3.2),
the AAUI connector taking a FriendlyNet transceiver, the interrupt into VIA2 port A bit 0
through the /SLOTIRQ OR-gate ([mcu.md](mcu.md) §5.2), first-priority bus mastership of the I/O
bus with the 68040 parked ([mcu.md](mcu.md) §5.3), the ROM's Ethernet driver and the
uncacheable descriptor pages it demands ([mcu.md](mcu.md) §5.4). The register file, the DMA
engine, the reset behavior and the bring-up sequences are [sonic.md](../../hardware/sonic.md)
§2–§4's. Whether the \"25 MHz version\" is a speed-binned DP83932B or a distinct ordering part
is [sonic.md](../../hardware/sonic.md) §6's open question, not restated.

### 3.6 Low-speed I/O: the IOPs and Caboose

The tower low-speed organization is inherited whole from the 900 ([mcu.md](mcu.md) §2.10): the
SCC IOP at the $5000C000 host aperture, the SWIM/ADB IOP at $5001E000 — both the IIfx's Apple
PIC parts with the IIfx register layout ([iop.md](../iifx/iop.md) §2) — and **Caboose** managing
keyswitch, system power, the real-time clock, parameter RAM and sound control, on the VIA1
handshake lines ([mcu.md](mcu.md) §6.2). The 950 note confirms the inheritance in its feature
list — *\"intelligent I/O processors (IOPs) for floppy-disk, ADB, and serial I/O ports\"* [1]
p. 5 — and adds nothing to the wiring.

The one 950-specific question the re-clocking raises is the IOPs' own clock: the PIC's 65C02
core runs at a divide of the parent clock in the 900's 15.6672 MHz I/O domain, and no document
states whether the 950's 24.28416 MHz domain scales that parent or keeps the parts at their
IIfx rate (§6.4). The DFAC sound-input filter, whose control belongs to the system manager on
the towers rather than to VIA2 port B as on the 700 ([mcu.md](mcu.md) §4.3), is likewise
inherited unchanged.

### 3.7 Sound

The sound chain is the family's: the Enhanced ASC (the ASC-compatible \"Batman\" part with
native 16-bit stereo output, sound input and hardware CD-XA decompression) at $50014000
([mcu.md](mcu.md) §3.2; [asc.md](../../hardware/asc.md) §2.3, §3.3), Sporty output
amplification, DFAC input filtering ([mcu.md](mcu.md) §4.3). The 950's feature-list line —
*\"improved sound capability with integration of sound from CD-ROM\"* [1] p. 5 — is the tower's
CD-ROM integration: an audio cable from the internal CD-ROM drive to the main logic board
providing playback through the internal sound system, mixing with computer-generated sound, and
digital recording of the CD audio ([2] §\"Internal CD-ROM integration\" p. 24). Which of the
chain's parts performs the mixing, and whether the EASC's CD-XA decompression path is the
\"improved\" element the 950 note claims over the 900, is not stated by any document in evidence
(§6.5); the CD-XA capability itself is the EASC's, common to the whole family
([asc.md](../../hardware/asc.md) §2.3).

### 3.8 The VIAs as fitted

The VIA2 **slot bank** is identical to the 900's column of the family table
([mcu.md](mcu.md) §5.2): PA0 the SONIC's interrupt, PA1–PA4 slots $A–$D, PA5 slot $E shared
with the PDS, PA6 the built-in video. The remaining level-2 wiring is the family's: CA1 the
/SLOTIRQ aggregate, CA2 the SWIM/ADB IOP host interrupt, CB1 the sound request, CB2 the two
53C96 interrupts wired-OR ([mcu.md](mcu.md) §5.2). VIA1 carries the model sense (§1.2), the
A/UX software-interrupt and interrupt-enable bits and the interrupt-control PAL remap
([mcu.md](mcu.md) §5.1) — unchanged from the 900.

The one VIA fact unique to this machine is a **write from the board, not a read**: VIA2 port B
bit 5 is the 25/33 MHz speed-sense strap, reading 1 on the 950 and 0 on the 700/900, and it is
the input Apple's SCSI driver uses to select the 33 MHz clock constants ([ncr-53c96.md](../../hardware/scsi/ncr-53c96.md)
§1.3; [5]). The strap's exact electrical implementation — a pull-up population difference or a
buffered clock-domain signal — is not documented (§6.10).

## 4. Expansion

### 4.1 The five NuBus slots

Five physical slots, $A through $E, with the family's NuBus '90 feature set and the towers'
power and mechanical allowances — all inherited from the 900 through the family doc
([mcu.md](mcu.md) §5.6): 19 W per slot, or two 25 W and three 15 W cards, up to 95 W total
[2] Table 1-4 p. 29; oversized cards 2 inches taller than standard, with the card guide removed
to fit, allowed in the tower and nowhere else in the II family [2] §\"NuBus slots\" pp. 24–25;
the STDBYPWR pin (B25) supplying low-current +5 V to cards whenever the machine is plugged in
[2] §\"NuBus '90 features\" Table 2-1 pp. 26–27. Slot $E's resources are shared with the PDS
(§4.2). The 950 note's own line is the feature-list phrase *\"five NuBus expansion slots with
NuBus '90 features and space for oversized NuBus cards\"* [1] p. 5; no 950-specific power or
clearance figures are published (§6.11).

### 4.2 The processor-direct slot at 33 MHz

The PDS is the family's 68040 Direct Slot ([mcu.md](mcu.md) §3.5) — the processor's own pins,
unbuffered, in line with NuBus slot $E, on a 140-pin connector, with the pseudoslot decode into
slot $E's standard and super space and the mandatory /TA-or-/TEA contract for a card asserting
/PDS.SLOT.E.EN — and Apple's entire 950-specific statement is the timing: *\"For a PDS card to
operate properly in the Macintosh Quadra 950, the card must be capable of meeting the 33 MHz
timing specifications of the MC68040\"*, with the numbers referred to Motorola's *MC68040
Designer's Handbook*; *\"Except for the timing changes, the PDS in the Macintosh Quadra 950 is
identical to the one in the Macintosh Quadra 900\"*, pinouts and signal loading included [1]
§\"Faster PDS\" p. 6.

The card-design book's statement of the slot's cross-machine contract predates the 950 and needs
the timing caveat applied to it: *\"The electrical characteristics of the processor-direct
expansion connectors of the Macintosh Quadra 700 and the Macintosh Quadra 900 are identical so
that cards designed for one 68040-based computer will work in the other one as well\"* — and
cards designed for 68000/68020/68030 machines *\"will not work\"* in any of them, nor Quadra
PDS cards in other Macintosh models [3] §\"The 68040 Direct Slot expansion interface\". On the
950 the same connector carries the 33.333 MHz bus clock and the 66.666 MHz 2X rate, so a card
designed to the 700/900's 25 MHz setup-and-hold margins is outside its timing specification
even though it plugs in — the compatibility statement is electrical-form, not timing-grade
(*inferred* from [1] p. 6 and [3]; the inference is the same one Apple's own sentence makes).
The design considerations, signal loading limits and the slot-$E hang contract are [mcu.md](mcu.md)
§3.5's and are not restated.

### 4.3 Memory and VRAM expansion

Main memory expands within §2.3's rules: four banks of four equal 30-pin SIMMs, 4 or 16 MB per
bank as documented, 64 MB documented maximum, banks mixed as the family's stitching allows
([mcu.md](mcu.md) §3.3). VRAM expands from the shipped 1 MB to 2 MB by SIMM sockets
([dafb-modes.md](dafb-modes.md)), which is what unlocks 16 bpp on the 21-inch and 19-inch
classes and 24 bpp on the 16-inch ([dafb-modes.md](dafb-modes.md); [1] p. 7). The ROM SIMM
socket the 700/900 boards carry ([mcu.md](mcu.md) §2.3) is nowhere stated for this board
(§6.7).

### 4.4 Internal storage

Four internal mass-storage locations, two of them front-accessible for removable media
([1] p. 5; [2] §\"Internal mass-storage devices\" p. 21) — the bay set that ships the machine
with a floppy, a hard disk and optionally an internal CD-ROM drive, the CD-ROM cabled to an
internal SCSI connector for data and to the logic board for audio ([2] §\"Internal CD-ROM
integration\" p. 24). Internal devices land on SCSI 0, the tuned internal bus
([ncr-53c96.md](../../hardware/scsi/ncr-53c96.md) §1.3); external devices on SCSI 1.

### 4.5 What this machine does not expand by

No second-level cache slot or card exists for the 68040's off-chip cache on this board — the
processor's internal caches are the whole cache subsystem ([mcu.md](mcu.md) §4.1). There is no
video-input path, no communication slot, and no processor card: the 68040 is soldered to the
board, and the machine's one processor-direct connector is shared with NuBus slot $E. Five NuBus
slots, the PDS, sixteen SIMM sockets, four VRAM banks and four drive bays are the entire
expansion surface.

## 5. Boot sequence summary

The boot contract — power sequencing, the access-triggered ROM-at-zero overlay, memory sizing
and stitching, IOP bring-up, the Slot Manager's declaration-ROM search — is the family's
([mcu.md](mcu.md) §2.7, §2.9–§2.10, §3.6, §5.6). This machine's branch points, in order:

1. **Power-on.** The keyswitch and soft-power sequencing run through Caboose
   ([mcu.md](mcu.md) §5.6): the machine can be turned on from the keyboard in the ON position
   and auto-starts under power application in SECURE [2] §\"Keyswitch\" p. 26. Reset release
   to the 68040 is the system manager's act.
2. **Overlay fetch.** The MCU maps the 1 MB ROM at $00000000 with RAM disabled, and the 68040
   fetches from the overlaid image; the first access to the $40000000 aperture drops the
   overlay and restores RAM at zero ([mcu.md](mcu.md) §2.9). The image is the 950's own
   `$3DC27823` [4] — this is the one ROM of the family that carries the 950's platform record
   and video driver.
3. **Machine identification.** The identify code reads VIA1 port A; the `$90` strap pattern
   satisfies the `InfoQuadra950` test, `(PA & $56) == $10`, and selects this machine's hardware
   paths — the tower IOP/Caboose organization, the dual-SCSI driver constants and the revised
   video driver (*observed* in the `$3DC27823` image's identify code [4]; the test itself
   recovered from Apple's released ROM software [5]). The VIA2 port B speed-sense bit reads
   1, selecting the 33 MHz timing constants wherever software asks.
4. **Memory sizing.** The ROM sizes the four banks and programs Orwell's serial configuration
   register — including the 33.333 MHz clock class — committing each staged selection with the
   latch strobes and re-stitching the banks contiguous ([mcu.md](mcu.md) §2.5–§2.7). The 950's
   own programming values are not captured in evidence (§6.3); the sequence is the family
   contract's.
5. **Video bring-up.** The driver reads the DAFB version/test register (revision 3 on this
   part), probes the monitor-sense lines, loads the palette and programs the CRTC and the
   DP8531 for the connected monitor's timing with the 80 ns VRAM's constants
   ([dafb.md](dafb.md) §2.2, §3.5, §4.1–§4.2). On a monitor whose mode is 16-bpp-capable and
   with the VRAM for it, the Monitors panel's \"Thousands\" selection reaches the AC842a's
   PCBR1 extension ([dafb.md](dafb.md) §2.4.4; [1] p. 7).
6. **Low-speed I/O.** The ROM loads and starts the SCC and SWIM/ADB IOPs through their host
   apertures ([mcu.md](mcu.md) §2.10; [iop.md](../iifx/iop.md) §9–§11) and hands RTC/PRAM
   service to Caboose ([mcu.md](mcu.md) §6.2).
7. **SCSI.** The driver writes the 33 MHz TurboSCSI channel configuration into DAFB and
   programs the 53C96s' clock conversion factor and selection timeout from the speed-sense
   discrimination ([ncr-53c96.md](../../hardware/scsi/ncr-53c96.md) §4.2), then scans the
   internal bus for the boot device.
8. **Slots.** The Slot Manager polls the physical slots $A–$E and the built-in video's
   pseudo-slot $9, with empty slots failing cleanly through the family's error contract
   ([mcu.md](mcu.md) §3.6) — the tower's five slots plus video is the family's largest poll
   set.
9. **System software.** The machine reports Gestalt machine type 26 to applications [1] p. 8.
   The system-software changes the note mentions (§2.4) ship with the machine's ROM and the
   matching Monitors/QuickDraw software; the minimum system version that carries them is not
   stated in evidence (§6.12).

## 6. Open questions

1. **The Zydeco identification.** Apple's released SCSI Manager platform tables list a
   \"Zydeco\" row at 33 MHz CPU / 24.28416 MHz SCSI clocks ([ncr-53c96.md](../../hardware/scsi/ncr-53c96.md)
   §1.3), secondary sources name the 950's project Zydeco, and the developer note uses no
   project name — but no Apple document in evidence states that Zydeco *is* the Quadra 950, and
   the same driver table lists the 900/950 pair as its own row. The identification is inferred
   from the matching clocks alone.
2. **The 950's SCSI chip clock.** Is the 53C96 CLK on this board a 25 MHz-grade oscillator (the
   \"25 MHz on the 33 MHz-CPU machines\" phrasing) or the 24.28416 MHz I/O-bus clock itself (the
   Zydeco row's figure)? The clock-conversion-factor difference between grade 5 (20.01–25 MHz)
   and grade 6 (25.01–30 MHz) makes the answer observable in principle, but no capture or
   schematic in evidence settles it.
3. **The 950's Orwell bring-up values.** The only observed MCU programming sequence in evidence
   is the `$420DBFF3` ROM's, on a Quadra 700 configuration ([mcu.md](mcu.md) §2.7). The
   `$3DC27823` image's own writes — in particular the 33.333 MHz clock-class bit and the DRAM
   timing fields the faster bus needs — have never been traced.
4. **The IOPs' parent clock.** The PIC/IOP 65C02 cores run at a divide of a parent clock in the
   900's 15.6672 MHz I/O domain; whether the 950's 24.28416 MHz domain scales that parent (and
   the IOPs' serial and floppy cadence with it) or keeps the parts at the IIfx rate is stated
   nowhere in evidence.
5. **The \"improved sound capability\" clause.** The feature list credits the 950 with
   *\"integration of sound from CD-ROM\"* [1] p. 5, but the CD-ROM audio integration is
   documented as a 900 feature [2] p. 24. What, if anything, differs in the 950's sound path —
   and whether the EASC's CD-XA decompression is the improvement meant — is not established.
6. **The SysEnvirons machine type.** The note gives Gestalt 26 [1] p. 8 and nothing else; the
   SysEnvirons type the 950 reports (20 on the 700, 18 on the 900) appears in no document in
   evidence.
7. **The ROM SIMM socket.** The 700/900 boards carry a ROM SIMM socket that disables the
   soldered ROM when populated ([mcu.md](mcu.md) §2.3); no 950 document mentions the socket,
   and whether this board carries it is unverified.
8. **Factory configurations.** The preliminary note publishes no configuration table: shipped
   RAM, disk, monitor and VRAM load-outs for the 950 appear in no document in evidence.
9. **The shipped VRAM bank split.** The note says 1 MB shipped with sockets to 2 MB [1] p. 7;
   the soldered-versus-SIMM split of the shipped megabyte is documented only for the 900
   (two soldered banks, two for expansion [2] Table 1-4 p. 29) and is inferred, not stated,
   for this board.
10. **The speed-sense strap's electrical form.** VIA2 port B bit 5 reads as the 25/33 MHz
    discriminator in Apple's released software [5]; whether the 950's 1 is a pull-up
    population difference, a jumper, or a clock-domain-derived signal is not documented.
11. **The 950's slot power and clearance figures.** The note's expansion statements are
    feature-list phrases; the 95 W budget, per-slot watts and oversized-card clearances are
    the 900 note's [2] pp. 24–29, and no 950-era document restates them for this machine. The
    33 MHz board's higher dissipation makes silent inheritance worth measuring rather than
    assuming.
12. **The minimum system software for the 16-bpp path.** The note states the system software
    was changed to accommodate the revised video hardware [1] p. 7 but names no version; the
    earliest system release carrying the AC842a driver path is not established from the
    evidence here.
13. **The board's physical revision.** The 950 is *\"basically a higher-performance Macintosh
    Quadra 900\"* [1] Chapter 1 p. 4, but the 80 ns VRAM, the AC842a and the reprogrammed DAFB
    imply at least a video-path revision of the Eclipse board; whether the 950's main logic
    board is a new PWB revision or the 900's with a changed video section is not stated by
    any document in evidence, and no 950 schematic is in evidence.
