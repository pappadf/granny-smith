# Apple Network Server 500/132

The Apple Network Server 500/132 ('Shiner LE') is the entry model of the Network Server family: a 132 MHz PowerPC 604 on a removable processor card over a 44 MHz system bus, 32 MB of parity DRAM, a 512 KB L2 cache DIMM, a single 325 W supply, seven front hot-swap drive bays, six PCI slots — and AIX as its only bootable operating system. Everything the machine shares with the [700/150](ans700.md) and the rest of the family — the board architecture, the memory map, the GBus devices, the interrupt remap, the backplane, the boot chain — is documented once in the family doc and cited here by section, never restated; this page carries only what is unique to the 500, plus its own column of the family's tables. Read [ans.md](ans.md) first.

## 1. Identity

### 1.1 What the machine is

The 500/132 is the lower of the Network Server line's two price points, separated from the 700 by "More drive Bays, Redundant Power Supplies, Higher Clock frequency, More Cache memory" [1] §1.1.2 p. 2 — the four axes on which this page's deltas are all taken. Its developer-note feature list names it directly: "604 µP at 132 MHz", "Expandable Main Memory to 512 Mbyte", "325 Watt modular power supply", "On Board video to 1024x768 @ 8-bits" [1] §1.3 p. 2. The Service Source calls it, in its own overview, a high-performance server "based on the PowerPC 604... RISC microprocessor", listing "132-MHz PowerPC 604 microprocessor, 32K on-chip cache, 512K Level 2 cache, 32 MB main DRAM memory, expandable to 512 MB" [2] Basics/Overview p. 2.

Apple's internal name for the project is **Shiner** [1] §8.2 p. 31, and Apple's own documents split the two boxes as the **LE** and the **HE**: the Service Source's electrical specification trades off the +3.3 V and +5 V outputs with "total power for both not to exceed 180 watts for the LE, 260 watts for the HE" [2] Specifications/Electrical p. 12, and the Hardware Developer Notes' interconnect matrix labels the 700-specific cabling "specific to SHINER HE (Hendy +)" [1] §8.2 p. 31 — the enclosure being the "Hendy" product design [1] §8.1 p. 30. The full codename "Shiner LE" for this machine and the January–February 1996 introduction window rest on secondary sources only; no Apple document in evidence dates the introduction (§6.1).

The machine's operating-system contract is the family's and is its defining property: AIX, no Mac OS — the production ROM carries no Mac OS Toolbox and answers a Mac OS boot with `MacOS is not supported` ([ans.md](ans.md) §1.3). This machine "Requires AIX version 4.1.4 or higher" [2] Specifications/Processor p. 1, and the AIX release in evidence as its install medium is 4.1.5 ([ans.md](ans.md) References, AIX media). Apple's positioning sentence — "the first servers from Apple to be designed as high performance, scalable, reliable, and serviceable servers targeted at Unix accounts serving Macintosh Desktops" [1] §1 p. 2 — is the family's ([ans.md](ans.md) §1.1); the 500/132 is its cheapest expression. AIX is not bundled: "AIX software does not come preinstalled in standard configurations of the Network Server 500 and 700 Series. The AIX software must be purchased separately." [2] Basics/Configurations p. 7.

### 1.2 Identity values

The Network Server has no Macintosh identity machinery at all: there is no Gestalt table entry, no box flag, no `Gestalt` machine type, because no Mac OS Toolbox ROM exists to host them ([ans.md](ans.md) §1.3). What identifies the machine to software, in full:

| Identity value | Value | Witness |
|---|---|---|
| Root `compatible` / `model` | `AAPL,ShinerESB` + `MacRISC`, set when the boot ROM's 53C825A probe succeeds | [ans.md](ans.md) §1.3, §5.1 (*observed*) |
| Boot ROM | the family's production image, Open Firmware 1.1.22 — header checksum $962F6C13, version field $077D.28F2 (byte-identical to the Power Macintosh 9500 v2 ROM's; identify by checksum, never by version) | [ans.md](ans.md) §1.3 |
| ROM per-model distinction | **none** — the same 4 MB image serves the 500 and the 700; no Open Firmware mechanism in evidence distinguishes the two models | [ans.md](ans.md) §6.1–§6.2 |
| Hammerhead part identifier (`$F8000000`) | first byte `$39` — the TNT identification path | [hammerhead.md](../tnt/hammerhead.md) §2.2 |
| Hammerhead machine-class flag (`+$20`) | the 9500 arm — the ROM is built on the 9500 v2 codebase; no Apple document states the ANS value (*inferred - unverified*, §6.11) | [hammerhead.md](../tnt/hammerhead.md) §2.3 |
| Board Register 1 top byte (GBus device 0xA, $F301A000) | with the front keyswitch locked: **$28** — `BoxId0` set, `BoxId1` clear, `Keyswitch ServiceL` deasserted, `Keyswitch LockedL` asserted, `TwoSuppliesH` **clear** | [ans.md](ans.md) §3.5.1 (*observed*) |
| `BoxId0`/`BoxId1` straps | 1/0 — the same on every Network Server, 500 and 700 alike; not a model discriminator | [ans.md](ans.md) §3.5.1 |
| `TwoSuppliesH` | **clear on this machine** — the single register-level 500/700 discriminator, set only on the 700's dual-supply backplane | [ans.md](ans.md) §3.5.1 |
| Device tree root | `/PowerPC,604@0` with its `l2-cache@0,0` child; the tree shape is the family's published one | [ans.md](ans.md) §4.2 |
| AIX's view | the ODM device database names the parts, never the model; AIX configures a 500 and a 700 identically | [ans.md](ans.md) §2.7, §5.2 |
| LCD identity display | ROM version line, parity DRAM size, and the card's clock figures — this machine's expected reading in §5.2 | [2] Basics/Overview of New Technologies p. 53; §5.2 |

The two identity facts worth underlining: a working 500 is *indistinguishable* from a 700 in every firmware-visible way except the `TwoSuppliesH` bit — software that needs to tell them apart must read Board Register 1 — and the machine-identity signal the ROM actually keys on is not a model strap at all but the pair of Symbios 53C825A SCSI controllers ([ans.md](ans.md) §1.1, §5.1).

### 2.2 Clocks on this machine

The clock architecture is the family's: the motherboard takes its system clock from the processor card, which must supply a `refClk` of at least 1 V/ns transition rate, and the board returns `clkToProc` roughly 700 ps in advance of the ASICs; supported system speeds are 40–50 MHz ([ans.md](ans.md) §2.2). This machine's column:

| Clock | Value | Authority |
|---|---|---|
| Processor core | 132 MHz [2] Basics/Overview p. 2 | [5]; [1] §1.3 p. 2 |
| Processor (AR) bus | 44 MHz | *inferred - unverified*: no Apple document prints the 500's bus rate. The derivation is three-legged — the TNT platform's ratio law, "the processor bus at 40 MHz or 44 MHz (one-third the processor speed)" [10] "Bus Clock Rates" p. 11, of which 132 MHz takes the 44 MHz grade; the family's fast-L2 rule "Network Server ROM enables 'fast L2' mode for bus speeds of 44 MHz or less" [1] §6.2 p. 21, a rule that can only have been written because a 44 MHz machine exists; and the family index's own figure ([ans.md](ans.md) §6.1, §5.4). Corroborated by the observed 11 MHz time base (next row) |
| Time base / decrementer | 11 MHz — one quarter of the bus clock, published by the production ROM as the CPU node's `timebase-frequency` | *observed* on a full boot of the production ROM in this machine's configuration [11] |
| PCI buses | 33 MHz, asynchronous ([ans.md](ans.md) §5.4) | (family) |
| DRAM timing | 60 ns with parity detected, 70 ns without ([ans.md](ans.md) §2.3) | at 44 MHz the 70 ns penalty of the family's 20%-at-50 MHz sentence is proportionally smaller; Apple gives no 44 MHz figure |
| L2 "fast" mode | **on** — the ROM's rule keys on the bus clock, not the processor part ([ans.md](ans.md) §2.4) | [1] §2.4.2 p. 8 |
| Fast/wide SCSI | up to 20 MB/s per channel, 40 MB/s for the pair ([ans.md](ans.md) §5.4; [sym53c8xx.md](../../hardware/scsi/sym53c8xx.md) §1.5) | (family) |
| External 53C94 | 25 MHz ([ans.md](ans.md) §5.4) | (family) |

Because the bus clock is a property of the installed card ([ans.md](ans.md) §2.2), every rate downstream of the card moves with a processor upgrade: installing the 200 MHz card raises the bus to 50 MHz, turns fast L2 off, and moves the time base to 12.5 MHz (§4.3). The 33 MHz PCI clock and the two SCSI cell clocks do not move.

### 2.3 Memory population

The memory law is the family's — eight 168-pin DIMM slots in four interleaved bank pairs labelled 1A/1B through 4A/4B, byte parity in the datapath, the parity-driven 60/70 ns DRAM timing switch, parity errors raising MCP, and the 512 MB ROM decode ceiling ([ans.md](ans.md) §2.3). This machine's population and the parts it takes:

- **72-bit DIMMs.** The specification is "168-pin, 72-bit, 60 ns (parity) or 70ns (non-parity) DRAM DIMMs" [2] Specifications/Memory p. 2 — 72 bits is 64 data plus eight parity, the physical expression of the family's byte-parity datapath ([ans.md](ans.md) §2.3). The brochure describes the same modules as "error-detecting parity DRAM" and specifies the slots as "eight slots for 168-pin, 72-bit, 60ns DIMMs" [5].
- **32 MB standard, 512 MB ceiling.** "32 MB standard expandable to 512 MB" [2] Specifications/Memory p. 2, the same ceiling as the 700's — the cap is the ROM's, not the model's ([ans.md](ans.md) §2.3). Above it the documented failure mode is a hang in the long RAM test, not a clean error ([ans.md](ans.md) §2.3).
- **Population in pairs.** Every factory memory configuration and every upgrade kit is two DIMMs at a time — the 32 MB fit is a matched pair, the 16/32/64 MB kits are pairs ([5]; §1.4) — which is what fills a bank pair and earns the 128-bit interleave ([ans.md](ans.md) §2.3). The two-DIMM 32 MB population is attested for the 700's 32 MB configuration; the 500's own factory pair is not separately published (*inferred - unverified*, §6.2).
- **The parity timing coupling applies in full.** One non-parity DIMM drops all memory to 70 ns timing ([ans.md](ans.md) §2.3); since parity memory is both the shipped configuration and the faster one, there is no reason to run this machine non-parity.
- **Device rules** — sixty-four-megabit technology recommended for large DIMMs, FCT buffers, ACT "specifically not supported" — are the family's ([ans.md](ans.md) §2.3).

### 2.4 The L2 cache as shipped

The cache subsystem is the family's: an 8500-compatible cache DIMM ([ans.md](ans.md) §2.4), sensed by Hammerhead through the size code in the register at +$E0, where 512 KB is code 0 ([hammerhead.md](../tnt/hammerhead.md) §2.8). This machine ships 512 KB — "512 KB of Level 2 cache" [2] Specifications/Memory p. 3 — against the 700's 1 MB, which is code 2 on the same strap ([hammerhead.md](../tnt/hammerhead.md) §2.8). POST maps, zeroes, tests and enables it, in that order ([ans.md](ans.md) §2.7), and the LCD reports the result ("Testing L2 Cache SIMM", then the size line; §5.2).

The one 500-specific behaviour is the fast-L2 rule: the ROM "enables 'fast L2' mode for bus speeds of 44 MHz or less", which "decreases latency to the L2 by one cycle" [1] §2.4.2 p. 8, §6.2 p. 21. On a 44 MHz bus the rule fires, and this is the only shipping Network Server on which it does ([ans.md](ans.md) §2.4) — the 500's L2 runs one cycle faster than the same DIMM would run in a 700. The rule is a function of the installed card's bus speed, not of the processor part: the 200 MHz upgrade card removes it (§4.3).

The DIMM's own requirements are the family's: tag SRAM 8 ns or better (7 ns preferred), cache SRAM 11 ns or better, and the recorded erratum against early Motorola burst SRAM whose "clocking glitches... cause failed burst writes" ([ans.md](ans.md) §2.4).

## 3. Per-subsystem wiring

### 3.1 The processor card and the 604

The card architecture is the family's and is cited, not restated: the ANS-specific connector and form factor (a 180-signal-contact AMP dual-90 edge connector, part 94-7831-08), the card-sourced clocking, the current limits (0.4 A at +12 V, 12 A at +5 V, 24 A at +3.3 V), the `OffSenseOut` unseated-card power interlock, the `ParityErrL`-to-MCP routing, and the ~500 ms processor-card reset de-assertion after board reset ([ans.md](ans.md) §2.2, §2.7). Two facts make the card *this machine's*:

- **It is a 604 at 132 MHz** — "132-MHz PowerPC 604 processor card" [2] Basics/Configurations p. 5, with "Integrated floating-point unit and 32K level 1 cache memory", "located on upgradable, replaceable CPU card" [5]. The 604 needs the connector's inserted clock delay ("processors with 0 ns output hold time... will require inserted clock delay of at least 1 ns", [ans.md](ans.md) §2.2), and its time base and decrementer tick at one quarter of the bus clock — 11 MHz here (§2.2).
- **It is single-socketed.** The card format was designed for two processors and 70 W of card dissipation ([ans.md](ans.md) §2.2), and the 700/200SMP shipped the dual configuration, but no dual-processor card was ever offered for the 500 ([2] Basics/Overview pp. 1–3 names the SMP configuration only as a 700). On this machine the second socket's supporting machinery — the Ethernet-PROM doorbell on EXT10, the timebase lock-step register at GBus $1C020 ([ans.md](ans.md) §3.5.4, §5.3) — is present and idle.

The card is not a Power Macintosh 9500 card: "the physical connector and card form factor are specific to the Network Server" and "the pinout and form factors are not compatible with the 9500" ([ans.md](ans.md) §2.2). The upgrade path is a card swap within the family (§4.3).

### 3.2 Memory and parity as fitted

§2.3 carries the population rules; nothing about the memory array itself is 500-specific beyond the factory fit. The parity datapath, the 60/70 ns timing decision the boot ROM makes from "the detected bus speed and detected parity" ([ans.md](ans.md) §2.3), and the 512 MB ROM decode cap are the family's in full. On this machine the ROM detects a 44 MHz bus and parity DIMMs, and therefore sets 60 ns timing ([ans.md](ans.md) §2.3) — the timing a factory 500 actually runs.

### 3.3 The chip set as fitted

The fitted silicon is the family roster exactly, with no 500-specific parts: Hammerhead, the two Bandit bridges, Grand Central and its Curio cells (53C94, MACE, ESCC, AWACS, SWIM III), the Cuda, the two Symbios 53C825A SCSI controllers, and the Cirrus 54M30 video device — six devices on Bandit 1, four slots on Bandit 2, the full IDSEL map of ([ans.md](ans.md) §3.3), ten DBDMA channels with channel 10 absent with MESH, and the six GBus devices including the LCD, the board registers and the Ethernet address PROM ([ans.md](ans.md) §3.4–§3.5, §4.1). The device tree it produces — `/PowerPC,604@0` with the `l2-cache` child, `bandit@F2000000` carrying the 53C825A pair, `gc@10` with the 9500's whole I/O subtree, the 54M30 at `@F` — is the family's published tree ([ans.md](ans.md) §4.2), and the 500's instance of it differs from the 700's in exactly one visible way: the `TwoSuppliesH` bit of Board Register 1 reads clear (§1.2).

The register-level 500/700 discriminators, complete list:

| Register | 500 reads | 700 reads |
|---|---|---|
| Board Register 1, `TwoSuppliesH` (bit 15) | clear | set ([ans.md](ans.md) §3.5.1) |
| Board Register 2, supply-fail/hot bits (bits 12–15) | one supply's worth meaningful; which physical supply maps to `FailPowSupplyLeft` vs `FailPowSupplyRight` is not documented (§6.3) | two supplies, left bay shipped ([ans.md](ans.md) §3.5.2; [2] Overview of New Technologies p. 47) |
| Hammerhead +$E0 L2 size code | 0 (512 KB) ([hammerhead.md](../tnt/hammerhead.md) §2.8) | 2 (1 MB) |
| Everything else | identical | identical |

### 3.4 SCSI: the backplane and the media bays as fitted

The two 53C825A controllers, their placement (Bandit 1 IDSEL 17 and 18, OF units `53c825@11` and `@12`), their big-endian strapping and their 20 MB/s-per-channel rate are the device page's and the family's ([sym53c8xx.md](../../hardware/scsi/sym53c8xx.md) §1.3, §1.5, §1.6; [ans.md](ans.md) §4.1); the hot-swap carrier mechanism, the FutureBus carrier connector, the drive power limits and the RAID interface are the family's ([ans.md](ans.md) §2.8). What is this machine's is the population:

- **Seven front bays, no rear bays.** "Front bays support seven half-height or three full-height (5.25-inch) tray-mounted SCSI devices; SCSI IDs are electronically preconfigured in each bay location" [5]. The 700's rear bracket and its two fixed bays are excluded: the bracket kits "are available only for the Network Server 700 models" [5], and the rear-mounted drives appear in the back view as "Optional rear bracket-mounted drives (NS700 Series only)" [2] Basics/Back View p. 25.
- **The 4+3 split across the two channels.** "Top four bays share one (20MB/sec) Fast/Wide SCSI-2 channel; Bottom three bays share a second" [5] — matching the firmware's disk aliases, `disk0`–`disk3` through `53c825@11` and `disk4`–`disk6` through `@12` ([ans.md](ans.md) §1.3).
- **SCSI ID assignment.** "On Channel 0, SCSI IDs 0–3 are assigned to front drive bays on all models of the Network Server. On Channel 1, SCSI IDs 4–6 are assigned to front drive bays on all models"; "SCSI ID 7 on both channels is reserved for the Network Server PCI RAID Disk Array Controller" [9]. The 500-specific consequence: with no rear bays, "On Channel 1, SCSI IDs 0, 1, 2, and 3 are available on the Network Server 500/132" for external arrays — where the 700/150 leaves only IDs 2 and 3 [9].
- **Device counts.** "A total of 14 SCSI devices (seven internal and seven external) can be connected to the server without adding additional PCI cards" [2] Specifications/I/O p. 4; "the buses accommodate 4, 3, and 7 SCSI devices, respectively" — four on fast/wide channel 0, three on channel 1, seven on the external SCSI-1 bus [4]. The internal buses also carry "the built-in hard disk drive, CD-ROM drive, optional DDS-2 DAT drive, and up to six additional internal SCSI drives", and Apple's tuning advice is to "balance the load between the two internal buses" [4].
- **The standard drive.** The 2 GB Fast/Wide drive (M4022Z/A) "operates at 7200 revolutions per minute (RPM), supports tag command queuing for increased disk performance, provides a sustained data rate of 7MB/sec, includes a standard 68-pin SCSI-2 connector", and ships preinstalled in a drive tray [5]. The AppleCD 600i is the 4×-speed internal CD-ROM [2] Specifications/Disk Storage p. 9; slot 0 of the backplane is the expected CD-ROM position ([ans.md](ans.md) §2.8).
- **The media bays.** The floppy, CD-ROM and the optional tape drive occupy the front media bays above the drive-bay area, behind the same security door [2] Basics/Front View p. 23; [1] §8.2 p. 31. The tape options are the DDS-2 DAT ("4GB uncompressed, up to 12GB compressed" [5], "DAT2 tape drive" in the standard configuration [2] Basics/Configurations p. 5) and the 8 mm drive ("20GB uncompressed, 40GB compressed" [5]).
- **The external bus.** The third, narrow bus — the 53C94 on Grand Central device 0x0 and DBDMA channel 0 ([ans.md](ans.md) §2.8) — serves "external devices and is compatible with most 50-pin SCSI drives such as those used with the Apple Workgroup Server 95, 6150, 8150, and 9150" [4], up to seven devices at SCSI-1 speed [2] Specifications/I/O p. 4.
- **Hot swap.** The electrically-timed carrier mechanism is the family's ([ans.md](ans.md) §2.8); Apple's user-facing caution belongs to this machine too: hot-swapping "requires procedures specific to the operating system in order to protect data" [4], and the Service Source adds that "an optional PCI RAID card must be installed to ensure that data will not be lost when drives are hot-swapped" [2] Basics/Overview of New Technologies p. 47. Total disk capacity with RAID is 368 GB [2] Basics/Overview p. 2, and up to 56 external SCSI devices hang off optional PCI RAID cards [5].

### 3.5 Video as fitted

The 54M30's identity, placement (Bandit 1 IDSEL 15, `54m30@F`, PCI $1013:$00A0), 1 MB little-endian frame buffer, 8 bpp big-endian ceiling, 68 MHz extended-RAS DRAM, missing interrupt line and driver reality are the family's ([ans.md](ans.md) §2.5). This machine's column of the video specification:

- **Connector:** "Standard three-row DB-15 video port for display support (Macintosh Display Adapter included)" [5] — the service manual names it "SuperVGA (SVGA) port requires an HDI-15 cable" [2] Specifications/I/O p. 5. The Macintosh Display Adapter in the box is what lets an Apple display with a DB-15 cable connect [5].
- **Modes:** 640×480 at 60, 70 and 72 Hz, 800×600 at 60, 72 and 75 Hz, 1024×768 at 60, 72 and 75 Hz — all at 256 colors [2] Specifications/Sound and Video p. 7.
- **Monitor reach:** "Support for up to 20-inch Apple displays at 256 colors" and "most third-party displays as well as VGA and SVGA monitors" [5]; the Service Source lists 14-, 15-, 17- and 20-inch multisync support [2] Basics/Overview p. 3.
- **Software:** AIX drives the part at 8 bpp as the console framebuffer; the production ROM contains no Mac OS driver for it ([ans.md](ans.md) §2.5). AIX's own LCD startup code names the graphics adapter configuration stage (§5.4).

### 3.6 Communications, sound, and input

- **Ethernet.** The Curio/MACE cell is the family's, brought out on "AAUI-15 Ethernet connector (requires adapter)" [5]; there is no 10BASE-T PHY and the 9500's `ETH10BT_Link` bit is unsupported ([ans.md](ans.md) §2.1). AIX's configuration stage for the network is LCD code 585 (§5.4).
- **Serial.** Two "DMA DIN-8 serial ports (RS-232/RS-422)" [5], "compatible with LocalTalk and GeoPort cables; mini DIN-8 connectors" [2] Specifications/I/O p. 4 — the ESCC channels of the family roster ([ans.md](ans.md) §4.1). AIX configures them as serial ports 1 and 2 (LCD codes 826 and 831, §5.4).
- **ADB.** "One Apple Desktop Bus port for a keyboard, mouse, or a three-button mouse" [2] Specifications/I/O p. 4; the supported population is "ADB keyboards with numeric keypads" and the ADB Mouse II [5]. Two AIX-side facts are load-bearing on this machine: "AIX requires an extended keyboard for installation" [2] Specifications/I/O Devices p. 8, and AIX configures the keyboard, mouse and floppy as separate adapter stages (LCD codes 821/823/828/921/925/935, §5.4). The port's budget is the family's Macintosh one: 500 mA for all ADB devices, a maximum of three devices recommended, the mouse drawing 10 mA and keyboards 25–80 mA [2] Specifications/Electrical p. 13; [5].
- **Sound.** "16-bit stereo sound input and output ports" [2] Specifications/Sound and Video p. 6 — the AWACS path, unchanged from the TNT platform ([ans.md](ans.md) §2.1), and the path the system boot "quack" sounds through ([ans.md](ans.md) §2.7). AIX never drove the codec as a device ([ans.md](ans.md) §2.7).

## 4. Expansion

### 4.1 The six PCI slots

The slot map, the IDSEL assignment and the electrical layer are the family's, cited in full: six slots, 32-bit 5 V, slots 1–2 on Bandit 1 at IDSEL 13–14 and slots 3–6 on Bandit 2 at IDSEL 13–16, a "PCI 2.1 compliant" aim with Special Cycle support and discontinuous byte enables as open issues, and the Cache-Line-Size / Write-with-Invalidate / Read-Line guidance ([ans.md](ans.md) §3.3). The 500's own numbers:

- **Power.** All six cards together: "Not to exceed 50.0 watts in any combination", budgeted at 10.0 A on +3.3 V, 10.0 A on +5 V and 2.0 A on +12 V [2] Specifications/Electrical p. 14; "Not to exceed 50 watts in any combination" with the per-card PCI 2.1 limit of 25 W always applying [1] §7.1.2 p. 22. The 700's budget is 90 W ([ans.md](ans.md) §3.3).
- **Cards Apple sold for it.** The PCI RAID Disk Array Card M4030Z/A with its 68-pin external cable M4031Z/A, the PCI Fast Ethernet Card (100Base-TX) M3906Z/A, and the PCI Ethernet Card (10Base2/10Base-T/AAUI) M4709Z/A [2] Basics/Options and Upgrades pp. 8–10 — with the brochure claiming "support for up to six PCI Ethernet cards" [5]. AIX's ODM stanzas name the expected plug-in classes, including the Mylex `dac960` RAID card and the DEC 21040/21140 Ethernet parts ([ans.md](ans.md) §2.7).
- **Slot 1 is the RAID slot.** The logic-board diagram labels it "Slot 1 Bus 0 (Raid)" ([ans.md](ans.md) §2.8), and the RAID card's boot-path table runs `pci1/dac960@d` for slot 1 through `pci2/dac960@10` for slot 6 ([ans.md](ans.md) §2.8, citing the RAID card guide). On the RAID card's own SCSI channels, ID 7 is reserved for the controller and the array's logical drives take IDs 8–15 ([ans.md](ans.md) §2.8); external arrays on channel 1 may use SCSI IDs 0–3 on this machine because its rear-bay positions do not exist (§3.4) [9].

### 4.2 Drive and media bays

§3.4 carries the backplane wiring. The bay inventory as expansion sites: seven tray-mounted front bays taking half-height devices (or three full-height 5.25-inch) with electronically preconfigured SCSI IDs [5]; the media bays above them holding the standard CD-ROM and floppy and the optional DDS-2 DAT or 8 mm tape [2] Basics/Front View p. 23; and no other internal storage sites — the 700-only rear bracket is not available for this machine ([2] Basics/Options and Upgrades p. 10; [5]). Drive power per bay is the family's 1.1 A at +5 V and 1.3 A at +12 V average, doubled for full-height drives, with drives configured for spin-up on command ([ans.md](ans.md) §2.8; [2] Specifications/Electrical p. 15).

### 4.3 Memory, cache and processor upgrades

- **Memory.** Paired parity DIMM kits to the 512 MB ROM ceiling (§2.3, §1.4) — eight 64 MB or four 128 MB DIMMs is the documented maximum population ([ans.md](ans.md) §2.3).
- **Cache.** The 512 KB DIMM can be replaced by larger 8500-compatible DIMMs within the family's SRAM speed rules ([ans.md](ans.md) §2.4); no 500-specific cache upgrade is documented.
- **The processor card.** The one documented field upgrade is the 200 MHz card: the procedure is "removing your existing processor card (132 or 150 MHz)" and installing "the 200-MHz processor card upgrade" [7] — open the rear drawer lock, remove four thumbscrews, slide the drawer, pull the card by its edges, seat the new card in the guides, close and lock [7]. Installed in a 500, the card converts the machine to the performance profile of the 700/200: the bus moves from 44 to 50 MHz, fast L2 turns off, the time base moves to 12.5 MHz ([ans.md](ans.md) §2.4, §6.1). Note that the leaflet's illustration titles the part "PowerPC™ 604 processor card" [7] while the Service Source names the 700/200's processor a 604e [2] Basics/Overview p. 3 — the leaflet's label is presumably generic (§6.9). Secondary sources also describe a 176 MHz upgrade card for the 500; no Apple document in evidence mentions it (§6.10).

### 4.4 Enclosure, rack mount, and physical security

The enclosure is the family's Hendy tower ([ans.md](ans.md) §2.1) — 24.5 × 16.5 × 18 inches, 84–92 lb depending on drives [2] Specifications/Physical p. 16 — with this machine's front view carrying "a single power supply" where the 700's carries two [2] Basics/Front View p. 23. The physical-security model is unusually explicit for an Apple machine and is all 500-relevant:

- **The three-level front door.** "Three-position translucent locking front door that offers three levels of access": full access to the seven drives and media; removable-media access only; or fully locked [5]. The Service Source's keylock diagram maps the positions: **Left = Service, Upright = Unlocked, Right = Locked**, with the unlocked position opening front door, base door, power supply, shelves and bezel, and the locked position still allowing drive-tray removal through a properly positioned front door [2] Basics/Keylock Positions p. 66.
- **The rear drawer lock.** "Rear keylock slide-out cabinet access to logic board, processor card, DIMM sockets, and PCI slots (rear keylock powers down system when unlocked)" [5] — the same lock whose closed position is a power-on precondition ([ans.md](ans.md) §2.7), and the reason the machine cannot run with the drawer open.
- **The rest:** locking wheels, a security slot (third-party accessory), a power cord lock [5], the 19-inch rack mount accessory kit M4036Z/A [2] Basics/Options and Upgrades p. 10, and environmental limits of 10–35 °C operating and 10,000 ft altitude [2] Specifications/Environmental p. 17. (The brochure quotes a wider 10–40 °C operating range and 5–95% RH [5]; §6.8.)

### 4.5 What this machine does not expand by

- **No redundant power.** "Hot-swappable, redundant power supplies are not available for the Network Server 500 Series" [2] Basics/Overview of New Technologies p. 47; the supply is "single, 325 W" [2] Specifications/Electrical p. 11 and "fixed": "The Network Server 500 comes equipped with a single fixed power supply... To replace a Network Server 500 power supply, contact your service provider" [4]. The +3.3 V/+5 V budget trades off within 180 W [2] Specifications/Electrical p. 12.
- **No rear drive bays.** The two rear fixed-mount bays and their bracket are 700-only ([2] Basics/Options and Upgrades p. 10; [5]).
- **No Mac OS.** The production ROM refuses it ([ans.md](ans.md) §1.3) — the machine's only expansion into another operating system is a different AIX, or a PCI card with its own firmware.
- **No NuBus.** The slots take "all PCI 2.0 specifications-compliant cards (not NuBus-compatible)" [2] Specifications/I/O p. 5.
- **No second processor.** No dual-processor card was offered for the 500 (§3.1); the SMP machinery sits idle.
- **Ceilings:** 512 MB RAM, the L2 DIMM family, the 200 MHz card, 50 W of slot power, 14 SCSI devices without a RAID card.

## 5. Boot sequence summary

The boot contract is the family's ([ans.md](ans.md) §2.7) — AC path, DC path, power controller, POST, Open Firmware, boot — and this section walks it naming only this machine's branch points.

### 5.1 Power-on preconditions

The family's preconditions all bind on this machine: the sliding drawer interlocked so the AC interlock closes only "because the logic board is fully seated", the +5 V trickle keeping Cuda alive, the rear keyswitch locked, the processor card fully seated (enforced by `OffSenseOut`), Cuda in its idle state, and the +5 V line monitored — below +4.7 V the unit shuts down ([ans.md](ans.md) §2.7; [3] p. 4). Two 500-specific points: the rear keylock is not just a precondition but a live interlock — unlocking it powers the running system down [5] — and the supply is the single 325 W part with the family's 500 budget, minimum 3 A at +5 V for startup and a +12 V peak allowance (16 A peak per the developer note [1] §2.5.1 p. 8; "18.0 A (12 seconds maximum)" at startup per the service manual [2] Specifications/Electrical p. 12) sized so that even simultaneous drive spin-up is survivable, though drives "should perform delayed spin up" with "remote start enabled is the desired configuration" [1] §2.5.1 p. 8.

### 5.2 POST and the LCD

POST initializes the hardware, establishes the LCD path before memory is sized, then reports progress on it ([ans.md](ans.md) §2.7) — the message sequence and the failure messages are the family's ([ans.md](ans.md) §2.7). This machine's own expected LCD result, by the family's format ("ROM ver.1.1.20.1 / 0048 MB Parity DRAM / 150 MHz 604, 50 MHz Bus / 1024 KB Level 2 Cache" [2] Basics/Overview of New Technologies p. 53, a 700/150 sample), is `132 MHz 604, 44 MHz Bus` on line 3 and `512 KB Level 2 Cache` on line 4, with `0032 MB Parity DRAM` on a factory machine (*inferred - unverified*: the printed sample is the 700's, and no 500 sample is published; §6.4).

One branch point in POST is this machine's to know about because it decides whether the machine boots at all: on a boot whose NVRAM already carries the ROM's four-character signature, POST reads Board Register 1 with a byte-reversed load and tests the result against mask $100 — the tested bit sits in the register's low byte, which the family's top-byte table does not cover ([ans.md](ans.md) §3.5.1). Clear, the boot diverts into the ROM's serial diagnostic monitor on the first serial port — a `>` prompt taking single-letter commands, no timeout — instead of launching Open Firmware; set, the boot proceeds. The real board idles the bit high, and a first boot on a blank NVRAM store never reaches the test (*observed* on full boots of the production ROM; the ROM addresses and the mask are witnessed in its reset code) [11].

### 5.3 Open Firmware

Open Firmware finds a bootable device "based on the device or devices listed in the boot path and the position of the front panel keyswitch" ([ans.md](ans.md) §2.7). The keyswitch positions and their reset semantics are the family's ([ans.md](ans.md) §2.6); the 500's physical positions are §4.4's. The install path is the family's documented one: "If Open Firmware detects the key in the service position on a Network Server that has never been booted before, it will automatically attempt to find a diagnostic floppy or Install CD to boot from" ([ans.md](ans.md) §2.7; [3] p. 6) — the route to an AIX install on a machine with blank NVRAM, and the observed Cuda reset dance that goes with it (`RESETing to change Configuration!`) is the family's ([ans.md](ans.md) §2.7). The disk aliases the firmware binds — `disk0`–`disk3` on the first 53C825A, `disk4`–`disk6` on the second, AIX boot paths of the form `/bandit/53c825@11/sd@0:aix` — are the family's ([ans.md](ans.md) §1.3) and match this machine's 4+3 bay split (§3.4).

### 5.4 bootapple, bosboot and AIX on this machine

The production ROM's `bootapple` prints its banner and hands off to the compressed `bosboot` image ([ans.md](ans.md) §2.7); on a clean machine the observed output is `POST results AOK.  Code is  00010000`, the `AAPL,cpu-id` line, the `Power Macintosh,AAPL,ShinerESB;MacRISC` model line and the boot device — all family-level behaviour witnessed on this machine's boots [11]. The install medium's block 0 is the RS/6000-layout IBM IPL record ([ans.md](ans.md) §2.7). After the kernel launches, configuration methods run, the boot "quack" sounds before the first system-wide interrupts, the SCSI buses are walked and `fsck` runs ([ans.md](ans.md) §2.7) — with the SCSI-walk cost of the empty bays recorded on the SCSI device page ([sym53c8xx.md](../../hardware/scsi/sym53c8xx.md) §4.3).

AIX then takes over the machine's own boot console — the front LCD — with the standard IBM three-digit startup codes. "For most problems with the booting process, a three-digit error code appears on the LCD panel on the front of your Network Server" [8], and the codes name the configuration stages this machine runs [8], corroborated and extended by the later software baseline [6]:

| LCD value | System action |
|---|---|
| 510 / 511 | the Configuration Manager started / completed |
| 517 | mounting the `/` (root) and `/usr` file systems (518 on a failed network-boot mount) |
| 538 / 539 | passing control to a configuration method / method completed |
| 551 / 553 | varying on the root volume group / phase one of boot complete |
| 585 | configuring the network |
| 591 | configuring the Logical Volume Manager |
| 704 | configuring a SCSI disk drive |
| 723 | configuring a CD-ROM or other SCSI device |
| 811 / 812 / 814 | configuring the system planar / standard I/O adapter / NVRAM |
| 821 / 823 / 828 | configuring the keyboard / mouse / floppy disk adapter |
| 826 / 831 | configuring serial port 1 / port 2 |
| 868 | configuring the integrated SCSI adapter (the 53C94 bus) |
| 890 | configuring a SCSI-2 adapter (the 53C825A pair) |
| 9002 | configuring the 825 SCSI card |
| 921 / 925 / 935 | configuring a keyboard / mouse / 3.5-inch diskette drive |

[8]; [6] adds 538, 539, 890 and 9002 to the published set. The boot-time operational rule that goes with them: "Before you restart, ensure that the front key is turned to the upright (unlocked) position and the boot device is on. To restart, press the reset button." [8]. Two more AIX-side constraints on this machine: installation requires the extended ADB keyboard (§3.6), and the software baseline requires AIX 4.1.4 or higher [2] Specifications/Processor p. 1 — the shipped accessory-kit release 4.1.4.1 and the 4.1.5 install medium are the documented successors [6].

## 6. Open questions

1. **The introduction date and the "Shiner LE" name.** No Apple document in evidence dates the 500/132's introduction or prints the full codename; the LE/HE split is attested only inside the Service Source's power specification ("180 watts for the LE, 260 watts for the HE" [2] Specifications/Electrical p. 12) and the developer note's "SHINER HE" cabling label [1] §8.2 p. 31. The January 1996 announcement, February 1996 ship date and "Shiner LE" form rest on secondary sources.
2. **The factory 32 MB population.** The 32 MB fit is documented [2] and the two-DIMM pair population is attested for the 700's 32 MB configuration and for every upgrade kit [5], but no source prints the 500's own factory DIMM sizes.
3. **Which supply bit covers the 500's single supply.** Board Register 2 carries `FailPowSupplyLeft`/`FailPowSupplyRight` and two `Hot` bits ([ans.md](ans.md) §3.5.2); with one fixed supply, which physical position it reports and what the orphaned bit reads are undocumented.
4. **The 500's completed LCD display.** The Service Source prints only the 700/150 sample ("150 MHz 604, 50 MHz Bus" / "1024 KB Level 2 Cache" [2] Basics/Overview of New Technologies p. 53); this machine's own four lines — the 132/44 and 512 KB readings — are inferred from the format and the configuration, not witnessed in print.
5. **The 44 MHz bus rate's primary attestation.** The rate is derived (§2.2): the platform's one-third law [10], the fast-L2 rule's 44 MHz threshold [1] §6.2, the family index, and the observed 11 MHz time base. No Apple document prints "44 MHz" for this machine, and the 604 card itself is not documented at the signal level anywhere in the corpus.
6. **The Hammerhead machine-class value.** The production ROM's 9500 lineage implies it takes the 9500 arm of the +$20 selector; no Apple document states the ANS's value (§1.2).
7. **Board Register 1's low bytes on this machine.** The family's top-byte table is complete, but the low bytes are "the same as in 9500" ([ans.md](ans.md) §3.5.1) — and the 9500's own bits are unpublished, so the 500's low byte is doubly undocumented, including the PCIPRSNT bits the slots drive.
8. **The environmental specification's spread.** The Service Source gives 10–35 °C and 20–80% RH [2] Specifications/Environmental p. 17; the sales brochure gives 10–40 °C and 5–95% RH [5]. Which governs the 500 is undetermined.
9. **The upgrade leaflet's processor name.** The 200 MHz upgrade leaflet's illustration titles the card "PowerPC™ 604 processor card" [7] while the Service Source names the 700/200's part a 604e [2] Basics/Overview p. 3; whether the upgrade card sold for a 500 is a 604 or a 604e is not stated outright.
10. **The 176 MHz upgrade card.** Secondary sources describe a 176 MHz (44 MHz bus) processor-card upgrade for the 500; no Apple document in evidence mentions such a card. If it existed it would preserve fast L2 where the 200 MHz card removes it.
11. **Whether AIX ever reads `TwoSuppliesH`.** The bit is the only firmware-visible 500/700 discriminator (§1.2), but no AIX code path in evidence reads it; whether any Apple software ever distinguished the models at runtime is unknown.
12. **The media bays' bus assignment.** The internal fast/wide buses carry the hard disk, CD-ROM and optional DAT [4], and backplane slot 0 is the expected CD-ROM position ([ans.md](ans.md) §2.8), but no document states directly which channel and connector the media-bay devices occupy versus the drive trays, nor the tape bay's ID.
13. **The ROM's serial diagnostic monitor.** The bit-8 gate of §5.2 diverts boots into a `>`-prompt monitor on the first serial port (*observed*); no Apple document describes the monitor, its command set beyond the witnessed single letters, or the register bit it keys on.
