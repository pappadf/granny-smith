# Apple Network Server 700/150

The Apple Network Server 700/150 is the high-end member of the two-box Network Server family: the same TNT-derived logic board as the [500/132](ans500.md) with every one of the family's four price-point differentiators present at once — a 150 MHz PowerPC 604 on a 50 MHz processor bus, a 1 MB L2 cache DIMM, one or two hot-swappable 425 W supplies on a power backplane, and nine internal drive bays. Everything the two servers share is the family doc's and is cited here by section, never restated; this page carries what is unique to the 700 — and, per the family index, also its two later variants, the 700/200 and the 700/200SMP ([ans.md](ans.md) §6.2).

**Contents:**

1. [Identity](#1-identity) — what the machine is; identity values; the spec table; factory configurations of the /150, /200 and /200SMP
2. [Deltas vs the family doc](#2-deltas-vs-the-family-doc) — the delta list against the 500/132; this machine's clocks; memory population; the 1 MB L2 cache as fitted

## 1. Identity

### 1.1 What the machine is

The 700 is the "HE" half of the family. Apple's own developer note introduces the product line as two price points "distinguished by: More drive Bays, Redundant Power Supplies, Higher Clock frequency, More Cache memory" [1] §1.1.2 p. 2 — a sentence the family doc carries ([ans.md](ans.md) §1.1) — and the 700 is the box in which all four are true: two rear drive bays on top of the shared seven-bay backplane, the dual-supply backplane, 150 MHz against 132, and 1 MB of L2 against 512 KB. Apple's service documentation uses the two-letter shorthand itself, in the one place it budgets the +3.3 V/+5 V trade-off: "total power for both not to exceed 180 watts for the LE, 260 watts for the HE" [2] Specifications/Electrical p. 11. The "Shiner HE" codename is secondary-source naming: Apple's published documents never print "Shiner", and the "HE" they do print is a power-class label, not a project name ([§6](#6-open-questions), item 7). Per that secondary coverage the 500/132 ("Shiner LE") and the 700/150 ("Shiner HE") were released together at Macworld Expo San Francisco in January 1996, the 700/150 shipping from February 1996 [9].

The subject of this page is the 700/150 as shipped in February 1996: a PowerPC 604 at 150 MHz on the removable processor card. The two later members of the 700 line — the 700/200 (a 200 MHz PowerPC 604e card) and the 700/200SMP (two of them) — are field upgrades of the same enclosure and logic board, delivered as processor-card swaps ([§1.4](#14-factory-configurations), [§4.4](#44-the-processor-upgrade-path)), and are covered here with the /150.

Like every Network Server, the machine runs AIX and only AIX: the production ROM carries no Mac OS Toolbox and refuses the Mac OS ([ans.md](ans.md) §1.3). The 700/150's floor is stated in the specification: "Requires AIX version 4.1.4 or higher" [2] Specifications/Processor p. 1; the 700/200's row reads "Requires AIX version 4.1.4.1 or higher recommended" [2] Specifications/Processor p. 1.

### 1.2 Identity values

The identity machinery of the Macintosh line — gestalt ID, box flag, the 68k decoder record — does not exist on this machine, because the production ROM has no 68k half. What identifies a 700 to software is the family's own identity path plus one register bit:

| Identity value | Value | Witness |
|---|---|---|
| Platform identity | the 53C825A probe: POST finds the two Symbios fast/wide SCSI devices, sets the ESB flag, and Open Firmware publishes root `compatible` = `AAPL,ShinerESB` + `MacRISC` — the family path, shared with the 500 ([ans.md](ans.md) §1.3, §5.1) | [7] (*observed*: `?esb .` prints true after the probe) |
| Open Firmware `model` | `Power Macintosh,AAPL,ShinerESB;MacRISC` | [7] (*observed* in `bootapple` output) |
| `AAPL,cpu-id` | `$39002089` — top byte `$39` is Hammerhead's part identifier, the rest derived from its configuration registers ([hammerhead.md](../tnt/hammerhead.md) §4.3) | [7] (*observed* in `bootapple` output) |
| Gestalt / box flag | none — no Toolbox ROM, no Mac OS identity decode ([ans.md](ans.md) §1.3) | — |
| Boot ROM | the production 4 MB image, header checksum `$962F6C13`, version field `$077D.28F2` (byte-identical to the Power Macintosh 9500 v2 field; identify by checksum), Open Firmware 1.1.22 ([ans.md](ans.md) §1.3) | [7] |
| Board Register 1 top byte | `$A8` with the keyswitch locked: `BoxId0` set, `BoxId1` clear, both keyswitch lines deasserted, **`TwoSuppliesH` set** — the register-level 500/700 discriminator ([ans.md](ans.md) §3.5.1) | [7] (*observed* on a full boot of the production ROM; the 500 reads `$28` under the same conditions) |
| 500-vs-700 discrimination in Open Firmware | none — no published device-tree property, alias or node distinguishes the two boxes ([ans.md](ans.md) §6.2) | — |

One provenance point is worth recording because it is the strongest single fact in the 700's evidence base: the production ROM in the corpus was captured from a **real 700** — a raw Open Firmware serial dump taken off the machine's second serial port, 65,536 lines of 128 hex characters, verified byte-for-byte against an independently packaged dump of the same image [7]. Everything the family doc marks *observed* on the production ROM is therefore witnessed against the image this very machine runs.

Two notes on the table. The service manual publishes at-introduction configurations for the /150 and /200 only; the SMP machine is documented as a feature row ("two 200-MHz PowerPC 604e microprocessors (Network Server 700/200SMP)" [2] Basics/Overview p. 1) with no separate configuration of its own — its non-processor configuration is the /200's. AIX is never preinstalled: "AIX software does not come preinstalled in standard configurations of the Network Server 500 and 700 Series. The AIX software must be purchased separately" [2] Basics/Configurations p. 7. And the CD-ROM column shows the generational split inside the one series: the /150 shipped the 4× AppleCD 600i, the /200 standardized the 8× AppleCD 1200i, and the specification chapter's series-level row lists the 1200i for the whole 700 Series [2] Specifications/Disk Storage p. 9 — the later drive becoming the series standard.

The /200's processor is documented as an upgrade first: "now the highest-performance member of the Network Server product line... a 33% increase in clock speed over the 150-MHz microprocessor", delivered as a processor-card upgrade [5] p. 2, installable in an existing machine [6]. The upgrade path is §4.4's.

## 2. Deltas vs the family doc

### 2.1 The delta list

Everything board-level is shared with the [500/132](ans500.md); the 700's complete delta set against its sibling — the things that make it a different machine to buy, to power, to populate and to model:

| Area | 500/132 | 700/150 | Authority |
|---|---|---|---|
| Processor card | 604 at 132 MHz | 604 at 150 MHz | [2] Basics/Overview pp. 1–2 |
| Processor bus | 44 MHz | 50 MHz — printed on the machine's LCD | [2] Basics/Overview of New Technologies p. 53 |
| "Fast L2" ROM mode | enabled (bus ≤ 44 MHz) | **not** enabled — the one place the 500 is architecturally ahead ([ans.md](ans.md) §2.4) | [1] §2.4.2 p. 8, §6.2 p. 21 |
| L2 cache DIMM | 512 KB | 1 MB | [2] Basics/Overview pp. 1–2, Specifications/Memory p. 3 |
| DRAM minimum | 32 MB parity | 48 MB parity | [2] Basics/Configurations pp. 5–6 |
| Power supplies | one 325 W, no redundant option | one or two 425 W, hot-swappable, on a power backplane | [2] Basics/Configurations pp. 6–7, Basics/Overview of New Technologies p. 47 |
| +3.3 V/+5 V supply trade-off | 180 W ("LE") | 260 W ("HE") | [2] Specifications/Electrical p. 11 |
| PCI aggregate card budget | 50 W | 90 W | [1] §7.1.2 p. 22 |
| Internal drive bays | seven (front backplane) | nine (seven front + two rear bracket) | [2] Basics/Overview pp. 1–4 |
| Internal SCSI devices | seven (4 on bus 0 + 3 on bus 1) | nine (4 + 5: the rear pair joins the second bus) | [2] Basics/Overview of New Technologies p. 41, Specifications/I/O Interfaces p. 4 |
| Supply-status sensing | left supply only | left **and** right supplies — Board Register 2 bits b13/b15 and the 700-only `Right Power Fail!`/`Right Power Hot!` LCD messages | [2] Basics/Overview of New Technologies p. 57 |
| `TwoSuppliesH` (Board Register 1, b15) | clear | set | [1] §4.6.1 p. 15; [7] (*observed*: `$A8` vs `$28`) |
| CD-ROM at introduction | AppleCD 600i | AppleCD 600i on the /150; 1200i from the /200 on | [2] Basics/Configurations pp. 6–7 |
| Intro hard drive | 2 GB | 4 GB | [2] Basics/Configurations pp. 5–6 |

Register-level, the whole difference between the two machines reduces to three values: the card's clocks (which set the bus rate, the timebase and the fast-L2 decision), the L2 DIMM size Hammerhead reports, and `TwoSuppliesH`. No Open Firmware property distinguishes them ([ans.md](ans.md) §6.2) — which is why the two models are one platform to AIX and a pair of profiles to a hardware model.

### 2.2 Clocks on this machine

The clock architecture is the family's — the card sources the system clock, PCI runs asynchronously at 33 MHz, DRAM timing follows the parity detect, and the L2 mode follows the bus speed ([ans.md](ans.md) §2.2, §5.4). This machine's column:

| Clock | Value | Authority |
|---|---|---|
| Processor core | 150 MHz | [2] Specifications/Processor p. 1 |
| Processor (AR) bus | 50 MHz — asserted by the machine's own LCD on a healthy 700/150 (`150 MHz 604, 50 MHz Bus`), so the 3:1 ratio is witnessed, not inferred | [2] Basics/Overview of New Technologies p. 53 |
| Time base and decrementer | one quarter of the bus clock — 12.5 MHz | [4] §1.3.2.7.2 |
| PCI buses | 33 MHz, asynchronous to the processor bus | [ans.md](ans.md) §5.4; [bandit.md](../tnt/bandit.md) §1.5 |
| DRAM timing | 60 ns with parity detected, 70 ns without — a ~20% bandwidth penalty at 50 MHz for 70 ns, a penalty this machine pays at the family's highest bus rate | [1] §2.4.1 p. 7 |
| L2 "fast" mode | **off** — the ROM enables it only at bus speeds of 44 MHz or less, and this card's bus is 50 MHz ([ans.md](ans.md) §2.4) | [1] §2.4.2 p. 8, §6.2 p. 21 |
| SCSI, video, LCD write timing | the family's values | [ans.md](ans.md) §5.4 |

Because the bus clock is a property of the installed card ([ans.md](ans.md) §2.2), the 200 MHz upgrade changes more than the core rate: it keeps the 50 MHz bus, keeps fast L2 off, and leaves every downstream rate standing — the two 700 cards differ from each other only in the core multiplier. The family's 40–50 MHz supported range [1] §2.10 p. 9 is fully exercised by the 700 line at its top end.

### 2.3 Memory population

The memory array is the family's — eight 168-pin slots in four interleaved bank pairs labelled 1A/1B through 4A/4B, byte parity in the datapath, the 60/70 ns timing switch, and the 512 MB ROM decode ceiling, all documented at [ans.md](ans.md) §2.3. What the 700 adds is the shipping population and the service rules that govern it:

- **48 MB standard**, expandable to 512 MB [2] Specifications/Memory p. 2 — against the 500's 32 MB. The DIMMs are "72-bit-wide, 168-pin parity DRAM" modules, "fast-paged mode, parity DRAM, with an access time of 60-nanoseconds or faster", and "should be installed in matched pairs (for example, two 8 MB DIMMs)" [2] Basics/Compatibility Issues p. 16. Which slots the factory 48 MB occupies — six 8 MB DIMMs, three bank pairs, or any other population — is not stated by any document in evidence (§6, item 2).
- **The all-or-nothing parity rule, in Apple's own service words:** "Nonparity DIMMs with 70-nanosecond or faster access time DRAM will work; however, if there is any nonparity DRAM installed, all server parity checking is disabled" [2] Basics/Compatibility Issues p. 16 — the service-side statement of the dev note's timing switch ([ans.md](ans.md) §2.3): one non-parity DIMM does not merely un-protect its own bank, it drops the whole array to 70 ns timing and disables checking everywhere.
- **No SIMMs:** "Some DIMMs and all Single Inline Memory Modules (SIMMs) from older Macintosh computers are not compatible" [2] Basics/Compatibility Issues p. 16.
- **The connector:** the mechanical interconnect matrix names the DRAM connector as a "168 position SMT, JEDEC, 72ECC" part [1] §8.2 p. 32 — the 72-bit width is the parity bits riding on the JEDEC ECC positions.
- **Apple's upgrade parts** are the 16, 32 and 64 MB parity memory kits ([§4.3](#43-memory-and-cache-upgrades)) [2] Basics/Options and Upgrades pp. 9–11.

### 2.4 The L2 cache as fitted

The cache subsystem is the family's — the 8500-pinout DIMM slot, the electrically sensed size, the SRAM speed rules and the burst-SRAM erratum, all at [ans.md](ans.md) §2.4. The 700 ships the family's largest documented DIMM: **1 MB** [2] Specifications/Memory p. 3, which the completed LCD reports on line 4 as `1024 KB Level 2 Cache` [2] Basics/Overview of New Technologies p. 53. The connector is a 200-position part — the interconnect matrix lists the "cache connector" as a "200 cache card" on a Burndy `ELF200DGC3Z50` [1] §8.2 p. 32.

The 700-specific consequence is the negative one: at this card's 50 MHz bus the ROM does **not** enable "fast L2" — that mode exists for "bus speeds of 44 MHz or less" [1] §2.4.2 p. 8, §6.2 p. 21 — so the 700/150 runs its larger cache at ordinary latency while the 500/132 runs its smaller one a cycle faster. The 200 MHz card does not change this: its bus is also 50 MHz. An implementation that keys L2 latency off the processor part instead of the bus clock gets both machines wrong in opposite directions.

## 3. Per-subsystem wiring

### 3.1 The processor card and the PowerPC 604

The card architecture, connector, current limits, reset timing and dual-processor design are the family's ([ans.md](ans.md) §2.2): the ANS-specific connector (the AMP 94-7831-08 dual-90, 180-signal-contact part), the card-sourced `refClk`/returned `clkToProc` discipline, the ~500 ms card-reset de-assertion, `OffSenseOut` power-on interlock, `ParityErrL` to MCP, and the spin-wait bring-up of a secondary processor. This machine's card is the one the family clocking rules were written around:

- **The 604 at 150 MHz**, with the part's standard organization — six parallel execution units, the on-chip MMU, and the split 16 KB instruction and 16 KB data caches [4], which the service spec flattens to "32K on-chip cache" [2] Basics/Overview p. 1. The 604's 0 ns output hold time is the reason the family requires an inserted clock delay of at least 1 ns on the card ([ans.md](ans.md) §2.2).
- **The 3:1 ratio** at 50 MHz is the machine's own printed figure ([2.2](#22-clocks-on-this-machine)); the time base and decrementer tick at 12.5 MHz [4] §1.3.2.7.2.
- **The 200 MHz 604e card** — Apple's "Processor Upgrade Card with One 200-MHz 604e PowerPC Processor", part M5177Z/A [2] Basics/Options and Upgrades pp. 9–11 — is the documented upgrade, a card swap in an existing 700 [5] p. 2, [6]. It doubles the on-chip cache to 64 KB [2] Basics/Overview p. 1 and keeps the 50 MHz bus, so it changes nothing downstream of the core.
- **The SMP card** puts two 200 MHz 604e parts on the one card [2] Basics/Overview p. 1 — the shipping expression of the family's designed-in dual-processor support ([ans.md](ans.md) §2.2). The secondary processor's spin-wait, the Ethernet-PROM doorbell and the lock-step timebase register are the family's and Hammerhead's ([ans.md](ans.md) §5.3; [hammerhead.md](../tnt/hammerhead.md) §4.5). Whether any AIX release enables the second processor is open at the family level and stays open here ([ans.md](ans.md) §7 item 3; §6 item 8).

### 3.2 The six PCI slots

The slot map — two buses, slots 1–2 on Bandit 1 and 3–6 on Bandit 2, the IDSEL assignments, the configuration ports, the discovery-order contract, the PRSNT bits — is the family's and is not repeated here ([ans.md](ans.md) §3.2–§3.3; [bandit.md](../tnt/bandit.md) §3.2). Three facts are this machine's own:

- **The card power budget is nearly doubled:** "Not to exceed 90 watts in any combination" across the six cards, at 18 A +3.3 V, 18 A +5 V, 2 A +12 V — against the 500's 50 W [1] §7.1.2 p. 22. The per-card PCI 2.1 limit of 25 W "always applies" [1] §7.1.2 p. 22. The service specification repeats the same three rails for the 700 row [2] Specifications/Electrical pp. 13–14.
- **One connector discrepancy to flag:** the developer note defines the implementation as a "32-bit card to motherboard 5 Volt implementation for six slots of PCI expansion" [1] §7.1 p. 22, while its own mechanical matrix lists the PCI connectors as "64 bit-5 V (184)" parts [1] §8.2 p. 32 and the service specification calls the slots "six 64-bit, universal (5 volt + 3.3 volt) PCI expansion slots... compliant with PCI 2.0 specifications" [2] Basics/Overview of Core Technologies p. 35. The physical sockets are 64-bit-position 5 V parts; the documented *implementation* is 32-bit 5 V, and whether a 64-bit-wide or 3.3 V-signalling card works in one is not established by any document (§6, item 12).
- **The RAID card's slot** is slot 1, labelled "Slot 1 Bus 0 (Raid)" on the logic-board diagram ([ans.md](ans.md) §3.3), and the RAID implementation caps the useful slot count: "due to a limitation in the PCI Redundant Array of Independent Disks (RAID) implementation, only four Network Server PCI RAID cards can be installed in a single Network Server" [2] Basics/Overview of New Technologies p. 45.

### 3.3 Storage: the nine-bay backplane

The seven-bay hot-swap backplane, the two 53C825A controllers, the hot-swap electricals, the RAID interface and its LED control are the family's ([ans.md](ans.md) §2.8; [sym53c8xx.md](../../hardware/scsi/sym53c8xx.md) §1.3, §4.5). The 700's addition is the rear bracket:

- **Two more drives, cabled.** "In the Network Server 700, a rear drive bracket will support two more drives which are cabled to the bottom bus" [1] §7.2.3 p. 25; the feature list gives them as "two drive bays in the rear for internal fixed drives" [2] Basics/Overview p. 4 — *fixed*, not hot-swap: the rear pair sits outside the seven-bay hot-swap backplane and its long/short-pin SCSI-reset mechanism ([ans.md](ans.md) §2.8).
- **Which bus.** The buses are documented by device count: "The buses accommodate four, five, and seven SCSI devices, respectively" with "a total of 16 SCSI devices (nine internal and seven external)" on a 700 [2] Basics/Overview of New Technologies p. 41, Specifications/I/O Interfaces p. 4 — four on one bus, five on the other, seven external. The seven front bays split four-and-three by the firmware's disk aliases ([ans.md](ans.md) §1.3), so the five-device bus is the one carrying front bays 4–6, and the rear pair joins it — the bus driven by `/bandit/53c825@12`, the "bottom bus" of the developer note's figure (*inferred* from the agreeing counts; no document names the bus number for the rear drives, and the ID-assignment evidence is a figure rather than text, §6 item 1).
- **Termination.** The backplane's terminator-stealing trick — "The terminators in the middle are automatically disabled by stealing a ground signal from the mating ribbon cable. This concept is also used to support the optional internal drives in the rear of Network Server" [1] §7.2.3 p. 26 — extends to the rear cabling. The service rules are concrete: "the last bracket-mounted drive on the SCSI cable has termination enabled"; with one drive in the bracket it must sit on the SCSI cable's last connector; with two, "the SCSI ID cable and the last connector on the SCSI cable are both connected to the bottom hard drive" [2] Troubleshooting/Symptom Charts/Hard Drive p. 23. The internal SCSI cable "has built-in termination" and drives must have their own termination disabled [2] Basics/Overview of New Technologies p. 43.
- **The wiring set.** The rear bracket hangs off the same interconnects as everything else: "10-inch and 20-inch mezzanine-to-SCSI backplane cables", a "rear drive SCSI cable", a "rear drive SCSI ID cable", a "rear drive power cable", and a "power backplane-to-SCSI backplane" power cable [2] Troubleshooting/Symptom Charts/Hard Drive pp. 23–25. One assembly trap is documented: the fan-to-SCSI-backplane cable's connector is similar to the rear drives' power connector, and "if the fan-to-SCSI backplane cable is incorrectly connected to it, the server will not power on" [2] Take Apart/Rear Panel p. 20.
- **The rear drives are boot drives.** The symptom charts treat "the internal rear hard drive... the boot drive (Network Server 700 Series only)" as a normal configuration with its own cabling checklist [2] Troubleshooting/Symptom Charts/Hard Drive p. 20.
- **Slot 0 is the CD bay.** The backplane assigns addresses by position — "Slots in the Network Server 500/700 are address 0-6 with 0 being the address of the uppermost slot and 6 being the lowermost slot" — and the CD-audio break-out "is only for a CD-ROM drive in Slot 0" [1] §7.3.2 p. 27.

### 3.4 The I/O set as fitted

The whole on-board I/O set — 54M30 video, MACE Ethernet on AAUI, the two ESCC serial channels, AWACS, SWIM III, Cuda/ADB — is the family's, chip for chip, and is documented at [ans.md](ans.md) §2.1, §2.5, §4.1. The 700 fits exactly the same silicon as the 500; the per-model facts are connector and mode details:

- **Video.** The port is "SuperVGA (SVGA)... requires an HDI-15 cable" [2] Specifications/I/O Interfaces p. 5 — not Apple's DA-15, and the machine "support[s] only multisynchronous displays" [2] Basics/Compatibility Issues p. 16. The supported mode set, from the specification's table [2] Specifications/Sound and Video pp. 6–7, all at 256 colors/grays (the 8 bpp ceiling of the family's little-endian byte-order rule, [ans.md](ans.md) §2.5):

| Refresh (Hz) | Resolution |
|---|---|
| 60, 70, 72 | 640×480 |
| 60, 72, 75 | 800×600 |
| 60, 72, 75 | 1024×768 |

- **Ethernet.** The AAUI port needs a media adapter to reach any cable system: thicknet, thinnet or 10BaseT [2] Basics/Overview of Core Technologies pp. 31–33 — the documented route to twisted pair on this machine, since the board itself has no 10BASE-T PHY ([ans.md](ans.md) §2.1).
- **Serial.** Two RS-232/RS-422 ports "compatible with LocalTalk and GeoPort cables" [2] Specifications/I/O Interfaces p. 5, on 9-pin mini-DIN connectors [1] §8.2 p. 32. (The specification's own text reads "mini DIN-8" [2] Specifications/I/O Interfaces p. 5, against the 9-pin part in the mechanical matrix and the two GeoPort channels of the FCS feature list [1] §1.3 p. 2 — the 9-pin connector is the one the parts catalogue names.)
- **ADB.** One port for "a keyboard, mouse, or a three-button mouse" [2] Specifications/I/O Interfaces p. 5; the ADB budget is 500 mA with no more than three devices recommended [2] Specifications/Electrical p. 12.

### 3.5 The power subsystem

The family's power-on contract — the rear drawer lock as a power-on precondition, the +5 V trickle to Cuda, the +4.7 V monitor, the card-seating interlock — is [ans.md](ans.md) §2.7's and is not restated. The 700's supply system is the machine's defining mechanical feature:

- **Two bays, hot-swap, current-share.** "The Network Server 700 Series has two bays for two power supplies. Although the server is shipped with only one power supply installed in the left bay, when a second power supply is installed in the other bay (right), the server power supplies become hot-swappable. When one of the installed power supplies fails, its LED will turn off. The failed power supply can then be replaced without shutting down the server. (A message will display on the LCD indicating that it is safe to shutdown the server.)" [2] Basics/Overview of New Technologies p. 47. The redundant system "will current share to increase longevity", and installing the second supply does **not** raise the delivery limits ([ans.md](ans.md) §2.6, quoting [1] §2.5.2 p. 8) — the second bay buys lifetime, not watts. "Hot-swappable, redundant power supplies are not available for the Network Server 500 Series" [2] Basics/Overview of New Technologies p. 47.
- **The backplane.** The 700 is the family's one machine with a power backplane: "Network Server 700 provides an optional redundant supply system. This provides higher power and a power backplane" [1] §2.5.2 p. 8, and against the 500's hardwired subset of the blind-mate connector, "The Network Server 700 power interconnect system pinout is available from Developer Support" [1] §6.3 p. 21 — it was never published (§6, item 11).
- **The budgets** are the family table's 700 rows — 44 A +5 V / 13 A +12 V / 13 A +3.3 V at load #1, 19/13/50 at load #2, 15 W minimum, 425 W total ([ans.md](ans.md) §2.6) [1] §2.5.2 p. 8 — with the service specification's own trade-off line: "+3.3 and +5.5 power outputs are traded off; total power for both not to exceed... 260 watts for the HE" [2] Specifications/Electrical p. 11. The AC side draws at most 708 W from a 100–240 V, 50–60 Hz single-phase line, automatically configured [2] Specifications/Electrical p. 11.
- **Sensing.** The supply states surface in Board Register 2 as active-low bits — `FailPowSupplyLeft`/`FailPowSupplyRight` (b12/b13), `powSupplyHotLeft`/`powSupplyHotRight` (b14/b15) ([ans.md](ans.md) §3.5.2) [1] §4.6.1 p. 15 — polled, never signalled, and mapped one-for-one onto the LCD problem messages, where the 700's right-bay pair is explicitly "Network Server 700 Series only": `Right Power Fail!`, `Right Power Hot!` [2] Basics/Overview of New Technologies p. 57. The presence of the dual-supply backplane itself is `TwoSuppliesH`, Board Register 1 bit 15 ([ans.md](ans.md) §3.5.1), read set on every 700 [7] (*observed*: `$A8`). Apple's own redundancy claim for the register is the feature list's "Redundant, hot-swappable power supplies" [2] Basics/Overview p. 4.
- **Drive spin-up.** The 700's nine bays make the family's spin-up advice bite harder: internal drives "should perform delayed spin up" / "Apple recommends that drives be configured for spin-up on command" ([ans.md](ans.md) §2.6) [1] §2.5 p. 8; [2] Specifications/Electrical p. 14, with the per-bay thermal budget of 1.1 A at +5 V and 1.3 A at +12 V [2] Specifications/Electrical p. 14.

### 3.6 Cooling, environment and the front panel

- **Two fans, hot-swappable.** The FCS feature list includes "Hot swap fans" [1] §1.3 p. 2, and the failure messages name the pair's placement: `Drive Fan Failed!` — "Fan on right when facing rear of server unit" — and `Processor Fan Failed` — "Fan on left when facing server unit" [2] Basics/Overview of New Technologies p. 56. Their states are Board Register 2's `FanFailDrive`/`FanFailProcessor` bits ([ans.md](ans.md) §3.5.2).
- **Thermal trips.** The two-trip Safe Server scheme — a warn trip "prior to hardware vulnerability", a shutdown trip "slightly beyond worst case thermal ratings" — is the family's ([ans.md](ans.md) §2.6), reported as `Temperature Warning!` and `Temperature Too Hot!` on the LCD [2] Basics/Overview of New Technologies p. 56.
- **The operating envelope.** 50–95 °F (10–35 °C), 20–80% relative humidity noncondensing, 10,000 ft (3,048 m) maximum altitude; storage −40 to 116.6 °F [2] Specifications/Environmental p. 17.
- **The enclosure.** The family's Hendy chassis — "30 second component access", the sliding logic-board drawer, the locking front security door ([ans.md](ans.md) §2.1) [1] §1.3 p. 2, §8.1 p. 30 — here at its heaviest: 24.5 × 16.5 × 18 inches and 84–92 lb depending on the drive population, on four wheels whose front pair has brake levers that must be unlocked before removal [2] Specifications/Physical p. 16, Take Apart (front-wheel caution). (The developer note's own figure for the enclosure — "approximately 17 W x 23 H x 18 D. Weight with 1 hard drive is approximately 60 pounds" [1] §8.1 p. 30 — reads as the family's lightest configuration; the service manual's 84–92 lb is the measured shipping weight of the class, and the two documents never reconcile, §6 item 5.)
- **The keylock and the access it grants.** The three front key positions gate physical access, not just firmware behaviour ([ans.md](ans.md) §2.6): service (left) opens the front door, base door, power supply, top and bottom shelves; unlocked (upright) adds the rear drawer and the front bezel assembly; locked (right) leaves only the drive trays — and only "if the front door is positioned properly" [2] Basics/Keylock Positions p. 66.

## 4. Expansion

### 4.1 PCI cards

The six slots, their bridge split, their interrupt lines and their configuration contract are the family's ([ans.md](ans.md) §3.3; [bandit.md](../tnt/bandit.md)). What a 700 owner can put in them, per the options catalogue [2] Basics/Options and Upgrades pp. 9–11:

| Card | Part |
|---|---|
| PCI RAID Disk Array Card | M4030Z/A |
| RAID external SCSI cable (68-pin to 68-pin) | M4031Z/A |
| PCI Fast Ethernet Card (100Base-TX) | M3906Z/A |
| PCI Ethernet Card (10Base2/10Base-T/AAUI) | M4709Z/A |
| 19-inch rack mount accessory kit | M4036Z/A |

The two Ethernet cards are the machine's route off the on-board AAUI's 10 Mb/s — the FCS feature list's "100 Mb/s 100BaseT card and 10BaseT card" [1] §1.3 p. 2. The RAID card takes slot 1 and the backplane's wide-SCSI takeover, per-drive LED interface and AIX contract (controller at ID 7, logical drives 8–15) — all family-level, at [ans.md](ans.md) §2.8; at most four of them fit ([§3.2](#32-the-six-pci-slots)) [2] Basics/Overview of New Technologies p. 45. Aggregate card power is capped at 90 W, 25 W per card ([§3.2](#32-the-six-pci-slots)) [1] §7.1.2 p. 22; [2] Specifications/Electrical p. 14.

### 4.2 Storage options

From the same catalogue [2] Basics/Options and Upgrades pp. 9–11 and the specification [2] Specifications/Disk Storage pp. 9–10:

- **Front-bay drives in carriers:** 2 GB (M4022Z/A), 4 GB (M4023Z/A) and 9 GB (M5178Z/A) Fast/Wide SCSI drives with tray; 1.2 GB drives are also listed in the specification's hard-drive row [2] Specifications/Disk Storage p. 9. A Quantum or other active-high-LED drive requires rewiring the SCSI ID cable — moving the pin-3 wire to pin 1 of the drive-tray connector [2] Basics/Configuring the SCSI ID Cable pp. 63–64.
- **The rear bracket kits** are 700-only options: "2 GB Fast/Wide SCSI Hard Drive & Bracket M4818Z/A" and "Two 4 GB Fast/Wide SCSI Hard Drives & Bracket M4819Z/A" [2] Basics/Options and Upgrades pp. 9–11.
- **Removable media:** the 4× CD-ROM drive with tray (M4024Z/A), the DDS-2 DAT drive (M4025Z/A) and the 8 mm tape drive (M4026Z/A) — the 8 mm part reading AME tapes at 20/40 GB and 3 MB/s uncompressed [2] Specifications/Disk Storage p. 10. The /150's standard DAT2 is the 4 mm DDS-2 [2] Basics/Configurations p. 6.
- **Adapter kits:** the SCSI Drive Adapter Kit (68- and 50-pin, M4028Z/A) and Front Drive Bezel Kit (M4029Z/A), with the two interface PCBs, ID cables and LED cable enumerated in the developer note's install kit ([ans.md](ans.md) §2.8) [1] §7.3.2 pp. 26–27. The ID cable itself is type-matched to the drive: Type 1 for 2/4/9 GB hard drives and the 8 mm drive, Type 2 for DAT, Type 3 for CD-ROM, Type 4 for the 1.2 GB drive [2] Basics/SCSI ID Cable Connector Matrix p. 65.

### 4.3 Memory and cache upgrades

The parity memory kits are 16 MB (M4017Z/A), 32 MB (M4018Z/A) and 64 MB (M4019Z/A) [2] Basics/Options and Upgrades pp. 9–11, installed in matched pairs ([§2.3](#23-memory-population)) under the family's parity and 512 MB decode rules ([ans.md](ans.md) §2.3). No Apple catalogue in evidence lists a cache DIMM part of any size: the 700 ships 1 MB and no documented upgrade changes it (§6, item 10).

### 4.4 The processor upgrade path

The documented upgrade is Apple's 200 MHz 604e card (M5177Z/A), a field procedure on an existing 700 [5] p. 2, [6]: the rear drawer is slid and locked out, the card guides seat the new card, and the machine comes up on the same 50 MHz bus with fast L2 still off ([§2.2](#22-clocks-on-this-machine)). The SMP configuration is the same slot carrying two processors ([§3.1](#31-the-processor-card-and-the-powerpc-604)). A community-attested 176 MHz 604 card also exists in secondary coverage but in no Apple document (§6, item 6).

### 4.5 What this machine does not expand by

- **No NuBus:** the machine takes "cards designed according to the PCI standard. Your server cannot accommodate NuBus cards" [2] Basics/Compatibility Issues p. 16.
- **No on-board twisted pair:** Ethernet reaches 10BASE-T only through an AAUI media adapter or a PCI card ([§3.4](#34-the-io-set-as-fitted)).
- **The 512 MB ROM decode ceiling** stands regardless of the sockets' physical capacity ([ans.md](ans.md) §2.3).
- **No Mac OS, by ROM:** the production image's software contract is Open Firmware plus the AIX bootstrap; the withheld Mac OS capability lives only in the unreleased prototype ROM ([ans.md](ans.md) §1.3).

## 5. Boot sequence summary

The boot chain — AC path, DC path, power-controller preconditions, POST, Open Firmware, `bootapple`, `bosboot`, the AIX "quack" — is the family's, message by message ([ans.md](ans.md) §2.7), and so is the LCD progress contract ([ans.md](ans.md) §2.6–§2.7, §3.5.3). This section walks that contract naming the 700's branch points and the behaviour witnessed on this machine.

1. **Power-on preconditions.** The operator sequence is the service manual's: rear drawer lock to locked, front lock key to unlocked or locked, then the power button next to the floppy drive [2] Basics/Setup and Operation p. 19 — on top of the family's electrical preconditions (card seated, Cuda idle, +4.7 V line healthy; [ans.md](ans.md) §2.7).
2. **Reset and POST.** The 604 fetches `$FFF00100` through Hammerhead; the primary proceeds and a secondary would spin-wait ([ans.md](ans.md) §2.2, §2.7). POST sizes memory, tests parity, configures the L2 and writes its progress to the LCD ([ans.md](ans.md) §2.7).
3. **The healthy 700/150 display.** The completed LCD on a correctly configured machine, from the service manual's own sample [2] Basics/Overview of New Technologies p. 53:

   ```
   ROM ver.1.1.20.1
   0048 MB Parity DRAM
   150 MHz 604, 50 MHz Bus
   1024 KB Level 2 Cache
   ```

   Line by line: the ROM version, the parity DRAM size (the 700's 48 MB), the card's clocks — the family's only on-hardware attestation of the 50 MHz bus — and the 700's 1 MB cache. Two observed corrections to the sample: the production ROM in evidence prints `ROM vers.1.1.22` on line 1 and packs the size lines to the display's 20-character width (`0048 MB Parity RAM`, `1024KB Level 2 Cache`) [7] (*observed* on full boots of the production image; the manual's `1.1.20.1` is either an earlier revision's display or a stale sample, §6 item 4). The observed progress-message order also differs from the manual's printed table — `MainLBU Enet Setup` and `Testing Parity DIMMs` both land earlier in the observed sequence, the latter immediately before POST writes `$FFFF` to the undocumented GBus register at `$F301C030` ([ans.md](ans.md) §3.5.6) [7] (*observed*).
4. **Memory configuration is cached in NVRAM — and trusted.** The production ROM carries `init-mem-config`, `set-dimm-sizes`, `nv-dimm-size@`, `dimm-size-tbl!` and `interleave-bit@`, and at the `Jumping To RAM Prog.` message it relocates into DRAM and begins trusting the cached per-DIMM sizes over re-probing [7] (*observed*: booting the ROM against a stale NVRAM store written by a differently-configured machine sizes memory correctly and then stops dead at exactly that message — the bring-up hazard of a persistent NVRAM model, and the mechanism behind the family's warning that over-capacity memory hangs the long RAM test, [ans.md](ans.md) §2.3).
5. **Open Firmware and identity.** OF reads the keyswitch from Board Register 1 — on the 700 with the key locked the byte is `$A8` ([§1.2](#12-identity-values)) [7] (*observed*) — runs the 53C825A probe that sets the ESB flag, and publishes `AAPL,ShinerESB` + `MacRISC` ([ans.md](ans.md) §5.1). The service position's first-boot install path and its Cuda reset requirement are the family's ([ans.md](ans.md) §2.7).
6. **`bootapple`.** The bootstrap's own console output on a healthy machine [7] (*observed*):

   ```
   bootapple: launched by "OpenFirmware1.1.22"
   bootapple: POST results AOK.  Code is  00010000
   bootapple: "AAPL,cpu-id" property is  39002089
   bootapple: model info is Power Macintosh,AAPL,ShinerESB;MacRISC
   bootapple: boot device is "/bandit/53c825@11/sd@0:aix"
   ```

   — POST's NVRAM-recorded results read back clean, the identity set of [§1.2](#12-identity-values) confirmed line by line, and the boot device the first front bay on the first fast/wide bus with the family's `:aix` suffix ([ans.md](ans.md) §1.3).
7. **AIX.** The compressed `bosboot` image loads, expands and jumps; the kernel sounds the system boot "quack" before the first system-wide interrupts, then walks the SCSI buses, runs `fsck` and configures the network ([ans.md](ans.md) §2.7). On the 700 the walk covers nine internal device addresses across the two wide buses, paying the per-absent-target probe cost recorded on the controller's page ([sym53c8xx.md](../../hardware/scsi/sym53c8xx.md) §4.3) [8].
8. **Install-time specifics.** The BOS installer's console-definition prompt appears on the 54M30 framebuffer and simultaneously on the second serial port, where the console can be claimed and the menus driven [8] (*observed* on the 4.1.5 media). During a graphics-console install AIX never touches Cuda or ADB — zero VIA accesses measured across the install [8] (*observed*) — which sits against the specification's "AIX requires an extended keyboard for installation" [2] Specifications/I/O Devices p. 8 (§6, item 9). AIX is never preinstalled ([§1.4](#14-factory-configurations)); the /150's floor is 4.1.4, the /200's 4.1.4.1 [2] Specifications/Processor p. 1. Orderly shutdown is by root: `shutdown -F` [2] Basics/Setup and Operation p. 20.

## 6. Open questions

1. **The rear bays' SCSI IDs.** The internal ID assignment is published as a diagram, not text [2] Basics/Overview of New Technologies pp. 41–45; no Apple document states in prose which SCSI IDs the two rear-bracket drives take, or which bus number the "bottom bus" of [1] §7.2.3 p. 25 is. The 4+5+7 device count pins the *bus* by arithmetic (§3.3) but the rear drives' own addresses are unestablished.
2. **The 48 MB factory population.** Neither the configurations table nor the specification says how many DIMMs the standard 48 MB occupies or which bank pairs they fill.
3. **`TwoSuppliesH` semantics.** The bit reads set on a 700 ([§1.2](#12-identity-values)), but whether it reports the dual-supply backplane strap or the actual presence of a second supply — i.e. whether a single-supply 700 would read it clear — is not stated; every observation in evidence is of the set state.
4. **The LCD's ROM version.** The manual's healthy display prints `ROM ver.1.1.20.1` [2] p. 53 while the production image prints `ROM vers.1.1.22` [7]. Whether `1.1.20.1` is a distinct, earlier ROM revision — the family's corpus holds two images, neither of which would print it — or a stale sample in the manual is unresolved.
5. **The enclosure weight.** The developer note's "approximately 60 pounds with 1 hard drive" [1] §8.1 p. 30 and the service manual's 84–92 lb [2] Specifications/Physical p. 16 never reconcile; neither document breaks the figure down per model.
6. **The 176 MHz 604 card.** Secondary coverage attests a 176 MHz 604 upgrade card (44 MHz bus, fast L2 enabled); no Apple document in evidence names it, and whether it shipped is open.
7. **The 'Shiner HE' codename.** No Apple document prints "Shiner" or "Shiner HE"; the name and the January 1996 Macworld introduction date are secondary-source material [9], with Apple's own corpus contributing only the LE/HE power-class labels [2] Specifications/Electrical p. 11.
8. **The SMP machine's firmware shape.** The 700/200SMP's device tree — whether it publishes two CPU nodes, and what `WhoAmI` returns on each — is unpublished, as is whether any AIX release enables the second processor ([ans.md](ans.md) §7 item 3).
9. **The extended-keyboard requirement.** The specification states AIX "requires an extended keyboard for installation" [2] Specifications/I/O Devices p. 8, yet observed installs never touch ADB at all (§5, item 8); whether any installer path actually reads the keyboard is unestablished.
10. **Cache DIMM options.** The 700 ships 1 MB; no Apple price list or service document names a smaller, larger or replacement cache DIMM part, so the range the hardware accepts beyond the fitted size is attested only by the family's generic rules ([ans.md](ans.md) §2.4).
11. **The 700 power interconnect pinout.** Apple deferred it to Developer Support [1] §6.3 p. 21 and it was never published — the one wiring document the dual-supply backplane would need.
12. **64-bit and 3.3 V PCI cards.** The sockets are "64 bit-5 V (184)" parts [1] §8.2 p. 32 and the service spec calls the slots "64-bit, universal" [2] p. 35, but the implementation is documented as 32-bit 5 V [1] §7.1 p. 22; whether a 64-bit-wide or 3.3 V-signalling card functions is not established by any document.
13. **The rear cabling's bus-length budget.** The family's under-6-feet SCSI bus extent ([ans.md](ans.md) §2.8) is stated for the backplane; how the rear bracket's cable run is accounted for in that budget — or whether it shortens the usable external chain — is not stated.
