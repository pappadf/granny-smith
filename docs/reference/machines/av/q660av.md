## 1. Identity

### 1.1 Names and model history

The **Macintosh Centris 660AV** is the second of the two shipping machines of the AV family: "a less expensive desktop
version of the Macintosh Quadra 840AV in the same low-profile enclosure as the Macintosh Centris 610", running the same
platform — one circuit board design, one chip set, one 2 MB boot ROM — at 25 MHz instead of 40 [1] p. 3
([AV](av.md) §1.1). Apple's board codename for it is **Tempest**, as the 840AV's is Cyclone; the codenames survive in the
platform's own naming, most visibly in the **CIVIC** chip's expansion: "Cyclone Integrated Video Interfaces Controller"
[1] p. 14.

The product was introduced in mid-1993 under the Centris name and renamed **Macintosh Quadra 660AV** when Apple retired
the Centris brand late in the machine's life ([AV](av.md) §1.2). Nothing hardware- or software-visible changed with the
renaming as far as the evidence reaches: the developer note was published under the Centris name [1], the shared boot
ROM's product record (§1.2) predates both names, and the system-software gating is by box flag alone, which is the same
for both names [3]. When the rename took effect, and whether any shipping software identifies itself as a "Quadra
660AV", is not established by the evidence set (§6).

Throughout this page the machine is called the **660AV**; its sibling is the [Quadra 840AV](q840av.md).

### 1.2 Machine identification

The 660AV is identified by the family's two-stage mechanism ([AV](av.md) §2.4); this section states only the values.

Two identity facts are unique to this machine in the shipping software set. First, the enabler that boots it carries
display-card name resources for exactly the two boards — "Macintosh 3A" and "Macintosh 3B" [3] — matching the ROM's
declaration strings [2], so the 660AV is the "3B" machine end to end. Second, the boot ROM's product table carries a
complete record for a **33 MHz Tempest** (strap nibble $8, machine ID 79, box flag 73) alongside this machine's record
[2] (*observed*); no such product shipped, and the developer note does not mention it ([AV](av.md) §6.3). A machine
whose strap nibble matches no record in the table never boots: the start-up code spins forever ([AV](av.md) §2.4).

## 3. Per-subsystem wiring

### 3.1 Processor, clocks and bus timing

The processor is the full MC68040 — integer unit, FPU, dual MMUs, dual 4 KB caches — at 25 MHz [1] p. 12. Neither model
uses the 68040's optional bus snooping ([AV](av.md) §1.4). The machine's clock tree is the family tree of
[AV](av.md) §5.5 with the asterisked (660AV) values selected:

| Domain | Clock | This machine | Same on both machines? |
|---|---|---|---|
| CPU bus | PClk | 50.0000 MHz | no — 80 MHz on the 840AV |
| CPU bus | BClk | 25.0000 MHz | no — 40 MHz |
| CPU bus | PClk/4 (I/O) | 12.5000 MHz | no — 20 MHz |
| DSP | CKI | 55.5000 MHz | no — 66.6667 MHz |
| I/O | C32M / C16M | 31.3344 / 15.6672 MHz | yes |
| I/O | C22_5792M / C24_576M (Singer) | 22.5792 / 24.5760 MHz | yes |
| I/O | C25M (SCSI) | 25.0000 MHz | yes — a separate oscillator that merely equals BClk numerically |
| I/O | C20M (MACE) | 20.0000 MHz | yes |
| I/O | CudaClk | 0.032768 MHz | yes |
| audio | ATECS 15.0528 / 16.384, 45.1584 / 49.152 | as listed | yes |
| NuBus | C40M / C20M / CN10M | 40 / 20 / 10 MHz | yes — but sourced from the adapter card's MUNI on this machine (*inferred — unverified*: the bridge is on the adapter, §4.1) |
| video | NTSC / PAL / video-in | 14.31818 / 17.734475 / 26.8000 MHz | yes |

[1] Table 2-2 pp. 17–18. BClk remains the platform's metronome ([AV](av.md) §5.5): DRAM, ROM, and the CPU-bus sides of
the PSC and MUNI all count in BClk, and the DSP alone counts in CKI.

The 660AV's access timings are the faster columns of the shared tables, because 70 ns DRAM at 25 MHz has more margin
than 60 ns DRAM at 40 MHz. DRAM access, in BClk cycles, under the developer note's single/multiple conditions [1]
Table 2-3 p. 20:

| Access | Main processor | MUNI and PSC | DSP (CKI cycles) |
|---|---|---|---|
| Single read, single / multiple | 4 / 5 | 4 / 5 | 9 / 11 |
| Single write, single / multiple | 3 / 5 | 3 / 5 | 8 / 11 |
| Burst read, single / multiple | 4-2-2-2 / 4-2-2-2 | 4-2-2-2 / 4-2-2-2 | 9-4-4-4 / 11-4-4-4 |
| Burst write, single / multiple | 3-2-2-2 / 4-2-2-2 | 3-2-2-2 / 4-2-2-2 | 8-7-7-7 / 11-7-7-7 |

VRAM access, in BClk cycles [1] Table 3-26 p. 56: single write 3 (random) / 4 (immediately succeeding); burst write
3-2-2-2 / 4-2-2-2; single read 4 / 4; burst read 4-2-2-2 / 4-2-2-2; VDC write 19 / 20 — the capture-path figure is
identical to the 840AV's, so the video-in write bandwidth per BClk is *lower* on this machine. DRAM refresh costs eight
main-processor clock cycles and does not disturb RAM access timing; refresh does not occur while the DSP holds the bus
[1] p. 20. ROM accesses cost five bus clock cycles on this machine [1] p. 21, matching the ROMspeed (0, set, 0) pattern
of §2's table ([AV](av.md) §2.5).

The CPU bus, its four masters, the arbiter and the timeout rules are the family's, unchanged ([AV](av.md) §5.2) — with
one wiring consequence specific to this board: since the MUNI lives on the adapter card, a machine without the adapter
has **three** bus masters, not four, and the YMCA's MUNI-side timeout simply never fires (§4.1).

### 3.2 Main memory

Main memory is DRAM on 72-pin SIMMs plus a soldered base: "In the Macintosh Centris 660AV, 4 MB of RAM capacity is
soldered to the board and there are slots for two expansion SIMMs" [1] p. 13. The capacities follow: each SIMM holds one
or two banks of up to 16 MB per bank [1] p. 13, so the ceiling is 4 MB + 2 × 32 MB = **68 MB** [1] pp. 3, 13. The
controller's own ceiling is unchanged — the ROM's RAM-information record for the Tempest boards declares the same eight
16 MB banks at 16 MB spacing, minimum bank 1 MB, as the 840AV's, with no 68 MB figure encoded anywhere [2] (*observed*);
the 68 MB limit is a configuration fact (population), not a controller one ([AV](av.md) §2.6).

Module rules are the family's ([AV](av.md) §2.8): CAS-before-RAS refresh, no more than eight chips per bank, composite
SIMMs unusable, parity ignored. The DRAM speed grade is this machine's delta: 70 ns access time acceptable, versus the
840AV's mandatory 60 ns [1] pp. 6, 13. The YMCA sizing algorithm — two passes per bank, standard then wide mode, bank
pairs programmed through the four width registers, contiguous banks merged ([AV](av.md) §2.6) — is identical here; the
shipped code makes no distinction between soldered and socketed banks (*inferred — unverified*: nothing in the sizing
path treats them differently, but no evidence pins the soldered memory to specific bank numbers, §6).

### 3.3 Video output

The display path is the family's ([AV](av.md) §4.3) with this machine's constraints. VRAM is fixed at 1 MB — "two banks
of VRAM soldered in, each bank providing 0.5 MB of storage" [1] p. 33 — with no expansion sockets and no expansion
support [1] pp. 6, 30. The developer note's monitor/depth table marks the configurations "also supported by the
Macintosh Centris 660AV (using standard VRAM)" in boldface [1] p. 34; the text layer of the source does not preserve
boldface, so the table's exact 660AV subset must be read from the printed page (§6) — the constraints that are stated in
prose are:

- graphics and video are both capped at **16 bits per pixel** on this machine [1] p. 5 (the 840AV reaches 24 bits for
  graphics);
- the maximum video window at 16 bits is **512 × 384** pixels [1] pp. 6, 33 (the 840AV's is 640 × 480);
- 21-inch RGB monitors are **not** supported [1] p. 6.

Where a 16-bit video window is offered at all, its size is constrained by the family rule: with the video window width
512 pixels or less the height may reach 512 pixels; wider than 512 the height is limited to 340 pixels [1] p. 35. The
shared CIVIC driver's 52-mode declaration roster, the monitor-sensing mechanism and the boot-time initialization sequence
are the family's and [CIVIC](civic.md)'s subject (§§3.4, 4.2); the ROM selects this machine's board sResource ($36,
"Macintosh 3B") at slot-initialization time [2] (*observed*).

The pixel-clock synthesizer is the one chip-set difference on the board: "The Endeavor is a programmable video clock
chip used in the Macintosh Quadra 840AV; the equivalent in the Macintosh Centris 660AV is called Clifton Plus" [1] p. 17.
It answers at the same $50F2E000 window, is programmed bit-serially rather than with Endeavor's byte registers, and is
probed at driver-open time because some 660AV boards carry a second-generation variant of it — the driver distinguishes
the two by shifting an ID word into the port and reading a byte back, and carries frequency words for both in every
mode's parameter block [2] (*observed* in the video driver and its boot-time initializer); the programming sequences are
[CIVIC](civic.md) §1.4's subject. Which board revisions carry which variant is not documented (§6; [CIVIC](civic.md) §6).

### 3.4 Video input

The capture chain — TDA8708/TDA8709 ADCs, the DMSD decoder, the VDC scaler, the capture buffer in VRAM — is identical to
the family's ([VDC](vdc.md) §1), with two machine deltas. First, the maximum video window is 512 × 384 pixels [1] p. 33.
Second, the 660AV's digitizer driver **skips the S-video input probe entirely**: where the 840AV's open path probes for a
live signal on the C input and falls back to composite, this machine's path commits the S-video configuration directly —
*observed* as the one use of the open path's machine-class byte (0 for the 840AV, 1 for the 660AV) [2]; the probe/commit
semantics and the full consequence are [VDC](vdc.md) §4.4's subject. The 660AV's analog front end does not need the
auto-detect — a genuine per-board difference in the input mux wiring, of which the machine-class byte is the only
software-visible trace. Composite input on both machines enters through the same 7-pin mini-DIN socket with the I²C
lines for the video-in chips [1] Table 2-12 p. 33.

The DAV expansion connector — the alternate source of YUV into the VDC — is on the adapter card on this machine, not on
the main board ([AV](av.md) §2.11; §4.3 below).

### 3.5 Audio, telephony and the DSP

The audio subsystem is unchanged from the family ([AV](av.md) §4.4): the Singer codec on the PSC's sound engine, all
sound synthesis and capture through DSP tasks, the ATECS clock synchronizer for the GeoPort telecom path. The external
panel is identical on both machines — ministereo Audio In and Audio Line Out sockets, with the left channel on the tip
and the right on the ring — and so are the signal levels, the 20 Hz–20 kHz bandwidth and the built-in speaker [1] p. 38
([Singer](singer.md) §1.2). The DSP runs at CKI = 55.5000 MHz on this board [1] pp. 13, 17–18, and its bus-side timing
is counted in that domain (§3.1); everything else about the DSP subsystem — the shared address space, the boot protocol,
the frame-overrun machinery — is [DSP board](dsp3210-board.md)'s subject, and the board wiring does not differ from the
840AV's ([DSP board](dsp3210-board.md) §1.2).

### 3.6 Storage and external I/O

**SCSI.** The internal bus is a 50-pin ribbon connector for internal devices plus the external DB-25; the interface is
electrically and mechanically compatible with the rest of the Macintosh family [1] p. 24. This machine's internal bay
set is the smaller of the two: "The Macintosh Centris 660AV can support one 3.5-inch internal hard disk and an optional
5.25-inch CD-ROM drive" — two internal devices where the 840AV mounts three — within the family-wide total of seven
SCSI devices [1] pp. 3, 24. The power budget per internal device is 1.5 A at +5 V and 1.5 A at +12 V [1] Table 2-7 p. 24.
Termination follows the installer's rule: the device at the end of the internal cable carries the terminators and the
others must not [1] p. 27; the bus is continuous across internal cable, board traces and external cable [1] p. 27.

**Ethernet.** Built-in, through the MACE core of Curio, on a standard Ethernet connector taking a drop-box cable
[1] p. 22 and Table 2-5 p. 22; the station address comes from the PROM at $50F08000 ([MACE](mace.md) §1.2). The ROM's
Ethernet configuration resource for this machine (the "Tempest25" record) is byte-identical to the other three variants'
[2] (*observed*; [AV](av.md) §6.4) — Ethernet sees no difference between the speed grades.

**Serial.** Two ports: an 8-pin mini-DIN printer port and a 9-pin mini-DIN modem port that accepts 8-pin plugs as well;
GeoPort telephony runs on the modem port [1] p. 22. LocalTalk on the printer port, the SCC's FIFOs and the PSC's serial
DMA are the family's ([AV](av.md) §4.2).

**Floppy.** One internal Apple SuperDrive, 1.4 MB media [1] p. 3, on the New Age controller with its PSC DMA channel
([New Age](new-age.md) §1.2); no machine delta exists.

**ADB.** One mini-DIN 4-pin socket on the back panel [1] p. 21, Table 2-4 p. 21, wired to the Cuda as on the 840AV
([Cuda](cuda.md) §1.2). The connector's pin 2 is the classic "power on" line, "connect to pin 4 to turn on the system"
[1] Table 2-4 p. 21 — stated in the shared section of the developer note; whether a machine with a hard power switch
(§3.7) honors it is not documented (§6).

### 3.7 Power and the hard switch

Two power-related deltas distinguish this machine. First, it has **no slot power control**: the 840AV "provides power
control service to its expansion slots, so plug-in cards can turn the computer on and off" — the 660AV does not [1]
pp. 5–6. Second, its power-off style is a **hard power switch**: the ROM's feature flags for the Tempest boards add the
hasHardPowerOff bit to the family value [2] (*observed*; §1.2), where the Cyclone boards carry the soft-power-off
configuration ([AV](av.md) §6.2). The Cuda microcontroller is present and wired identically — power management, resets,
PRAM, the real-time clock, ADB, the GeoPort power-signaling path ([Cuda](cuda.md) §1.2) — so the difference is the
presence and behavior of the front-panel switch, not the controller. How the hard switch interacts with the Cuda's
power-down pseudo-commands on this machine is not separately documented; the transport-level behavior is [Cuda](cuda.md)
§3.11's subject.

## 4. Expansion

### 4.1 The NuBus adapter card and the single slot

This machine's NuBus is optional in the strict sense: "In the Macintosh Centris 660AV, NuBus exists only if an adapter
card has been installed in the PDS connector" [1] p. 18. The adapter card "places its NuBus accessory card parallel to
the main circuit board" [1] p. 40 (Figure 2-13), accepting **one short card** — 4 by 7 inches, of the same physical
configuration as the 840AV's short cards; the 660AV cannot take a long card [1] pp. 6, 40. The adapter carries the MUNI:
"the adapter card carries the MUNI chip, so this chip is present in the system only when the adapter card is installed"
[1] p. 40 (also [1] p. 14). The card-mounting hardware — the expansion-card bracket, its insulator, its EMI shield, and
the adapter card itself — is documented as Apple drawings 805-0530-06, 725-0051-02, 630-0450-10 and 630-0450-12
respectively [1] Appendix D p. 453.

Because the MUNI may be absent, this machine is the reason the platform has a MUNI presence probe: the boot ROM reads
the bridge's Control register under a bus-error handler and records the bridge as absent when the access faults
([AV](av.md) §5.4). A 660AV without the adapter card must therefore answer the read of $50F30008 with a clean bus error,
not with data ([AV](av.md) §3.6). With the adapter installed, the slot behaves exactly as the family's NuBus section
describes — NuBus '90 at the 10 MHz clock with the 20 MHz burst clock, MUNI block transfers enabled per slot, the 25.6 µs
MUNI transaction timeout ([AV](av.md) §5.4) — with the slot-card power budget of [1] Table 2-18 p. 42 (2.0 A at +5 V,
0.175 A at +12 V, 0.15 A at −12 V, with the capacitance limits listed there). Whether that budget applies unchanged to a
card fed through the adapter, or the adapter imposes its own, is not stated (§6).

**The slot's geographic address is the one place the two primary sources disagree.** The developer note states: "The
Macintosh Centris 660AV slot is address $C" [1] p. 39. The boot ROM's own machine records say **slot $E**, twice and
consistently:

- the machine's slot-PRAM default resource declares exactly one physical connector, slot $E at position 1, where the
  840AV's declares three, slots $C/$D/$E at positions 1/2/3 [2] (*observed*: the "Tempest25" record is 12 bytes, the
  "Cyclone40" record 20, and the connector list is the difference);
- the machine's decoder record marks slots $C and $D as direct-slot entries — present for software, no connector — and
  slot $E as the one physical connector [2] (*observed* in the per-family decoder tables).

The PDS connector's documentation leans the same way: its /NMRQ(6) line is annotated "NuBus slot $E interrupt; also
connected to NuBus slot $E" [1] Table 3-23 p. 49 — and /NMRQ(6) is, in the Macintosh slot-interrupt numbering, slot $E's
line. On the reading of the ROM records, a card in the adapter answers $FE000000–$FEFFFFFF and would collide with
nothing, since the 660AV has no slot-$E PDS video card to claim that window (contrast the first Power Macintosh
machines, where slot $E is a PDS video slot); on the developer note's reading it answers $FC000000. The conflict is
recorded here unresolved: both readings are sourced, neither source reconciles them, and a re-implementation must
choose (§6). Everything else about the slot is source-consistent.

### 4.2 The processor-direct slot

"The Macintosh Centris 660AV (but not the Macintosh Quadra 840AV) can accept an accessory card that plugs directly into
the main circuit board … An accessory card plugged into the main circuit board can gain access to the processor as well
as to the DAV bus" [1] p. 46. The connector is an **AMP type 650231-3**, 140 pins, "pin-compatible" in the sense that its
pins align with the Macintosh Centris 610's 650231-5, "so it is possible to design PDS cards that work on both models"
[1] p. 46. The full pin assignments are [1] Table 2-21 pp. 47–48; the table marks with an asterisk the pins whose signals
differ from the Centris 610's and with a minus sign the pins the 660AV does not use.

The signal inventory, grouped as the developer note groups it. Most pins connect **directly to the main processor with
no buffers** [1] p. 49: the full 32-line address bus A(0)–A(31), the full 32-line data bus D(0)–D(31), SIZE(0)/(1), RW,
/LOCK, /TS, /TA, /TEA, TT(0)/(1), TLN(0)/(1), TM(0)–TM(2), /CPURESETOUT, /MEM.RESET, /TRST, BS.CLK, /BS.MODE, and
+5 V/+12 V/−12 V/GND. The remainder divide into two documented classes:

| Signal | Class | Function [1] Tables 3-22/3-23 pp. 49 |
|---|---|---|
| /IPL(0)–/IPL(2) | restricted | interrupt priority lines **from the PSC**; "not to be used as wire-OR lines; can be monitored by a PDS card" |
| /TIP.CPU | restricted | from the 68040 on the main board; "not connected to any other part of the computer" |
| /SYS.RESET | I/O | lets a PDS card drive system reset; "used only for testing" |
| AUX.CPUCLK (pin 71) | input | "buffered version of main processor's bus clock (BClk)" — the only buffered clock |
| /BG.CPU | output | bus grant for the main processor |
| /BG.40SLOT / /BR.40SLOT (pins 119 / 51) | I / O | bus grant / bus request for a PDS card — **not supported** on this machine (below) |
| /MEM.RESET | input | "fast reset generated for memory controller IC" |
| /MI.SLOT | output | memory inhibit from the PDS card to the memory controller |
| /NMRQ(6) (pin 58) | output | "NuBus slot $E interrupt; also connected to NuBus slot $E" (§4.1) |
| 040INPROGRESS (pin 57) | input | high when the main processor is bus master (§4.2.1) |
| MUNI/RQ (pin 137) | — | named for the NuBus bridge; otherwise undocumented (§6) |

The designer cautions, all from [1] p. 49, define the board's electrical contract:

- **Capacitive load**: not more than 40 pF on the address, data and clock lines, not more than 20 pF on the control
  lines — the consequence of the unbuffered wiring.
- **AUX.CPUCLK** is terminated with a series resistor; all loads on the card should be lumped to reduce reflections.
- **/DLE (pin 45) is not connected**, because DLE-type read actions are not supported by some of this machine's bus
  masters.
- **No snooping**: pins 46 and 116 are grounded.
- **/BR.CPU (pin 50) is not connected**, "because the Macintosh Centris 660AV system bus arbiter always grants bus
  control to the microprocessor when there are no other high-priority bus requests" — the YMCA parks the bus on the
  processor.
- **No PDS bus mastering**: the machine "does not support using an accessory card as a bus master in addition to the
  existing bus masters (the processor, the DSP, the PSC, and the MUNI)", so /BG.40SLOT (pin 119) and /BR.40SLOT
  (pin 51) are not used. This is the platform's four-master arbitration statement with the PDS explicitly outside it
  ([AV](av.md) §5.2).
- **/TBI (pin 112) is tied to +5 V**, the TBI signal being "not allowed by some bus masters".
- **/PDS.SLOT.E.EN (pin 132) is not connected**, "because the MUNI is programmed to decode or ignore individual slots".

#### 4.2.1 040INPROGRESS and the alternate burst-write protocol

The 040INPROGRESS line is this machine's one exported piece of arbitration state: it "is high when the main processor
is the bus master. When this signal is low, a different bus master can use the alternate burst write timing protocol"
[1] p. 49. The processor bus accordingly supports **two burst-write timings** [1] p. 51: the standard 68040 protocol
when pin 57 is high (processor mastering), and an alternate protocol — with different setup and hold relationships,
shown in Figure 2-19 of the developer note — that a non-processor master (the DSP, the PSC, or the adapter's MUNI) uses
when pin 57 is low. A PDS card that monitors the line can tell which master's timing to expect; the cycle-by-cycle
numbers of the two protocols are in the figure and not in the text (§6). This is the PDS-side counterpart of the family
bus statement ([AV](av.md) §2.2).

### 4.3 The DAV connector on the adapter card

The digital audio/video expansion connector gives a slot card direct access to the platform's 4:2:2 unscaled YUV video
input and the Singer codec's digital audio ([AV](av.md) §2.11). On this machine it "is mounted on the optional NuBus
adapter card" [1] p. 42 — so DAV access, like NuBus, requires the adapter. The connector is the same 40-pin KEL
8801-40-170L with the same pin assignments and 20 pF load limit as the 840AV's [1] pp. 42–45; both machines take a
short card carrying the DAV plug, and the 840AV can also take a long one [1] p. 42. A DAV card may disable the DMSD and
feed its own YUV into the VDC ([AV](av.md) §2.11), and the audio subframes it can inject ride the same Singer time-division
frame bus ([Singer](singer.md) §3.1). The PDS grants "access to the DAV bus" as well [1] p. 46, but Table 2-21 lists no
Y/UV or Singer pins among the PDS assignments — which pins carry the DAV signals to a processor-direct card is not
documented (§6).

### 4.4 What the machine does not carry

Against other low-profile Macintosh machines of its generation — and against its own sibling — the 660AV lacks:

- **No VRAM expansion.** No VRAM sockets; 1 MB is the fixed configuration [1] pp. 6, 30, 33.
- **No second or third NuBus slot**, and no NuBus at all without the adapter [1] pp. 18, 40.
- **No slot power control** — a card cannot turn the machine on or off [1] pp. 5–6.
- **No long-card capability** [1] pp. 6, 40.
- **No communication-slot-class internal connector** of the kind its enclosure sibling (the Centris 610) carries is
  documented anywhere in the developer note; the PDS connector is the machine's one non-NuBus internal expansion
  interface on record (§6).
- **No 1 GB internal hard disk option** — of the two internal-drive options beyond the base configuration, the 500 MB
  drive is offered for both machines and the 1000 MB drive "in the Macintosh Quadra 840AV only" [1] p. 3.

## 5. Boot sequence summary

The platform-level start-up path is the family's ([AV](av.md) §§2.4–2.6, 3.5, 5.4); this section walks it in order and
marks every point at which this machine's identity changes what happens. All ROM observations are from the shared image
[2].

1. **Reset.** The YMCA's startup overlay maps the ROM at address 0 ([AV](av.md) §3.5); the 68040 takes its initial stack
   pointer from the ROM's checksum longword and its initial PC from offset $04 — $0000002A, a `JMP` into the ROM's
   start-up entry ([AV](av.md) §2.9). The start-up code sets its stack and installs data transparent translations
   covering the $5xxxxxxx I/O region and NuBus space, so POST reaches the CPU-ID register and the I/O island with the MMU
   off (*observed* in the cold-start prologue; [AV](av.md) §3.1).
2. **Identity.** GetCPUIDReg reads $5FFFFFFC, requires $A55A, requires the location not writable, then the four strap
   registers are read as longwords and their bit-31 values assembled into a nibble ([AV](av.md) §2.4). **$B selects the
   Tempest 25 product record** — machine ID 60, box flag 54, and the speed pattern of step 3. A nibble matching no
   record hangs the machine forever at the identity-failure loop [2] (*observed*).
3. **Speed programming.** The Tempest 25 path clears DRAMspeed0/1 and CPUspeed0/1, writes ROMspeed as (0, set, 0), then
   calls the expansion-information routine and — only if it reports the MUNI present — writes **$14** to the MUNI's
   Control register [2] (*observed*, instruction for instruction at ROM offset $4080F468 through $4080F496). This is the
   third row of the family speed table ([AV](av.md) §2.5). On this machine the MUNI write is *gated*, unlike the 840AV's:
   the code tests the presence bit and skips the write when the adapter card is absent [2] (*observed*).
4. **The MUNI presence probe** itself has already run inside step 3's call: the routine reads the MUNI Control register
   under a bus-error handler, and a fault marks the bridge absent ([AV](av.md) §5.4). This machine's decoder record
   deliberately omits the expansion bases, so the ROM trusts nothing and probes [2] (*observed*;
   [AV](av.md) §3.3). A machine without the adapter must fault the probe cleanly.
5. **VIA and Cuda initialization.** The pseudo-VIA1/VIA2 windows are initialized and the Cuda sync transaction brings up
   PRAM access ([AV](av.md) §4.1; [Cuda](cuda.md) §4.1) — identical here; the ROM carries one VIA-init and Cuda-init
   sequence for both boards [2].
6. **POST.** The power-on self-test runs the ROM checksum, the boot chime, RAM sizing (the two-pass bank sweep of
   [AV](av.md) §2.6) and the memory tests. The AV machines have **no machine-specific POST subtest**: they fall through
   to the generic set — SCC and VIA tests only, no sound and no DSP self-test [2] (*observed* in the subtest selection;
   the shipped POST for this machine exercises none of the AV-specific hardware).
7. **MMU and 32-bit mode.** The page templates of the family map are installed ([AV](av.md) §3.1): RAM cacheable, ROM,
   the video I/O region, VRAM, the I/O island and its alias, the E-Disk aperture, and the 24-bit compatibility map with
   the second ROM megabyte at $900000 ([AV](av.md) §3.4). Identical for both boards.
8. **Slot initialization.** The CIVIC video primary initializer runs — the one shared copy [2] — and selects this
   machine's board sResource, "Macintosh 3B" (spID $36) [2] (*observed*); the video record's board-ID field is the one
   per-board selector ([CIVIC](civic.md) §1.2). The slot manager's enumeration is fed by this machine's records: one
   physical connector, slot $E (§4.1) [2] (*observed*), with the MUNI's interrupt disabled outright as on the 840AV
   ([AV](av.md) §5.4) — whether that disable write is presence-gated on an adapterless machine is unverified (§6).
9. **Data cache.** The 68040's data cache is enabled only after slot initialization ([AV](av.md) §5.2) — the platform's
   coherency caution, identical here.
10. **OS load.** System 7.1 with **System Enabler 088** boots: the enabler's machine-gating resource admits exactly box
    flags 72 and 54 [3] — and the inference is that a stock 7.1 volume will not boot this machine
    (*inferred — unverified*: the gating mechanism is the documented behavior; no stock-volume boot attempt is on
    record) — and the enabler supplies
    the newer builds of the serial HAL, the video digitizer, the sound component stack and the DSP sample-rate converter
    whose ROM-resident predecessors are the shared image's [3] ([AV](av.md) §2.9).

The chime, the error beeps and the whole DSP bring-up are the family's ([Singer](singer.md) §4.2,
[DSP board](dsp3210-board.md) §4.2); no step of them differs on this machine beyond the clock rate.

## 6. Open questions

1. **The NuBus slot's geographic address** (§4.1): the developer note says $C [1] p. 39; the ROM's slot-PRAM resource and
   decoder record both say $E [2], and the PDS /NMRQ(6) annotation leans $E [1] Table 3-23 p. 49. No source reconciles
   the two. Which address the physical connector straps decides where a card's declaration ROM answers, so it is the
   single most load-bearing unknown on this page.
2. **The soldered RAM's bank assignment** (§3.2): which of the YMCA's eight banks the 4 MB soldered memory occupies, its
   organization, and whether the two SIMM slots map to fixed bank pairs — none of it is documented, and the sizing
   algorithm's indifference means software cannot reveal it either.
3. **The declaration-data board identity immediate** (§1.2): the $50 value in this machine's board sResource (and the
   840AV's $3D) is observed, but no document names the field or its consumer; what software reads it, if any, is
   unknown.
4. **PDS pin 137, MUNI/RQ** (§4.2): a PDS pin named for the NuBus bridge on a machine whose MUNI is on a card plugged
   into that very connector. Whether the adapter's MUNI bus request actually crosses the PDS, and what the pin does on
   a processor-direct card, is undocumented. The footnotes on pins 42 and 43 of Table 2-21 are likewise lost in the
   text layer of the source.
5. **/NMRQ(4) and /NMRQ(5) on the PDS** (§4.2): three NuBus interrupt inputs on a one-slot machine, the two lower ones
   marked as differing from the Centris 610. Their purpose — spare slot positions, or a different function entirely —
   is not documented.
6. **The DAV bus on the PDS** (§4.3): the developer note grants a processor-direct card access to the DAV bus, but
   Table 2-21 assigns no Y/UV or Singer pins. How DAV reaches a PDS card is unknown.
7. **The alternate burst-write protocol's numbers** (§4.2.1): the two timing protocols of Figure 2-19 are described in
   prose only to the level of "different"; the cycle-by-cycle figures are in the drawing and not in the text layer.
8. **The pixel-clock chip split** (§3.3): which 660AV board revisions carry Clifton Plus and which the second-generation
   variant, and what else differs between those boards, is undocumented ([CIVIC](civic.md) §6 carries the same hole).
9. **Table 2-13's 660AV subset** (§3.3): the boldface marking of the 660AV-supported monitor/depth configurations does
   not survive the text layer; beyond the prose constraints (16-bit cap, 512 × 384 window, no 21-inch), the exact
   per-monitor depth support must be read from the printed table.
10. **The renaming** (§1.1): when the Centris 660AV became the Quadra 660AV, and whether any shipped software or
    documentation artifact identifies the machine by the later name, is not established by this evidence set; the
    hardware identity (machine ID 60, box flag 54) is fixed from the June 1993 ROM onward.
11. **ADB power-on with a hard switch** (§3.6): the ADB connector's power-on pin is documented in the shared section
    [1] Table 2-4 p. 21; whether this machine — with its hard power switch and no slot power control — honors it is not
    stated.
12. **The MUNI interrupt-disable write on an adapterless machine** (§5 step 8): the boot ROM writes the MUNI's interrupt
    control register to disable its interrupt ([AV](av.md) §5.4); on this machine without the adapter that write would
    fault unless gated, and the gating of that specific write is unverified.
13. **The slot-card power budget through the adapter** (§4.1): Table 2-18's per-card budget is stated for the family;
    whether the adapter card passes it through, derates it, or adds its own allowance is not documented.
14. **Figure 2-1's dotted lines** (§1 of the developer note): the block diagram encloses "parts omitted in the
    Macintosh Centris 660AV" in dotted lines [1] p. 10, but the text layer does not identify them; the expected members
    — the MUNI, the VRAM expansion sockets — are *inferred — unverified*.
