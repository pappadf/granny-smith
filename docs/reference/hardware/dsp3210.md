## 1. Overview

### 1.1 What the part is

The AT&T DSP3210 is a 32-bit floating-point digital signal processor in the AT&T (later Lucent)
WE DSP32 lineage — the third generation after the DSP32 and DSP32C, whose instruction-set
architecture it inherits [2] §1.2. Unlike its ancestors it was designed not as a stand-alone DSP
board part but as a **bus-master peripheral for personal computers and workstations**: a 32-bit,
byte-addressable external bus with direct support for both 680x0- and 80x86-style signalling,
retry, relinquish/retry and bus-error protocols, and page-mode DRAM support [1] "Features and
Benefits", §"Bus Interface". The design goal is that the DSP fetches its programs and data
directly from the host's system memory, replacing the expensive local SRAM of a conventional DSP
system with the computer's existing RAM [1] "Applications".

Internally the part combines seven functional units [1] "Functional Description" [2] §3.1:

- **Control Arithmetic Unit (CAU)** — a RISC-like integer core: 32-bit ALU, 32-bit barrel
  shifter, 32-bit program counter and twenty-two 32-bit general-purpose registers; it executes
  the integer, data-move and control instructions and generates the operand addresses for the
  floating-point instructions (§2.1).
- **Data Arithmetic Unit (DAU)** — the signal-processing engine: a 32-bit floating-point
  multiplier and a 40-bit floating-point adder working in parallel, four 40-bit accumulators
  with guard bits, single-cycle data-type conversion hardware, and two control registers
  (§2.2, §3.8).
- **On-chip memory** — two 1K × 32 SRAM banks and a 256 × 32 mask boot ROM, all usable for
  instructions and data interchangeably (§3.1).
- **Bus interface** — the 32-bit external master/slave interface with quarter-cycle wait-states,
  arbitration and error handling (§3.4).
- **Serial I/O (SIO)** — a double-buffered serial port pair (input and output) with on-chip
  clock generation, up to 25 Mbit/s (§3.5).
- **DMA controller (DMAC)** — two DMA channels moving data between memory and the serial port
  without program intervention (§3.6).
- **Timer/Bit I/O (BIO)** — a 32-bit interval timer/counter plus an 8-bit general-purpose
  parallel port; four of the port's pins double as reset-configuration straps (§3.7).

Every instruction executes in one instruction cycle — **four CKI clock periods, four memory
accesses per cycle** (instruction fetch, X and Y operand fetches, and an optional Z write) — and
the multiplier and adder each produce one result per cycle, giving 33 MFLOP / 16.7 MIPS at the
66 MHz-class clock [1] "Functional Description" [2] §3.1, §7.1. The fully vectored interrupt
structure with hardware context save is rated at up to 2.6 million interrupts per second [2]
Table 3-1.

The part is supported by an optimizing C compiler and by AT&T's VCOS real-time multitasking
operating system, which keeps task code in host memory and caches working sets into the on-chip
RAM ("visible caching") [1] "Introduction", "System Integration". Apple's machines do not use
VCOS; the Macintosh AV systems ship their own DSP kernel — Apple's *Real Time Manager* — which
nevertheless follows exactly the same host-memory model (§4) (*observed*, [3]).

### 1.3 Clocking, packaging and electricals

- Single clock input **CKI**; the instruction cycle is CKI/4 [2] §7.1. The data sheet specifies
  the part at **55 MHz and 66 MHz** grades (CKI period 18 / 15 ns minimum) [1] "Timing
  Specifications", Table 3.
- Static design: no minimum CKI frequency is specified, but the maximum period *guaranteed by
  test* is 50 ns [1] Table 3 footnote.
- 5 V ± 5 % supply, 0–70 °C ambient; **132-pin PQFP** [1] "Pin Information", "Electrical
  Specifications".
- Typical internal power dissipation 750 mW; **powerdown (wait-for-interrupt) mode drops
  consumption below 300 mW** [1] "Low-Power, Powerdown Mode" [2] §3.2.3.
- Worst-case IDD at 5.25 V: 220 mA (55 MHz) / 285 mA (66 MHz) [1] "Electrical Specifications".
- Absolute maximum ratings: −0.5 V to +6 V on any pin, −40 to +120 °C ambient, −65 to +150 °C
  storage [1] "Absolute Maximum Ratings".

The AV Macintosh boards run the part at the 66 MHz-class CKI rate (*inferred from the shipped
kernel's observed timer cadence — 166,667 CKI/4 ticks per 10 ms frame — unverified at board
level*; see §4.2 and the board page).

## 2. Register file

The programming model spans three register classes: the CAU register set and the DAU
accumulators (instruction-operand registers), a small set of **IO registers** reachable through
the `iorN` syntax of the instruction set, and the **MMIO registers** of the on-chip
peripherals, addressed as memory in the MMIO window (§3.1). The IO register set proper is [2]
§3.6:

| IO# | Name | Size | Function |
|---|---|---|---|
| ior0 | ps | 16-bit | processor status (§2.2.1) |
| ior8 | emr | 16-bit | exception mask register (§2.3) |
| ior10 | spc | — | special control; write *size* selects the operation: `(byte)` = **sftrst**, `(long)` = **waiti** (§2.4) |
| ior12 | pcw | 16-bit | processor control word (§2.5) |
| ior14 | dauc | 8-bit | DAU control (§2.2.2) |
| ior15 | ctr | 8-bit | DAU clip-test register (§2.2.3) |

IO registers are of fixed size and must be accessed with the matching transfer size; reserved
bits must be written as zero [2] §3.6.

### 2.1 The CAU register set

Twenty-two general-purpose 32-bit registers r1–r22, plus r0, pc and the pc shadow [2] §8.1.1:

| Register(s) | Role |
|---|---|
| r0 | hard-wired to zero; writes are discarded, reads return 0 (also the source of the SAR boot's "clear location 0" instruction, §3.9) |
| r1–r14 | general-purpose in CA instructions; **pointer registers (rP)** in DA instructions, where they hold 32-bit byte addresses |
| r15–r19 | general-purpose in CA instructions; **increment registers (rI)** in DA instructions, holding 2's-complement post-modification values |
| r20 | **error trace**: receives the pc as part of error-exception dispatch (§3.3.3) |
| r21 | **stack pointer (sp)**: post-increment/decrement on it are always ±4 so the stack stays word-aligned; the conditional `sp = (long) sp++/--` forms disable interrupts for one instruction cycle [2] Table 4-8 |
| r22 | **exception vector table pointer (evtp)**: base of the 16-entry vector table (§3.3.2); cleared to 0 on reset |
| pc, pcsh | program counter and its interrupt shadow (§3.3.2) |

### 2.2 The DAU registers

#### 2.2.1 Accumulators a0–a3 and the ps register

Four 40-bit accumulators, each 24-bit mantissa + 8 guard bits + 8-bit exponent (§3.8). The
**ps** register exposes all machine flags [2] Table 8-1:

| ps bit(s) | Field | Meaning |
|---|---|---|
| 0–3 | n, z, v, c | CAU flags (negative, zero, overflow, carry) — read/write |
| 4–7 | N, Z, U, V | DAU flags (negative, zero, underflow, overflow) — read-only |
| 8–9 | ibf, obe | serial input buffer full / output buffer empty — read-only |
| 10–11 | sy, fb | SY pin level / SIO frame boundary — read-only |
| 12–13 | ir0, ir1 | **live level of the IR0N / IR1N pins** — read-only |
| 14–15 | — | reserved, read as zero |

The CAU flags are read/writable (a program can set them by writing ps); the DAU and I/O flags
are read-only. The ir0/ir1 bits are the *pin* level, not a latched interrupt request — the
distinction matters in practice because a polling loop watching them sees the pin, while the
interrupt machinery consumes the edge-latched request (§3.3.2); Apple's kernel depends on
exactly that distinction (*observed* [3], §4.2).

#### 2.2.2 dauc — DAU control register (ior14, 8-bit)

Selects the 8-bit conversion performed by `ic`/`oc`, the float→integer rounding mode, and the
write behaviour of the conditional accumulator loads [2] Table 8-3. Cleared on reset.

| Bits | Field | Encoding | Function |
|---|---|---|---|
| 3–0 | CONV | x0x0 / x0x1 / x1xx | μ-law / A-law / unsigned linear-byte **input** conversion for `ic` |
| | | 0x0x / 0x1x / 1xxx | μ-law / A-law / unsigned linear-byte **output** conversion for `oc` |
| 5–4 | ROUND | x0 / 01 / 11 | round-to-nearest / truncate-toward-−∞ / truncate-toward-0 on float→integer |
| 6 | COND | 0 / 1 | `ifalt`/`ifaeq`/`ifagt` have unconditional / conditional Z-writes |
| 7 | — | 0 | must be written 0; reads 0 |

Linear-byte mode overrides the μ/A-law setting on the corresponding direction. **A loading of
dauc from memory affects the following instruction** [2] §8.2.1, and a dauc load must be
followed by a CA instruction [2] §4.4.1.3. (For an unresolved contradiction between this
table and the instruction pages, see §5.)

#### 2.2.3 ctr — clip-test register (ior15, 8-bit)

Holds the last six values of the DAU N flag: bit 0 = current N, bits 1–5 = the flags computed by
the previous five flag-setting DA instructions [2] Table 8-4. It exists for 2-D/3-D clip-test
algorithms (a six-sided outcode can be assembled in six instructions and read into a CAU
register in one move). Bits 7–6 read as zero.

### 2.3 emr — exception mask register (ior8, 16-bit)

One mask bit per maskable exception source; 1 = enabled, 0 = disabled; all zero on reset [2]
Table 7-2. Bits are laid out in exception-priority order (highest to lowest):

| Bit | Field | Gates |
|---|---|---|
| 4 | AERR | address error exception (§3.3.3) |
| 5 | U/V | DAU overflow/underflow exception |
| 6 | NAN | IEEE NaN on an IEEE→DSP32 conversion |
| 8 | EXT0 | external interrupt 0 (IR0N, vector 8) |
| 9 | TIMER | timer counted to zero (vector 9) |
| 11 | IBF | serial input buffer full (vector 11) |
| 12 | OBE | serial output buffer empty (vector 12) |
| 13 | IFRM | input DMA frame complete (vector 13) |
| 14 | OFRM | output DMA frame complete (vector 14) |
| 15 | EXT1 | external interrupt 1 (IR1N, vector 15) |
| 0 | SL | not a mask: if 1, the current processing level is presented on the IACK[1:0] pins (00 base / 01 interrupt / 10 error / 11 double-error) |
| 1–3, 7, 10 | — | reserved |

Writing emr with bit 0 set additionally **drops a latched but not-yet-taken EXT1 request**
without taking it — undocumented in the manual, but exercised by Apple's kernel, which pulses
`r = emr; emr = r|1; emr = r` around its frame-overrun paths (*observed* [3]; §4.2).

### 2.4 spc — special control (ior10)

Accessed only through writes whose *size* is the opcode: `spc = (byte) r0` is **sftrst**
(software reset — returns the processor from the error level to base level, doing nothing
else), `spc = (long) r0` is **waiti** (enter powerdown / wait-for-interrupt) [2] Table 4-6. The
boot ROM's error routine writes it with a **`(short)`** store to assert both IACK pins at once
and halt [1] Listing 1 `boot_error` — the same signal pair that a double-error exception
asserts [2] §7.5.2.1. No other access size is documented for this register.

### 2.5 pcw — processor control word (ior12, 16-bit)

Configures the external memory system and the memory map [2] §6.2, Figure 6-2:

| Bits | Field | Function | Reset value |
|---|---|---|---|
| 1–0 | WA | wait-states for external partition A: 00 = 0-or-more, 01 = 1-or-more, 10 = 2-or-more, 11 = 3-or-more (quarter-cycle waits; SRDYN handshake extends further) | 11 (3-or-more) |
| 3–2 | WB | same, for partition B | 11 |
| 6–4 | PBD | page size for page-break-detect: 256/512/1K/2K/4K/8K/16K/32K words (i.e. 64k×n through 1G×n DRAM column geometry); A2–A9 always masked, A17–A31 never, A10–A16 per this field | 000 |
| 7 | SBD | sequential-address break detection enable (usable with 256-word pages only) | 1 |
| 8 | B/LN | byte order: 1 = big-endian, 0 = little-endian | 1 (big-endian) |
| 9 | M/IN | MS0–MS3 signalling style: 1 = Motorola, 0 = Intel | 1 |
| 10 | C/PN | memory map select: 1 = computer mode (on-chip at 0), 0 = processor mode (external memory A at 0) | from **BIO7** at reset |
| 11 | R/WN | RW pin polarity (active high for read vs. write) | from **BIO6** at reset |
| 12 | D/SN | AEN/MRN + DEN/MWN pin function: 1 = DRAM-style (AEN/DEN), 0 = SRAM-style (MRN/MWN) | from **BIO5** at reset |
| 13 | BRC | boot ROM control (0 = SAR boot, 1 = EPROM boot) | from **BIO4** at reset; **writing 1 from software locks the pcw against further modification** until reset or error exception |
| 15–14 | P/BN | PBD/BLMN pin function: 00 = BLMN (block-move indicator), 01/10/11 = PBD on partition A / B / both | 00 |

Note the reset interplay: pcw[9–0] reset to 0x38F (maximum waits, 256-word page, big-endian,
Motorola, SBD on, BLMN), while bits 10–13 are latched from BIO[7:4] on the rising edge of
RESTN [2] Table 7-4, §7.5.4.1. Writing pcw[13]=1 from a program *locks* the register — the
boot ROM relies on this only when BIO4 straps it at reset; a software write of the bit does
not force the EPROM path, it freezes the register ([1] Table 1 footnote).

### 2.6 The MMIO registers

All peripheral registers live in the 256-word MMIO window and are accessed as ordinary memory
(§3.1). Addresses differ between byte orders [2] Figure 3-5, §9:

| Register | Big-endian address | Little-endian address | Bits | Access | Unit |
|---|---|---|---|---|---|
| ibuf | 0x0404 | 0x0404 | 31–0 | R | serial input buffer (§3.5) |
| obuf | 0x0408 | 0x0408 | 31–0 | W | serial output buffer |
| ioc | 0x040C | 0x040C | 31–0 | R/W | serial I/O control (§3.5) |
| tcon | 0x0413 | 0x0410 | 7–0 | R/W | timer control (§3.7) |
| timer | 0x0414 | 0x0414 | 31–0 | R/W | timer count (§3.7) |
| bioc | 0x041B | 0x0418 | 7–0 | R/W | bit-I/O direction (§3.7) |
| bio | 0x041E | 0x041C | 15–0 | R/W | bit-I/O data (§3.7) |
| idp | 0x0420 | 0x0420 | 31–0 | R/W | input DMA pointer (§3.6) |
| odp | 0x0429 | 0x0424 | 31–0 | R/W | output DMA pointer |
| icnt | 0x042A | 0x0428 | 15–0 | R/W | input DMA transfer count |
| ocnt | 0x042E | 0x042C | 15–0 | R/W | output DMA transfer count |
| dmac | 0x0433 | 0x0430 | 7–0 | R/W | DMA control |

(The MMIO word at 0x0400 is reserved.) Each register must be accessed with its own transfer
size [2] §3.4 — though in practice the hardware tolerates violations (§5, the masked
misaligned-store quirk).

### 2.7 Reset state

On reset — power-on reset (the internal circuit holds the chip for the first 8 rising CKI
edges after VDD ≥ 3 V) or assertion of RESTN (asynchronous, internally synchronized to the
falling CKI edge, minimum pulse 4 CKI periods) — the following state is forced [2] §7.5.4,
Table 7-4:

| Register | Reset value |
|---|---|
| evtp (r22) | 0 (vector table at address 0) |
| pc | 0 (reset dispatches through vector 0) |
| r20 | the previous pc (result of the internal `call evtp+0 (r20)`) |
| dauc | 0 (round-to-nearest, μ-law, unconditional Z-writes) |
| pcw[9–0] | 0x38F |
| pcw[10–13] | latched from BIO[7:4] on the RESTN rising edge |
| emr | 0 (all maskable exceptions masked) |
| tcon | 0 (timer held) |
| timer | 0xFFFFFFFF |
| ioc | 0 (external clocks, 32-bit lengths, LSB-first) |
| dmac | 0 (DMA disabled) |
| bioc | 0 (all BIO pins inputs) |
| bio output bits | 0 |

The CAU general registers, the DAU accumulators and the MMIO data buffers (ibuf, obuf) are not
listed as affected. All bus-interface pins sit at high impedance through the reset state and
the first 11 clock periods of the reset sequence [2] §7.5.4.1.

## 3. Behaviour

### 3.1 Memory organization: the two memory maps

The 4 Gbyte byte-addressable space is divided into seven regions; which map is active depends
on **pcw[10] (C/PN)** [2] §3.4, Figure 3-4:

**Computer mode (C/PN = 1)** — on-chip resources at the bottom of the map:

| Range | Region |
|---|---|
| 0x00000000–0x000003FF | boot ROM (256 words) |
| 0x00000400–0x000007FF | MMIO (256 words) |
| 0x00000800–0x0000DFFF | reserved (future on-chip expansion, to 15.5K words) |
| 0x0000E000–0x0000EFFF | RAM1 (1K × 32) |
| 0x0000F000–0x0000FFFF | RAM0 (1K × 32) |
| 0x00010000–0x5FFFFFFF | external memory A |
| 0x60000000–0xFFFFFFFF | external memory B |

**Processor mode (C/PN = 0)** — external memory A at the bottom, on-chip rebased to 0x5003xxxx:

| Range | Region |
|---|---|
| 0x00000000–0x5002FFFF | external memory A |
| 0x50030000–0x500303FF | boot ROM |
| 0x50030400–0x500307FF | MMIO |
| 0x50030800–0x5003DFFF | reserved |
| 0x5003E000–0x5003EFFF | RAM1 |
| 0x5003F000–0x5003FFFF | RAM0 |
| 0x50040000–0x5FFFFFFF | external memory A (continued) |
| 0x60000000–0xFFFFFFFF | external memory B |

(The manual's printed RAM0 start address in this map has a stray digit; the region is
0x5003F000–0x5003FFFF by construction — §5.) The two maps expose the *same physical* on-chip
memories, rebased; execution can cross the map switch mid-stream, which is exactly what the
SAR boot path does (§3.9). Reset fetches from physical 0 in whichever map the C/PN strap
selected.

**Alignment rules.** Bytes are arbitrary; half-words must be halfword-aligned; words
word-aligned; violations raise the address-error exception (maskable via emr[4]) [2] §7.5.3.3.
Byte order is the pcw[8] selection, and applies to memory data — not to on-chip MMIO registers,
whose big/little-endian addresses differ instead (§2.6).

**Memory-direct addressing.** The 16-bit `*L` form of data moves always targets the 64 Kbyte
on-chip space: upper 16 bits 0x0000 (computer mode) or 0x5003 (processor mode) [2] §3.5.6 —
which is why Apple's kernel reads the timer with the one-instruction `r2 = *0x414` (*observed*
[3], §4.2).

### 3.2 The instruction cycle and the pipelines

One instruction cycle = four CKI states (0–3). In a single cycle the machine performs an
instruction fetch, two operand fetches and a write: CA instructions use up to two accesses, DA
multiply/accumulate instructions up to four [2] §7.1. The CAU generates one DA operand address
per state.

**The CAU pipeline.** CA instructions decode and execute in overlapping fashion with the
standard delayed-branch latency (§3.2.1); the CAU holds the do-loop K/L/SA registers (iteration
count, loop start) and a Z-address delay line for DA instructions [2] §8.1.2.

**The DAU pipeline.** Four stages — fetch, multiply, accumulate, (optional) store [2] §8.2.6.
With a full pipe of multiply/accumulate instructions one result completes every cycle; the
optional Z store rides as a fourth stage at no cost. Two "tap-update" forms write the *Y
operand* instead of the result in that store slot (held in a 3-cycle delay), which is what lets
a single instruction implement a delay-line tap update [2] §8.2.6.

**Wait-states.** Two kinds insert single states (each 1/4 instruction cycle) [2] §7.2:

- *Conflict* wait-states: back-to-back accesses to the same **physical** memory, where the
  physical memory is external A/B (one memory) or boot-ROM/MMIO (one memory). The on-chip
  RAMs never conflict.
- *External* wait-states: external memory slower than two states, or the bus not granted.
  The per-partition programmed waits (§2.5) plus the SRDYN handshake add states in the E
  state of the bus cycle.

### 3.2.1 Instruction-set summary and latencies

The 32-bit instruction word's top 6 bits (31–26) are the opcode; 57 of the 64 opcodes are
defined, seven are illegal (0x00, 0x01, 0x02, 0x0F, 0x16, 0x17, 0x22) [2] §7.5.3.2. The
assembly syntax is deliberately C-like — `a0 = a1 + *r2++ * *r3++` reads as it executes [1]
"DSP3210 Instruction Set".

**CA instructions** fall into three groups [2] §4.3:

- *Control*: `goto`, `if (COND) goto`, `if (rM-- >= 0) goto` (loop counter), `call … (rM)`,
  `return (rM)`, `do K,{L,rM}`, `dolock` (asserts LOCKN for the loop's bus accesses),
  `doblock` (asserts BLMN, quad-word block moves), `ireturn`, `sftrst`, `waiti`, `nop`. The
  `pcgoto label` spelling is PC-relative.
- *Arithmetic/logic*: three-register and register-with-immediate forms of add, subtract, AND,
  OR, XOR, AND-complement, carry-reverse add `#` (bit-reversed carry, for FFT addressing), the
  logical/arithmetic shifts, rotates through carry, compare, bit test — almost all of them
  conditionally executable (`if (COND) rD = …`), which is the machine's branch-avoidance
  idiom. 16-bit `(short)` operations compute on the lower halfword with 16-bit flag rules.
- *Data move*: register set (16- and 24-bit immediate), memory↔register, IO-register↔register,
  IO-register↔memory, in byte/hbyte/short/long sizes with defined extension rules
  (zero-extend for `byte`/`ushort`, sign-extend for `char`/`short`).

**DA multiply/accumulate instructions** — eight forms over the three-operand
`[Z =] aN = [-]aM {+,-} Y * X` skeleton [2] Table 4-2, with X/Y each either memory through a
pointer (r1–r14, post-modifiable) or an accumulator, and Z an optional memory store; the
"tap" forms write Y through Z instead of the result. **DA special functions** [2] Table 4-4:
`ic`/`oc` (μ-law, A-law, 8-bit linear), `float16`/`float32` (integer→float), `int16`/`int32`
(float→integer), `round` (40→32 bit, always round-to-nearest), `ifalt`/`ifaeq`/`ifagt`
(zero-latency conditional accumulator loads), `dsp`/`ieee` (format conversions, §3.8.1),
`seed` (reciprocal seed). In the X/Y/Z pointer fields, bits 6–3 select the pointer register
(p = 0000 means accumulator-direct) and bits 2–0 the post-modification (none, ±operand size,
or +r15–r19) [2] Table 10-3.

**Condition codes** [2] Table 4-7: 16 CAU conditions (pl mi ne eq vc vs cc cs ge lt gt le hi
ls, plus true/false), 10 DAU conditions (ane aeq age alt avc avs auc aus agt ale), and 13 I/O
conditions testing the SIO flags and the live IR0N/IR1N pin levels (ibe ibf obe obf syc sys
fbc fbs ir0s ir0c ir1s ir1c).

**The four latency rules** — documented behaviour, not warnings; schedulable code exploits
them [2] §4.4.2:

1. **DA memory writes** are not readable from that location until four instructions later
   (three-instruction latency). A read inside the window returns the *old* value.
2. **An accumulator feeding the multiplier** reads its value as of three instructions prior
   (two-instruction latency). Adder inputs are *live* — no latency.
3. **Branches are delayed**: `goto`/`call`/`return`/`if()goto` also execute the following
   instruction before transferring control; `ireturn` alone is immediate.
4. **A DAU condition tested by a conditional branch or conditional arithmetic/logic
   instruction** is the one established by the last flag-setting DA instruction no sooner
   than four instructions prior (three-instruction latency). The `ifalt`/`ifaeq`/`ifagt`
   accumulator loads are the documented zero-latency escape hatch.

**The three restriction rules** — *illegal* sequences, rejected by the assembler [2] §4.4.1:

- **R1**: the instruction after a DA instruction whose Z-field pointer is post-modified may
  not reference that register (except as another DA Z pointer).
- **R2**: a CAU/IO register *store* may not immediately follow a DA instruction with a memory
  reference in its Y field.
- **R3**: a CAU register loaded from memory or an IO register (and its resulting flags) may not
  be referenced in the following instruction (except as a DA Z pointer); a dauc load must be
  followed by a CA instruction.

Three instructions are not interruptible: CAU register loads from memory/IO, branch
instructions, and stack-pointer increment/decrement [2] §7.5.1.

### 3.3 Exceptions and interrupts

#### 3.3.1 Processing levels

Four levels: **base**, **interrupt**, **error**, **double error** [2] §7.5. Interrupts use a
*continuation* model (full invisible state shadowed; execution resumes exactly where it
left off); errors use an *abort* model (the current instruction is killed, do-loops
terminated, pending transactions cancelled, ongoing bus transactions completed but their data
ignored, DMA disabled, interrupts disabled — no resumption); a double error stops the
processor dead, asserts IACK0 and IACK1 simultaneously, and only a reset recovers it [2]
§7.5.2, §7.5.2.1.

#### 3.3.2 The exception vector table and interrupt entry

Sixteen vector entries of two 32-bit words each, based at **evtp (r22)**; entry *n* is at
`evtp + n*8` [2] §7.5, Figure 7-5:

| Vector | Address | Source | Maskable |
|---|---|---|---|
| 0 | +0 | RESET | no |
| 1 | +8 | bus error | no |
| 2 | +16 | illegal opcode | no |
| 3 | +24 | reserved | no |
| 4 | +32 | address error | emr[4] |
| 5 | +40 | DAU overflow/underflow | emr[5] |
| 6 | +48 | IEEE NaN | emr[6] |
| 7 | +56 | reserved | — |
| 8 | +64 | external interrupt 0 (IR0N) | emr[8] |
| 9 | +72 | timer | emr[9] |
| 10 | +80 | reserved | — |
| 11 | +88 | SIO input buffer full | emr[11] |
| 12 | +96 | SIO output buffer empty | emr[12] |
| 13 | +104 | SIO input DMA frame complete | emr[13] |
| 14 | +112 | SIO output DMA frame complete | emr[14] |
| 15 | +120 | external interrupt 1 (IR1N) | emr[15] |

Interrupt arbitration happens in state 1 for the following cycle; interrupts outrank DMA,
which outranks instruction processing [2] §7.5. On recognition the hardware: saves the
machine-invisible state, the accumulators a0–a3 *including guard bits*, all DAU flag status and
dauc into shadow registers; parks the resume pc in **pcsh**; disables interrupts; then executes
`goto evtp + offset` plus one latent `nop`. Latency is three cycles in, one (`ireturn`) out
[2] §3.2.2, §7.5.1. The `ireturn` restores the shadows, refetches from **pcsh**, and — crucially
— first *re-executes the instruction held in the instruction shadow register* (the one
prefetched before the interrupt), so pcsh holds the address *after* the shadowed instruction
[2] §7.5.1, Figure 7-6. Programmer-visible state other than the DAU set must be saved by the
handler itself.

Because the vector entries are ordinary memory words, a handler can be *written into the
table*: a two-word quick interrupt (goto + latent instruction, optionally spilling into unused
following entries) services an interrupt in three cycles [2] §7.5.1.1 — the facility Apple's
kernel uses for its frame-tick gadget (§4.2, *observed*).

The interrupt *request* is edge-latched separately from the pin level (§2.2.1): the request
latch is what emr gates and dispatch consumes; taking the interrupt does not change the pin.

#### 3.3.3 Error exceptions

Dispatch is `call evtp + VN*8 (r20)` — a call, so **r20 receives the pc (the address of the
prefetched instruction)** for tracing [2] §7.5.2; observed in Apple's handlers as the faulting
pc + 8 (*observed* [3]). Errors also clear tcon[0] (stop timer), dmac[0,4] (stop DMA), and
pcw[13] (unlock pcw) [2] Table 7-3. Nesting: a maskable error in the error level is ignored; a
non-maskable error while processing a maskable error takes the new vector; a second
non-maskable error during non-maskable error processing is the double error [2] §7.5.2.1. Exit
from the error level is software's job: reconfigure registers, execute **sftrst** (§2.4),
branch [2] §7.5.2.

#### 3.3.4 The sources in one line each

- **Bus error** — BERRN asserted with SRDYN deasserted terminates the cycle and invalidates
  outstanding fetches [2] §7.5.3.1, §6.4.
- **Illegal opcode** — the seven undefined opcodes above [2] §7.5.3.2.
- **Address error** — misaligned word/half-word access [2] §7.5.3.3. A *masked* address error
  still completes the access, aligned down (§5).
- **DAU overflow/underflow** — 40-bit-format range exceeded: overflow above (2 − 2⁻³¹)·2¹²⁷ /
  below −2·2¹²⁷; underflow for nonzero results below 1·2⁻¹²⁷ in magnitude [2] §7.5.3.4.
- **NaN** — an IEEE operand with e = 255, f ≠ 0 in an `ieee`→`dsp` conversion [2] §7.5.3.5.

#### 3.3.5 Wait-for-interrupt (powerdown)

`waiti` stops CAU and DAU execution; outstanding memory operations complete; the bus
arbitration logic and *all peripherals* (SIO, DMAC, timer, BIO) stay active, as does interrupt
sensing. Exit is on any unmasked interrupt (the instruction after the waiti executes first)
or any error exception [2] §3.2.3, §7.4. Power drops below 300 mW [1].

### 3.4 The external bus

- **Cycle shape**: synchronous, two-phase clock periods, minimum two periods per transaction
  with zero programmed waits; state S0 issues A2–A31, MS0–MS3, RW, PBD/BLMN and asserts CSN,
  then ASN and the MRN/MWN (or AEN/DEN) strobes; the E state watches **SRDYN** each ø1 — high
  inserts a wait state, low completes with data sampled (read) or the bus 3-stated (write)
  [2] §6.3. Programmed waits (S1–S3 states) and handshake waits stack: the longer of the two
  applies [2] §6.3, §3.1.4.
- **Byte lanes**: with A0–A1 absent from the bus, MS0–MS3 select the byte within the word
  according to the transfer size and the pcw[9] signalling style [2] §5, §6.
- **Arbitration**: the DSP is a default bus slave; it executes from internal memory while
  another master owns the interface, asserts **BRN** when it needs an external access, and
  takes the interface on **BGN** by asserting **BGACKN**; when BGN negates it completes any
  ongoing transaction, then 3-states and negates BGACKN [2] §3.1.4, §6.5.
- **Error protocols**: the interface supports retry, relinquish/retry and bus error;
  external logic terminates a failing cycle with BERRN (+SRDYN high) [1] "Bus Interface"
  [2] §6.4.
- **Page-mode DRAM support**: the PBD/BLMN pin, configured by pcw[15:14] and the PBD page-size
  field, asserts page-break-detect so an external DRAM controller can hold RAS across
  in-page accesses; SBD adds sequential-address detection [2] §6.2, §6.6.1.
- **Block moves**: `doblock` loops assert BLMN so the memory system can see quad-word
  transfers; `dolock` asserts LOCKN for interlocked (read-modify-write) sequences [2]
  Table 4-6, §6.6.2, §6.6.3.
- **Multiplexed buses**: the DLE (data latch enable) pin supports systems that multiplex
  address and data onto one set of lines [2] §6.6.4, §6.6.5.

### 3.5 Serial I/O

Two independent double-buffered ports — serial input (DI, ICK, ILD) and serial output
(DO, OCK, OLD) — plus the SY frame-sync pin; either port's clock and load signals can be
external or generated by the on-chip clock generator, and SY can likewise be either direction
[2] §9.1. The port set is aimed at zero-chip interfaces to codecs, TDM lines and other
DSP32-family parts [2] §9.1, [1] "Serial I/O".

**Registers** (§2.6): ibuf (read side of the input double buffer), obuf (write side of the
output double buffer), ioc (32-bit control). Data lengths: input 8/16/32 bits, output
8/16/24/32 bits, each direction independently LSB- or MSB-first [2] §3.1.5. Status is
reflected in the ps ibf/obe/sy/fb bits and testable by conditional branches (§3.2.1).

**The ioc register** [2] Table 9-1, in brief: ASY (SY internal/external), BC (derive from ICK
or OCK), SLEN (load-to-SY ratio 8/16/32), AIC/AIL/AOC/AOL (each of ICK, ILD, OCK, OLD internal
or external), ILEN/OLEN (data lengths), BO (burst vs. ÷32 internal OLD), IIC (ICK edge
polarity), SAN (sanity bit), IN/OUT (bit order), ISZ/OSZ (DMA transfer size follows length
config), ICN (internal bit-clock divider, CKI/(4·N), N = 1–15; 0 disables).

**The clock generator** produces the internal bit clock, load and sync signals; a typical
configuration (ioc[3:0] = 5, ICN = 6, CKI = 49.152 MHz) yields a 2.048 MHz bit clock, 64 kHz
load, 8 kHz sync — the TDM CEPT frame [2] §9.1.5.1. It detects the **frame boundary** condition
(the first OBE after an SY falling edge while SAN = 0 — marks channel 0 of a TDM frame) and two
error conditions, **loss of sync** (internal sync transition without a matching external SY)
and **loss of sanity** (an SY transition while SAN = 1 — i.e. the frame handler overran its
frame); the manual notes that error-exception *handling* for the two loss conditions is not
supported on this part [2] §9.1.5.3–§9.1.5.5.

**Operating modes**: program-polled (test ibf/obe flags), interrupt-driven (unmask emr[11]/[12]),
or DMA (§3.6) [2] §9.1.6.

### 3.6 The DMA controller

Two channels, one per serial direction, each a base-address register + transfer-count register
+ adder + counter + comparator [2] §9.2. A DMA cycle steals one whole instruction cycle
(cycle-stealing); with both channels configured, frames of samples flow between memory and the
serial port with no program intervention [2] §7.3, §9.2.

- **idp/odp** hold the 32-bit buffer base; the current address is idp/odp + counter, so
  reads return progress.
- **icnt/ocnt** are set in *bytes*, to one transfer less than the frame size (e.g. 64
  halfword transfers → ocnt = 126) [2] §9.2.1.
- **dmac** [2] Table 9-3, bits: per channel an enable (IDE/ODE), a mode select (IRS/ORS:
  **stop-on-complete** vs. **reload** — in reload mode the pointer/count registers are
  double-buffered: a write while running updates only the *next* registers, and frame
  completion swaps current ← next and keeps running), a change-select (ICS/OCS: whether
  loading dmac also updates that channel's enable/mode bits), and the bus-ownership option
  (IRB/ORB: only steal cycles when the DSP already owns the external bus — otherwise assert
  BRN first, so a shared-memory system pays no arbitration latency) [2] §9.2.2.
- Transfer size follows the serial port configuration (ISZ/OSZ + ILEN/OLEN): 1, 2 or 4 bytes
  per move [2] §9.2.3–§9.2.4. Mode and size must not be changed while a channel is enabled
  [2] §9.2.2 note.
- Frame completion raises the IFRM/OFRM interrupt sources (emr[13]/[14], vectors 13/14).

### 3.7 Timer and Bit I/O

**Timer.** A 32-bit down-counter with an 8-bit control register [2] §9.3:

| tcon bits | Field | Function |
|---|---|---|
| 0 | E/HN | 1 = count, 0 = hold |
| 1 | R/SN | 1 = auto-reload from the initial-count register on reaching zero, 0 = stop |
| 2 | T/PN | output mode: pulse vs. toggle flip-flop on zero |
| 3 | H/LN | pulse polarity (1 CKI-period pulse) |
| 4 | OUT | route the timer output to BIO1 (if BIO1 is an output) |
| 7–5 | SRC | 000 = CKI/2, 001 = CKI/4, 100/101 = external BIO0 rising/falling edge; rest reserved |

Writing the MMIO **timer** word loads both the initial-count register and the counter; reading
it returns the current count [2] §9.3.1. The interval is N+1 source clocks with reload, N
without [2] §9.3.2. On zero: an interrupt request (emr[9], vector 9), a toggle, and a
1-CKI-period pulse; with count 0 + continuous reload the timer becomes a CKI/2 or CKI/4
waveform generator on BIO1 (tcon 0x13 → CKI/2, 50 %; 0x17 → CKI/4, 50 %; 0x33 → CKI/4, 75 %;
0x3B → CKI/4, 25 %) [2] §9.3.2.

**Bit I/O.** Eight pins, each independently input or output via **bioc** (1 = output); the
**bio** register is written as eight 2-bit fields — 00 keep, 01 drive 0, 10 drive 1, 11 toggle
— and read back as {output-register bit, live pin} pairs [2] §9.4, Tables 9-5/9-6. Pins
configured as outputs change on the falling CKI edge; inputs are asynchronously sampled and
internally synchronized [2] §9.4.3. BIO0 doubles as the timer's external clock input, BIO1 as
the timer output, and BIO4–BIO7 are the reset-configuration straps latched into pcw[10–13]
[2] §9.4.2.

### 3.8 Data formats and the DAU arithmetic

#### 3.8.1 The DSP32 floating-point format

Internal 32-bit format (shared with the DSP32 and DSP32C): sign bit, 23-bit fraction, 8-bit
biased exponent; **2's-complement mantissa** of magnitude in [1, 2) with an implicit leading
!s bit; value N = M·2^(e−128) [2] §3.3.3. e = 0 denotes zero (sign and mantissa must be zero;
a "dirty zero" — e = 0 with nonzero sign/mantissa — is treated as zero, and dirty zeros
generated in the multiplier or adder are flushed before reaching accumulators or memory).
No negative zero; the nonzero range is approximately ±[5.877E−39 … 3.403E38] — over 1500 dB of
dynamic range.

The **40-bit extended format** exists only inside the DAU: 24-bit mantissa, 8 guard bits,
8-bit exponent [2] §8.2.2. Accumulator layout: bit 39 sign, 38–16 fraction, 15–8 guard,
7–0 exponent [2] §3.3.3. When a 40-bit value meets a 32-bit register or bus, guard bits are
truncated; when a 32-bit value drives a 40-bit bus, the guard bits read zero [2] §8.2.2.

#### 3.8.2 Arithmetic rules

- The multiplier inputs are 32-bit (24-bit mantissa) values from memory or accumulators —
  **an accumulator's guard bits are truncated on the way into the multiplier** [2] §8.2.2.
  Constants 0.0 and 1.0 can be selected as operand [2] §4.2.1.
- The product retains three integer bits (it may be denormalized, e.g. −2 × −2); the adder
  normalizes every result, so accumulator contents are always fully normalized [2] §8.2.3.
- The adder inputs (product P and addend S) and the accumulator result carry the full 8 guard
  bits; an accumulator feeding the **adder** uses its full width [2] §8.2.3. This is the
  precision rationale of the whole design: 24-bit results accumulated with 8 guard bits keep
  24-bit accuracy through long sums.
- **Overflow/underflow** of the 40-bit format raise the maskable exception (§3.3.4);
  float→integer conversions **saturate** instead — int32 to 0x7FFFFFFF/0x80000000, int16 to
  0x7FFF/0x8000, 8-bit unsigned to 0xFF/0x00 (negatives → 0x00) [2] §8.2.4.3–§8.2.4.5.
- **Rounding modes** (dauc[5:4], §2.2.2) apply to float→integer conversions: round-to-nearest
  (0.5 → 1, −0.5 → 0), truncate-toward-−∞ (floor), truncate-toward-0. The `round` instruction
  (40→32-bit float) is always round-to-nearest regardless of dauc [2] §8.2.5.
- **`int32`/`int16`/`oc` leave the raw integer in the accumulator's top bits** — "the result is
  stored in the 32 MSBs of an accumulator (aN), the mantissa, and guard bits" for int32; the
  upper 16 bits for int16; the most significant byte for oc — with the remaining bits
  unpredictable [2] INT32 p. 4-57, INT16 p. 4-56, OC p. 4-63. Since `float32`/`float16`/`ic`
  read an *accumulator* operand from exactly that lane, `float32(int32(x))` is a defined
  round trip — a property Apple's rate converter depends on (§4.3, *observed* [4]).
- **`seed`** converts a float to a 3-bit-mantissa reciprocal approximation for
  Newton-Raphson division [2] §8.2.4.6.

#### 3.8.3 IEEE P754 conversion

Single-instruction conversions in both directions [2] §8.2.4.1:

- IEEE→DSP32 (`dsp`): exponent 255 + nonzero mantissa is NaN — the converted result is
  undefined but the **NaN error** source latches (maskable, vector 6); ±∞ map to the largest
  / most-negative DSP32 values (0x7FFFFFFF / 0x800000FF); exponent 0 (zeros and
  denormals — not supported) map to +0 (0x00000000).
- DSP32→IEEE (`ieee`): never produces NaN.

### 3.9 The boot ROM

256 words of mask ROM whose first 32 words are the reset exception table [1] "Boot ROM Code",
Listing 1. Its CHECKSUM (0x789B8099) is stored negated in the last word and makes the 16-bit
arithmetic sum of the image zero — the basis of the self-test. On reset, execution begins at
physical 0, which is the boot ROM's `if(true) pcgoto boot_begin` in computer mode, or external
memory in processor mode; the latent second instruction `r1 = (short) pcw` captures the pcw for
the path test [1] "Detailed Description of Start-up Boot Routines", Listing 1.

**Option 1 — processor-mode boot (C/PN = 0).** The boot ROM sits at 0x50030000 and is ignored;
the DSP executes from external memory A at 0 [1] Table 1.

**Option 2 — SAR boot (C/PN = 1, BRC = 0), the shared-memory path.** The routine [1] Table 1,
"SAR Boot":

1. Set r22 (evtp) to 0x50030000 — the boot ROM's *future* address in processor mode (the first
   32 words there double as the exception table).
2. Enable external interrupt 1 (emr bit 15).
3. Clear pcw[10] — switch to processor mode *while entering the interrupt level*; external
   memory A now occupies address 0.
4. `waiti`.
5. On the host's IREQ1 pulse (acknowledged on IACK1): load **pcsh** from location 0 — the
   host-provided start vector — clear emr, and `ireturn`. The return replays the prefetched
   shadow instruction `*r0 = r0`, which **writes zero to location 0** — the "boot complete"
   handshake the host polls — and execution continues at the host's vector.

The mode switch has one externally visible trap: right after the switch the DSP prefetches at
what was the boot ROM's boot_error address, which now appears as external address 0xFC. The
fetch is discarded, but **the external system must complete the read or the DSP hangs** [1]
"SAR Boot".

**Option 3 — EPROM boot (C/PN = 1, BRC = 1).** The routine loads from a byte-wide EPROM
mapped at 0x60000000: the LSBs of the words at 0x60000000–0x0C assemble the **Address**
(big-endian, first byte = MSB), those at 0x60000010–0x1C the **Count**; Count = 0 with a
nonzero Address branches directly to Address; otherwise Count bytes are copied from 0x60000020
to Address (instructions assembled MSB-first) and execution branches to Address, still in
computer mode [1] Table 1, "EPROM Boot", Figure 9. Because the DSP always leaves reset in
big-endian Motorola-style signalling, an Intel-style/little-endian system must first load an
alternate loader through this path and use it to set pcw[8:9] before byte/word moves [1]
"Special Note for Intel-Style Signaling Implementations". F12 removes the F11 routine's
2048-word copy limit [1] "F12 Silicon Revision".

**Self-test** (F12), at boot_rom + 0x58, callable with `call r10 + 0x58 (r1)`: locates itself
and the on-chip RAM in whichever map is active, copies the boot ROM to RAM, computes the
16-bit image checksum simultaneously in the DAU and CAU and compares, checksums the whole RAM
in 32 bits, performs dummy reads of ioc, timer, dauc and idp "to exercise their respective
peripheral buses", and returns 0 in r2 on success, 1 on failure; all user registers except
r1 are destroyed [1] "Detailed Description of Self-Test Routine", Listing 1.

**Error parking**: the ROM's boot_error writes `ior10 = (short) r0` (§2.4 — both IACK pins
asserted) and spins forever [1] Listing 1.

## 4. Programming model

This section records how the shipped Macintosh software actually drives the part. The 68040
host and the DSP share the host's RAM; the host sees the DSP's external memory as ordinary
Macintosh memory, and the DSP boots through the documented SAR path. All behaviour below is
*observed* by disassembly and execution of the shipped code [3][4].

### 4.1 How the host boots the DSP (Real Time Manager)

The AV ROM's DSP driver performs, in order [3]:

1. **Copy the kernel resources into shared RAM, verbatim** — no interpretation at all: each
   `'3210'` resource (core, evt, patches, and the modules' containers) is block-moved into a
   host-RAM buffer. One twist: `core` is copied minus its trailing 12-byte `'term'` entry and
   the `slave` segment is appended, producing a single well-formed chunk chain "core ++ slave".
   The `evt` image is loaded into a buffer $A00 bytes larger than its $200 vector-table image:
   the extra bytes hold the kernel's **data area at evt+0x200** (0x400 bytes) and three 0x200
   blocks at +0x600/+0x800/+0xA00 (the kernel stack among them).
2. **Write the boot header** at a known cell: evt physical address, core physical address,
   patches physical address, then the literal instruction pair `r1 = (ushort24) $3B80` /
   `pcw = (short) r1` — the host places the kernel's own pcw value in the stream.
3. **Set up the SAR handshake**: write the start vector (the boot segment's entry, boot+$C)
   to physical 0 and pulse IR1N. The kernel — in its first $1F0 bytes, the chunk-chain loader
   described below — dispatches through vector 15, loads pcsh from location 0, and its
   `ireturn` replays `*r0 = r0`, zeroing location 0: **handshake one**.
4. **Poll two flags**: stage 1, the kernel's `call r1 (r1)` link-register write of $18 into
   cell $18; stage 2, bit 0 of the kernel data area at +$198 ("kernel alive").

### 4.2 The kernel's own start-up and steady state

- **The chunk loader.** The first $1F0 bytes of `core` are a loader (entered at core+$C with
  r1 = chain base, r22 = evtp) that walks 12-byte headers `{tag, size, field3}`. field3 is the
  index of a longword **slot** in the data area (`*(evtp + $200 + 4*field3)` receives each
  chunk's resolved address); the vocabulary is nine tags — `xmem` (leave payload in host RAM;
  slot = its address), `hmem` (copy on-chip, allocated top-down from RAM0's top),
  `lmem` (copy on-chip, bottom-up from the RAM1 heap at 0x5003E000), `cnst` (slot = the
  payload value), `rmem` (debug hook, armed only by the magic `'ejb '` in on-chip word
  0x500303F8), `alia`, `hndl`, `offs` (slot indirections) and `term`. The copy loops use the
  DA tap instruction `a0 = (*r2++ = *r4++) * a0` as a 32-bit block mover. The boot segment
  runs the loader over "core ++ slave", then over `patches`, then jumps through **slot $1C**
  — the kernel main. Host-side, this is why the host does no parsing: **the kernel interprets
  its own image**.
- **Vector table.** The kernel relocates evtp as the manual prescribes (build table, move
  evtp, then unmask): during boot it runs on the evt image's own table; at its sleep gadget
  it briefly points evtp at a scratch NOP table so nothing disturbs the spin.
- **Two periodic inputs, not one.** The frame tick from the codec subsystem arrives as
  **EXT1 (IR1N, vector 15)**; the kernel also programs the **timer** (`tcon = 0x23`:
  enabled, auto-reload, source CKI/4) as its scheduling heartbeat and sleeps in `waiti`
  under **emr = 0x0200** — timer only — between frames. The sleep gadget is a quick
  interrupt in RAM1 that polls the *live* IR1N pin with `if (ir1s) goto` and samples the
  timer through memory-direct `r2 = *0x414`; at boot the same gadget measures the frame
  period (two pin-wait spins around one timer sample) and reports it to the host.
- **Frame service.** Each serviced tick ends with a 16-bit write to the MMIO **bio** register
  — the DSP→host doorbell interrupt, driven by software through the bit I/O port rather than
  by any dedicated pin.
- **Error handling.** The kernel's evt handlers stash **r20** (the error trace — the faulting
  pc + 8) and build the four-character codes `'xbus'` / `'xill'` in it, write a full crash
  frame (error code, r19, r1–r18, r20–r22, emr, pcw, timer, dauc, ctr, a0–a3, then a copy of
  on-chip RAM) into the host-visible dump block, set **emr = 0**, execute **sftrst**, and park
  in `waiti` — deliberately unwakeable until the host intervenes.
- **Latency-disciplined code.** The shipped dspf task modules are software-pipelined to the
  DAU latencies of §3.2.1: the input converter's inner loop reads an accumulator exactly
  three instructions after writing it (Latency 2), the recognizer's pre-emphasis filter
  reads back a DA store inside the three-instruction window (Latency 1), and its codebook
  search mixes zero-latency `ifalt` with four-back `if (agt)` tests in four instructions
  (Latency 4). Code that ignores the latencies computes a different filter, not merely a
  slower one.

### 4.3 Conversion idioms the sound stack depends on

- `*rZ = aN = int32(Y)` followed by `aN = float32(aN)` splits a phase accumulator into
  integer and fractional parts through the accumulator's integer lane (§3.8.2).
- The Z-field with pointer code 1111, "not allowed" per the manual's field table, is in
  real use as an **in-place store through the Y operand's own address** — the rate
  converters' read-modify-write cursor (see §5).
- Module-to-kernel communication runs through records (a MsgFIFO of command words, DSPFIFO
  ring records with host-RAM base pointers) rather than through any DSP hardware queue.

### 4.4 A driver's checklist

For anything driving this chip as the Macintosh software does:

1. Choose the boot path by straps: BIO7 = 0 (processor mode, execute from external memory at
   0) or BIO7 = 1 with BIO4 selecting SAR vs. EPROM; BIO6/BIO5 pick RW and AEN/DEN
   signalling; all four latch at the RESTN rising edge [2] §6.2, §7.5.4.1.
2. Program the pcw first (waits, page size, byte order — remembering the R3 rule if it is
   loaded from memory), and never write pcw[13] = 1 unless the register should be locked.
3. Relocate the vector table per §3.3.2 — entries first, evtp second, emr last.
4. Respect the three assembler restrictions (§3.2.1) and schedule around the four latencies;
   prefer the zero-latency conditional accumulator loads over flag-testing branches.
5. Save the CAU state in handlers yourself — the hardware shadow covers only the DAU set and
   the invisible machine state (§3.3.2).

## 5. Quirks & errata

- **The manual's "not allowed" Z-field is a real addressing mode.** Table 10-3 calls Z-field
  pointer code p = 1111 "not allowed", and a naive reading treats it as a synonym for the
  no-write encoding ($07). In silicon a Z field with p = 1111 **stores through the Y operand's
  own effective address** and post-modifies *Y's* pointer with the Z field's increment bits;
  when Y is an accumulator there is genuinely no store — which is how the misreading survived
  (*observed* in three independent shipped modules: an in-place integer→float conversion
  whose result must be read back, a gain stage whose entire body is otherwise a no-op, and a
  rate converter's output cursor [3][4]). Apple's assembler uses the canonical $07 wherever
  no store is intended, and p = 1111 exactly where a read-modify-write is needed; the two
  spellings coexist in the same loops.
- **LOAD sets the CAU flags.** The LOAD instruction page's header says "CAU flags affected:
  none", contradicting the Restriction-3 text on the same page ("the flags set as a result of
  the load"). Shipped code settles it — it dispatches on `r1 = *r1; nop; if (gt) goto`
  (*observed* [3][4]). The header is wrong.
- **A masked address error still completes the access**, aligned down. The manual documents
  only that a misaligned access raises vector 4; it does not say what happens to the access
  when the exception is masked. Apple's kernel programs the timer with a misaligned *long*
  store to 0x50030413 with emr[4] clear, and the timer starts: the write must land on the
  0x50030410 word slot with tcon in the low byte lane (*observed* [3]).
- **pcsh/irsh interplay.** `ireturn` re-executes the prefetched instruction from the
  instruction shadow register and resumes at pcsh, which holds the address *after* the
  shadowed instruction. The boot ROM's SAR path hides its "clear location 0" handshake write
  exactly there — an implementation that resumes at pcsh without the replay executes the
  interrupted instruction twice or not at all [1] "SAR Boot" [2] §7.5.1, Figure 7-6.
- **dauc rounding-mode encodings disagree with the instruction pages.** Table 8-3 assigns
  x0/01/11 to round/truncate-−∞/truncate-0; the INT16/INT32/OC pages say 00/10/11 — the
  encodings 01 and 10 conflict between the two. No shipped code selects either disputed
  encoding, so silicon has not arbitrated it here (§6) [2] Table 8-3 vs. instruction pages.
- **OC's μ-law/A-law polarity disagrees with itself.** The OC page and Table 8-3 disagree on
  which dauc bits select μ-law vs. A-law output; unresolved for the same reason [2].
- **The float32/int32 G-code examples are misprints.** The FLOAT32/INT32 instruction-page
  examples encode G = 1010/1011, where Table 10-3 assigns 1000/1001 and reserves 101x. Apple's
  shipped converter encodes 1000/1001 — the table is right [3][4].
- **Table A-1's count-zero claim hinges on load-flag timing.** The boot ROM listing's
  count/address test reads `r5 = *0xE004; r1 = *0xE000; if (eq) …`; since both loads set the
  flags, which one the branch tests depends on the visibility latency of load flags
  (Restriction 3). Under the manual's own restriction the branch sees the *count* load, as
  Table A-1's comment claims; under a zero-latency reading it sees the *address* load and the
  count-0 branch never fires. The listing's own comment ("check number of bytes") supports
  the manual's restriction; silicon has not settled it (§6) [2] Appendix A.
- **Printing errors in the memory-map figure.** The processor-mode map's RAM0 row is printed
  with a nine-digit start address (read in context: 0x5003F000–0x5003FFFF), and §3.5.6's
  memory-direct description prints "C/PN = 1" in both of its clauses (the second must be
  C/PN = 0 for the 0x5003 base) [2] Figure 3-4, §3.5.6.
- **The datasheet's SAR text drops a digit** in the evtp value ("0x5003000" for 0x50030000)
  — harmless in context but worth knowing when cross-reading [1] "SAR Boot".
- **One physical on-chip array, two decodes.** The boot ROM/MMIO/RAM regions are one physical
  set rebased by the C/PN bit, and the SAR path executes *across* the switch; a memory system
  that decodes only one window breaks the boot. The external system must also answer the
  discarded 0xFC prefetch after the mode switch, or the DSP hangs [1] "SAR Boot".
- **The `(short)` write to spc asserts both IACK pins** — the same signal pair as the double
  error — giving a bare-metal "signal the world and stop" idiom [1] Listing 1 `boot_error`
  [2] §7.5.2.1. Other access sizes for spc are not documented anywhere.
- **The DSP never gets a word-aligned guarantee on MMIO**: registers must in principle be
  accessed with their own size (§2.6), but the kernel's misaligned long to tcon works — the
  aligned-down completion above. The safe rule for new code remains "use the documented size".
- **Interrupt-request latch vs. pin level.** ps[13] is the *live* pin; the *request* is
  edge-latched and is what emr gates. Writing emr with bit 0 (SL) set drops a latched,
  not-yet-taken EXT1 request without taking it — undocumented, and load-bearing for the
  kernel's overrun handling (*observed* [3]).
- **F11 → F12**: the EPROM copy limit (2048 words) is gone in F12, and the self-test entry
  exists only in F12; object code is upward compatible [1] "F12 Silicon Revision".
- **The `round` instruction ignores dauc** — always round-to-nearest, unlike the
  float→integer conversions [2] §8.2.5.
- **Dirty zeros are flushed, not propagated** — any dirty zero produced in the multiplier or
  adder becomes a clean zero in accumulators and memory [2] §3.3.3.

## 6. Open questions

1. **The dauc rounding-encoding conflict** (Table 8-3's x0/01/11 vs. the instruction pages'
   00/10/11): which is silicon? No shipped code exercises encodings 01 or 10.
2. **The OC μ-law/A-law polarity conflict**: likewise unresolved by any observed `oc` use.
3. **Load-flag visibility latency** (Restriction 3's "cannot be referenced in the following
   instruction"): whether the flags are visible with a one-cycle delay — which would make the
   boot ROM's count-zero branch behave as Table A-1 describes — is the one manual timing rule
   with an architectural consequence, and silicon has not settled it.
4. **The DAU adder's 40→32 truncation**: the manual documents `round` for the 40→32-bit step
   and no rounding in the adder; whether an accumulator store truncates or rounds without an
   explicit `round` is not stated outright, and no observed code distinguishes the two.
5. **Product width into the adder**: whether the multiply product is aligned into the adder at
   its full fractional width or truncated to the 32-bit operand width first is observable only
   under extreme cancellation or sub-2⁻³² products.
6. **`float32`'s operand lane for an accumulator input** is taken by symmetry with int32's
   documented output lane (mantissa + guard bits); the manual does not state it.
7. **The behaviour of spc accesses other than `(byte)`/`(long)`** — the boot ROM's `(short)`
   write asserting both IACK pins is the only third-size evidence; nothing documents the
   register further.
8. **The `do` loop with K = 0 executing one iteration** (the "do 2, r5"-style boundary cases in
   the boot ROM listing) is exercised by the ROM but not narrated in the instruction pages;
   the exact off-by-one at the K = 0/L = 0 boundaries deserves a hardware test.
9. **Which BIO pin the host watches** for the DSP→host doorbell, and the board-level interrupt
   plumbing generally, is outside the chip's documentation and belongs to the
   [board page](../machines/av/dsp3210-board.md); the DSP-side software only shows a 16-bit
   bio write per serviced tick (*observed* [3]).
10. **The host↔kernel message protocol** (the MsgFIFO command word layout, the DSPFIFO record
    binding) is inferred from what the shipped modules compute, not from documentation.
11. **Whether the AV Power Macintosh configurations carry the same part** — reported, but not
    established by the primary sources behind this page.
12. **CKI frequency on the AV boards** — the 66 MHz-class rate is inferred from the kernel's
    observed timer cadence, not read from a board schematic; see the board page.
